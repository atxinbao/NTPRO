## Plain Chinese Summary

本次修改解决的是 `ntpro-node` 以前只会一直等 `stop-file` 的问题。现在节点在等待停止时不再只有一种退出方式：

- stop file 出现时正常退出；
- 收到 Ctrl-C / SIGTERM 时退出；
- 达到最大运行时间时退出；
- 配置了 parent pid 且父进程已退出时退出；
- 调用 `LiveNode::stop()` 时有 shutdown timeout 保护。

没有改交易语义，没有接真实交易所，没有提交真实订单，也没有把 live/sandbox 写成生产可用能力。

## Goal

Prevent `ntpro-node` from running forever when stop files are missing or when a real long-lived supervisor parent exits.

## Files Changed

- `crates/cli/src/bin/ntpro_node.rs`
  - Added `--max-runtime-ms`, `--heartbeat-interval-ms`, `--parent-pid`, and `--shutdown-timeout-ms`.
- `crates/cli/src/live.rs`
  - Added `NtproNodeRunControls`.
  - Replaced the unbounded stop-file wait loop with a shutdown trigger loop.
  - Added running heartbeat status/metrics rewrites while waiting.
  - Added timeout protection around `LiveNode::stop()`.
  - Added tests for stop file, max runtime, and parent-dead shutdown.
- `crates/cli/src/lib.rs`
  - Exposed `NtproNodeRunControls` and `run_ntpro_node_with_controls` for the binary entrypoint.
- `crates/cli/src/opt.rs`
  - Added supervisor start options for node runtime/heartbeat/shutdown controls.
- `crates/cli/src/supervisor.rs`
  - Passed max runtime, heartbeat interval, shutdown timeout, and optional parent pid to spawned `ntpro-node`.
  - Kept CLI `supervisor start` parent pid unset by default because it is a short-lived command.
- `crates/cli/src/dashboard.rs`
  - Passed the Dashboard server process pid as parent pid for Dashboard-started nodes.
- `.agentflow/state/task_status.json`
  - Moved P0-007 into running/review state.

## Behavior Impact

- `ntpro-node` no longer has only an infinite stop-file wait path.
- Supervisor-started CLI nodes keep running after the short `supervisor start` command exits; max runtime still gives a bounded fallback.
- Dashboard-started nodes receive the Dashboard server pid and can stop when that long-lived parent exits.
- Status and metrics artifacts are refreshed while a node is waiting for shutdown.
- Summary and event logs record the shutdown reason.

## Public API Impact

- New `ntpro-node` CLI options:
  - `--max-runtime-ms`
  - `--heartbeat-interval-ms`
  - `--parent-pid`
  - `--shutdown-timeout-ms`
- New supervisor start options:
  - `--node-max-runtime-ms`
  - `--node-heartbeat-interval-ms`
  - `--node-parent-pid`
  - `--node-shutdown-timeout-ms`
- Added Rust API surface in `nautilus-cli`:
  - `NtproNodeRunControls`
  - `run_ntpro_node_with_controls`

## Important Design Decision

An initial smoke run failed because `supervisor start` is a short-lived CLI command. Passing `std::process::id()` by default made the child node stop immediately after the start command exited.

The final design is:

- CLI `supervisor start`: does not pass parent pid by default; uses max runtime and stop file.
- Dashboard start action: passes the Dashboard server pid because the Dashboard process is long-lived.
- Direct `ntpro-node`: accepts explicit `--parent-pid` for callers that have a real long-lived parent.
