Status: REVIEW_REQUIRED

## 缺陷证据

PR #1331 的重复真实交付验收中，launcher 已向 `mvp serve` 发送 `SIGINT`，但活动 Demo 停止
偶发耗尽 60 秒预算并进入强杀。保留 workspace 中的 node 最终以 `parent-exited` 原因停止，且
服务日志缺失 `mvp.serve status=stopped`。源码审查确认事件循环在每次
`status_refresh.tick()` 后重建 `tokio::signal::ctrl_c()` future；当前监听被取消时存在丢信号窗口。

## 修复

- `run_mvp_serve` 在进入循环前创建并 pin 单一 shutdown future；
- `wait_for_mvp_serve_exit` 在 Dashboard、同一 shutdown future 和状态刷新之间选择；
- 直接回归先完成至少三次刷新，再发送一次 shutdown，要求监听仍注册且循环在一秒内成功退出；
- `docs/product/mvp_freeze_manifest.json` 只更新 `crates/cli/src/mvp.rs` 哈希为
  `6fddc776224956a5b7e1a57859a68cac887f5a871b122e3fdaef3611dc1c8ed6`。
- backend runtime risk inventory 只新增 3 个 `test_inline expect`，production 保持 2,703。

## 边界

本修复不改变 Product API、Supervisor registry、node 合同、策略语义或交易能力。Live、外部
Venue、真实订单、订单 mutation、自动重试、自动修复和交易控件均未从冻结基线继承或开启。

## 风险与回滚

信号监听保持时间变长，但退出后的 `runtime.stop`、错误组合和日志分支不变。若回滚，必须同时
恢复 `mvp.rs` 和 manifest 原哈希；PR #1331 重新标记为阻塞，不能接受强制终止作为正常停止。
