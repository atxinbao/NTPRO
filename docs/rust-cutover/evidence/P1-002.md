# P1-002 Evidence - LiveNodeHandle Atomic Ordering

Date: 2026-06-11
Executor: Codex
Task: P1-002 LiveNodeHandle Atomic Ordering

## Plain Chinese Summary

这次修的是 `LiveNodeHandle` 这种跨线程 stop/state 句柄的原子读写语义。以前 stop flag 和 state 都用 `Relaxed`，只保证原子性，不表达“先写后读”的可见性关系。现在写入用 `Release`，读取用 `Acquire`，让其它线程观察 stop/state 时有更明确的同步语义。

另外，如果 `AtomicU8` 里的 state 因为未来 bug 或内存破坏变成非法值，`handle.state()` 不会再 panic 崩掉调用方，而是按保守方式返回 `Stopped`，并打 warning。直接调用 `NodeState::from_u8(255)` 的显式转换仍然保持 panic，用来保留开发期错误暴露。

没有改 live node 启停流程、adapter 行为、交易语义、CLI 或公开配置。

## Files Changed

## Behavior Impact

- Cross-thread readers of `LiveNodeHandle` now use Acquire loads paired with Release stores.
- Invalid raw atomic state no longer panics through `LiveNodeHandle::state()`.
- Invalid raw state is treated as `Stopped`, which is conservative for product control paths.
- Direct `NodeState::from_u8` invalid conversion still panics for explicit developer misuse.

## Public API Impact

- No CLI, config, dashboard, control API, adapter API, or trading semantic change.
- `NodeState::try_from_u8` is a small public helper on an already public enum.
- Existing `NodeState::from_u8` behavior is preserved.

## Migration Note Status

No migration note required. This tightens runtime handle internals without changing user-facing commands or config.

## Rollback Plan

Revert this PR to restore relaxed atomic ordering and the previous direct `from_u8` handle conversion behavior.

## Remaining Risk

- This change improves synchronization semantics but does not prove every live node caller has a complete cancellation protocol. Broader live runtime cancellation coverage remains in adjacent P1 work.
