## 审查修复

提交前差异审查发现 Runtime 回读 sizing 工件时未按启动当前时间拒绝过期证据，也未独立复算
订单名义金额和预算上限。现已在执行客户端注册前补齐时效、数量、算术及预算校验，并增加过期和
算术漂移负向测试。

独立 Gatekeeper 初审进一步发现 SELL 方向账户预算未乘账户预算比例，且 sizing 工件未携带完整
规则与细分拒绝原因。现已按 `base_free * price * max_account_budget_fraction` 约束 SELL，工件、
OpenAPI、Runtime 和工作台同步携带并核验 tick、step、min/max quantity、min notional 与账户预算
比例；新增 SELL 预算边界测试和中文细分拒绝原因。

最终复审发现工作台只校验规则字段形状，未独立复算 tick、step、名义金额和 request/risk 上限。
现已使用 BigInt 十进制定点校验全部语义关系，并增加 6 个伪造 sizing 响应负向用例，避免浏览器
接受结构合法但违反交易规则的响应。

二次复审补充发现 request 上限与风险策略上限之间还缺少直接关系校验。现已要求
`request_max_notional <= risk_policy_max_notional`，并增加跨上限漂移负向用例。

本任务为 critical，当前停在 `REVIEW_REQUIRED`；独立 Gatekeeper 审批和 hosted checks 全绿后
才允许手动合并。
