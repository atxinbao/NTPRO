## 中文大白话总结

这次修的是“同一个节点有两个名字，系统却不知道该信哪个”的问题。

以前 supervisor 注册节点时使用 `sandbox-a`、`sandbox-b`，但节点生成的
`status.json` 和 `metrics.json` 可能写成配置里的 `LiveInitSmoke`。这样 Dashboard
或控制命令看到工件后，无法可靠判断数据到底属于哪个注册节点。

现在规则统一为：status 和 metrics 里的 `node_id` 必须等于本次运行的
`run_id`；supervisor 管理的进程中，这个值就是注册时的节点 ID。配置里的
`node_name` 和 `instance_id` 仍保留给 LiveNode 做显示名称，但不能再替代工件身份。

如果 status 或 metrics 工件写了别的节点 ID，supervisor 会把工件标记为 invalid
并返回明确错误，Dashboard 也会显示 unavailable/gap，不会继续把错绑数据当成正常
节点状态。双节点 smoke 已验证 `sandbox-a` 和 `sandbox-b` 在启动、查询、停止阶段
身份始终一致。

这次没有连接真实交易所，没有提交真实订单，没有修改交易语义，没有创建 tag，也
没有发布 GitHub Release。P0-006 是高风险任务，因此只提交 PR 给人工 review，不
启用自动合并。

## Goal

Remove ambiguity between supervisor registry identity and runtime status/metrics
identity before Dashboard and control consumers rely on those artifacts.

## Files Changed

- `crates/live/src/status.rs`
  - Documents `NodeStatus.node_id` as the canonical runtime artifact identity.
- `crates/cli/src/live.rs`
  - Writes the resolved run ID into status and metrics artifacts.
  - Keeps configured node name/instance ID as LiveNode display metadata only.
  - Adds assertions for standalone and supervisor-spawned identity behavior.
- `crates/cli/src/supervisor.rs`
  - Rejects status and metrics artifacts whose node ID differs from the
    registry record.
  - Preserves the last trusted status instead of replacing it with mismatched
    data.
  - Clears previous-run status/metrics artifacts before spawning a new process,
    so stale identity data cannot block or impersonate a new startup.
  - Fails startup immediately on an invalid status artifact.
  - Renames CLI output labels from `status_node_id` / `metrics_node_id` to
    `runtime_node_id`.
  - Adds status and metrics mismatch regression tests.
- `crates/cli/src/dashboard.rs`
  - Rejects mismatched status and metrics artifacts at the direct Dashboard
    read boundary.
  - Emits explicit unavailable state, gap, and error details.
  - Adds Dashboard regression tests for both artifact types.
- `scripts/ai/v02_two_node_supervisor_smoke.sh`
  - Asserts registry, status, and metrics node IDs match for both nodes while
    running and after stop.
- `docs/rust-cutover/migration/node_identity_contract.md`
  - Records the artifact semantic and CLI output label migration.
- `docs/rust-cutover/migration/README.md`
  - Links the new migration note.
- `docs/rust-cutover/release/v0_2_local_multi_node_readiness_report.md`
  - Replaces the old identity ambiguity risk with the P0-006 contract.

## Behavior Impact

- Runtime status and metrics identity is deterministic and unique per run.
- Supervisor-managed status/metrics artifacts must match the registered node ID.
- Mismatched status cannot make startup appear successful.
- Mismatched metrics cannot be returned as valid supervisor metrics.
- Starting a new process removes prior-run status/metrics artifacts before
  waiting for new canonical artifacts.
- Dashboard does not aggregate mismatched artifacts into a node snapshot.
- Configured LiveNode display names remain unchanged.
- No trading semantics, venue connectivity, or order submission behavior changed.

## Public API Impact

The serialized JSON shape and schema version remain unchanged, but the meaning
of `NodeStatus.node_id` and `NodeMetrics.node_id` is tightened to the canonical
run ID.

Supervisor text output changes:

```text
status_node_id  -> runtime_node_id
metrics_node_id -> runtime_node_id
```

Scripts that parse those output labels must update. The migration note is
`docs/rust-cutover/migration/node_identity_contract.md`.

## Rollback Plan

Revert the P0-006 PR. This restores config node name/instance ID precedence for

`scripts/ai/v02_two_node_supervisor_smoke.sh` and update any parser that had

## Remaining Risk

- The identity contract is local supervisor/run-ID based; it does not create a
  distributed node identity or cross-host ownership protocol.
- Existing persisted status/metrics artifacts from before P0-006 are rejected
  by direct reads; a supervisor restart clears them before the node rewrites
  canonical artifacts.
- PID reuse protection remains separate from artifact identity.
