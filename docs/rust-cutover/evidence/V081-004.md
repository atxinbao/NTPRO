## Scope

Harden the Binance testnet authenticated read-only account probe response-shape
metadata without expanding the v0.8 product scope.

This task does not add order submission, cancel/replace/amend, account
mutation, production Binance connectivity, real funds, production trading, or
Dashboard-started probes.

## Changes

- Renamed the authenticated account response shape label from
  `binance_account_v1` to `binance_account_readonly_redacted_v1`.
- Tightened response-shape validation so a successful authenticated account
  response must include:
  - `accountType` as a string;
  - `balances` as an array;
  - `canTrade` as a boolean;
  - `canWithdraw` as a boolean;
  - `canDeposit` as a boolean.
- Updated dashboard fixture expectations to use the hardened redacted label.
- Updated the v0.8 authenticated read-only verification gate to expect the
  hardened redacted label in both offline preflight and manual-online success
  checks.
- Updated the authenticated read-only boundary document to clarify that the
  label proves only bounded shape validation and still forbids persisting raw
  account data, balances, account IDs, headers, signatures, signed URLs, or
  signed query strings.

## Behavior Impact

Authenticated read-only probe success is now stricter: an HTTP 2xx account
response must contain `canWithdraw` and `canDeposit` booleans in addition to the
previous bounded account-shape fields. Invalid or incomplete responses remain
classified as `response_shape_invalid` and do not establish authenticated
connectivity proof.

Artifact persistence remains redacted. The task does not persist balances,
account IDs, raw response body, API key values, secret values, signatures,
signed query strings, signed URLs, or headers.

## Public API Impact

Artifact metadata label changes from `binance_account_v1` to
`binance_account_readonly_redacted_v1` for authenticated account shape status.
The label is more explicit about read-only/redacted semantics.

## Migration Note Status

Covered by the boundary document update. Older v0.8 artifacts with
`binance_account_v1` remain historical evidence, but new V081/V0.8.1 artifacts
use the hardened label.

## Rollback Plan

Revert this PR to restore the previous account response shape label and the
previous account response shape validator. No runtime order path or credential
persistence behavior would need rollback because this task does not change
those paths.
