## 实现证据

- `ntpro-node` 支持严格的 `production-market-data` 配置模式，固定
  `Environment::Live`、Binance Spot 和环境凭证引用；
- Runtime 只向 `LiveNode` 注册 `BinanceDataClientFactory`，启动后验证 data client connected，
  挂载 quote/trade 订阅 Actor 并运行完整 `LiveNode::run` 事件循环，同时断言 execution client
  列表为空；
- StrategyVersion 的生产行情 symbols 在候选创建时写入不可变 manifest，Runtime 启动不重新
  解释可变策略配置；
- Binance WebSocket 的 Runtime 专用连接将重连次数固定为 0；底层断线立即使 data client
  状态失效，LiveNode fail closed 退出；
- Product API 新增 `start_market_data`，以外部单调锚点记录 starting/running/stopping/stopped/
  failed，并由 Supervisor 绑定不可变 Run ownership；
- Supervisor ownership 建立前的 register/claim 失败会写入 failed 终态并释放活动候选；
  ownership 建立后的 start/runtime 失败还会确认进程清理并登记 terminal anchor；
- list/detail/action 会在跨进程锁内回收异常退出的 Runtime，锚定 revision 4 的 failed 终态并
  释放活动候选，不会永久停留在 `market_data_running`；
- OpenAPI、生成 SDK、严格 TypeScript 客户端和策略工作台展示真实 Runtime/行情/进程状态；
- 订单 endpoint、下单、撤改、成交对账、自动重试、自动修复、自动恢复和交易控件保持 false。

## 独立审查修复

首轮 Gatekeeper 指出的四项阻塞已本地修复：

1. 生产行情 WebSocket 禁用自动重连，真实连接状态纳入 `DataClient::is_connected`；
2. Product API 自动识别异常退出，写入外部审计锚定的 failed 终态并释放候选；
3. Runtime 改为运行完整事件循环，并通过 Actor 实际订阅和消费 quote/trade；
4. TypeScript 接受启动失败 revision 3 与运行后失败 revision 4，OpenAPI 明确 lifecycle 与
   Runtime/连接字段组合，生成合同和 121 项客户端测试通过。
5. `failed` 回收改为可重复收敛：无 active pointer 的已验证终态可重复读取，残留 pointer 会
   驱动 Supervisor terminal anchor 与 pointer 清理重试；重复 reconcile、启动失败详情和
   分阶段失败恢复均有测试覆盖。
6. `starting`、`stopping`、`stopped` 中间态改为 pointer 驱动的确定性恢复；注册前、注册后、
   进程启动后、停止请求前和终态锚定前五个持久化中断点均有直接故障注入测试。
