这次改动解决的是本地 supervisor 同时被多个 CLI 命令操作时，`registry.json`、节点
状态、metrics、pid 和 stop 请求文件可能被写坏或互相覆盖的问题。

替换正式文件；registry 修改还会先拿 `registry.json.lock`，同一时间只允许一个命令改 registry。

## Goal

Prevent supervisor registry, node status, metrics, pid, and stop-request
artifacts from being corrupted by concurrent CLI operations or interrupted
writes.

## Implementation Notes

- Atomic writes use `OpenOptions::create_new(true)` for the temp file so an
  existing temp path is never silently reused.
- Temp files live beside the final artifact. This keeps `rename` on the same
  filesystem and avoids cross-device partial copy behavior.
- Failed writes remove the temp file best effort.
- Registry locking uses `registry.json.lock` style lock files created with
  `create_new(true)`.
- The lock waits up to 10 seconds and retries every 25 ms before returning a
  clear timeout error.
- The lock is removed by RAII drop after the registry transaction completes.

## Remaining Risk

- The lock is intentionally local filesystem based. It is suitable for the
  v0.2 local multi-node runtime foundation, not distributed multi-server
  orchestration.
- If a process is killed while holding the lock, the lock file may remain until
  manual cleanup or a future stale-lock policy. This is safer than silent
  registry corruption, but it can block later registry mutation until resolved.
- This task does not implement production live trading readiness, dashboard UI,
  manual order entry, or real exchange connectivity.
