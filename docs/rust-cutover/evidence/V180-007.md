## Plain Chinese Summary

这次只处理 V180-007。它定义未来撤单后的只读回查合同：系统可以用已经脱敏的回查元数据判断撤单后订单是 canceled、filled、rejected、expired、missing 还是 unknown，但 v0.18 仍不发撤单、不触网回查、不重试、不自动补救，也不开 Dashboard 撤单控件。

## Scope

- Added `nautilus live production-mutation-post-cancel-readback`.
- Added schema `ntpro.v180_post_cancel_readback.v1`.
- The command consumes a ready `ntpro.v180_cancel_response_redaction.v1` artifact.
- The command consumes synthetic/read-only post-cancel readback metadata.
- The artifact classifies:
  - `CANCELED` -> `terminal_canceled`
  - `FILLED` -> `terminal_filled`
  - `REJECTED` -> `terminal_rejected`
  - `EXPIRED` -> `terminal_expired`
  - `MISSING` -> `ambiguous_missing`
  - `UNKNOWN` -> `ambiguous_unknown`

## Artifact Contract

```text
schema_version = ntpro.v180_post_cancel_readback.v1
artifact_type = post_cancel_readback
status = ready_post_cancel_readback_classified
post_cancel_readback_ready = true
post_cancel_readback_classified = true
redacted_metadata_only = true
readback_type = binance_post_cancel_order_readback_redacted_metadata_v1
```

Readback identifiers are persisted only as hash-shaped metadata:

```text
readback_order_id = readback_order_id:sha256:<prefix>:len=<n>
readback_client_order_id = readback_client_order_id:sha256:<prefix>:len=<n>
readback_orig_client_order_id = readback_orig_client_order_id:sha256:<prefix>:len=<n>
```

The artifact rejects raw or sensitive readback material:

```text
headers
body
payload
apiSecret
fills
balances
signature
signed query
signed URL
raw response body
```
