## Summary

V200-006 adds a local Rust guarded single-shot submit candidate gate in
`nautilus-risk`. It requires risk allow evidence, active owner approval,
env-only signing readiness, request builder evidence, matching request digest,
strict release provenance, and an explicit manual online gate before submitted
evidence can be recorded.

Plain Chinese summary: 本任务把真实 submit 前最后一层 gate 落到 Rust 代码里。
preview/dry-run 只产出证据，不消费 approval；submit 模式必须有 manual gate，并会把
owner approval 标记为 consumed。重复 request digest 会被拒绝，不会 retry、replace、
amend、flatten 或批量提交。

## Behavior Impact

The new gate is local Rust evidence logic only. It does not call adapters, open
network connections, store secrets, persist raw signed payloads, read exchange
responses, retry failed submits, or enable Dashboard order controls.

## Public API Impact

New Rust module:

```text
nautilus_risk::v20_submit_candidate
```

New public entry:

```text
evaluate_guarded_single_shot_submit_candidate(request, risk, approval, signing, builder, evaluated_at_unix_ns)
```

No Python, PyO3, Cython, CLI, or Dashboard public API is changed.

## Migration Note

No user migration is required. Downstream V200-007 through V200-012 tasks can
consume `GuardedSubmitCandidateEvidence` as the submit attempt evidence input.

## Rollback Plan

release contract, and evidence. V200-007, V200-008, V200-009, V200-010,
