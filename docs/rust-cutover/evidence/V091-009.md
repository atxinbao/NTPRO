## Discovered Issue And Fix

The first V091 integration run exposed a restart bug: after the first stop,
starting the same registered node could publish `lifecycle_state=running` while
the registry process state was marked `stale`, causing `supervisor stop` to
fail with `node is not running`.

Root cause: the provisional pid artifact reused the previous run's
`started_at` identity until the new running status artifact was loaded. The
process refresh could compare that old identity with the new status artifact
and mark the fresh process as stale.

Fix: clear the provisional `started_at` identity before the startup wait, then
write the full pid identity after the new running status artifact is observed.
