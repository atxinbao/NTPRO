## Hosted Smoke Remediation

PR #312 initially failed the hosted `Rust Cutover Smoke / smoke` job during the
workspace clippy step. The failure was not in the new HTTP testnet probe path;
the hosted workspace clippy gate surfaced existing `crates/core` warnings:

- `clippy::indexing_slicing` in `crates/core/src/hex.rs`;
- `clippy::expect_used` in documented `_unchecked` datetime wrappers.

The remediation keeps behavior unchanged:

- fixed-size hex lookup table indexing remains documented and bounded;
- `decode` now reads each two-byte pair through an iterator instead of slice
  indexing;
- `_unchecked` datetime wrappers still intentionally panic on invalid input, as
  their public docs already state.

## Behavior Impact

Default behavior remains offline. `dry-run` mode does not open sockets even when
the network gate is allowed.

The only new network attempt is:

- workflow: `binance-testnet`;
- mode: `connectivity-probe`;
- CLI flag: `--allow-testnet-network`;
- env: `NTPRO_ALLOW_TESTNET_NETWORK=1`;
- config: Binance Spot testnet, `order_submission=disabled`,
  `real_orders_submitted=false`.

## Public API Impact

No Rust public crate API changes and no CLI command shape changes.

The local workflow artifact contract changes additively. Consumers of
`testnet/connectivity_probe.json` can read the new fields:

- `endpoint_class`;
- `latency_ms`;
- `http_status`;
- `error_code`.
