## 实现结果

- 新增 `ntpro.mvp_status_contract.v1`，写入
  `<workspace>/mvp/status_contract.json`；
- `research` 只声明回测引用已绑定，时效保持 `unknown`，并显式声明未完成研究验收；
- `runtime` 联合 Supervisor 进程状态与节点生命周期，不从进程存活推断节点运行；
- `technical_health` 联合 status、metrics、生命周期和错误；两类工件必须都有效才可为
  `healthy`；
- status/metrics 的 `generated_at` 必须可解析、未超过心跳阈值且代际一致；
- 顶层、execution、risk 和 metrics 错误全部进入错误信封；
- `trading_readiness` 在当前沙盒只读 MVP 中保持 `blocked`，Unified Read Model 缺失
  时为 `availability=missing`；
- 合同按节点心跳间隔原子刷新，干净停止后更新为 `stopped` / `not_running`；
- 启动前清除旧身份/状态合同，并持续验证已发布身份与当前运行身份一致；
- HTTP 成功、进程存活、回测引用和回测完成均不能隐式提升其他维度；
- 外部 Venue、提交、变更、重试、补救和真实订单字段全部为 false。

## 负向测试

- 进程仍在运行但 metrics 缺失：`runtime=running`，技术健康降级为
  `degraded/missing`；
- status/metrics 时间戳陈旧、未知或代际不一致：技术健康不得为 `healthy`；
- 时间戳非法：运行状态和技术健康进入 error；
- status JSON 非法：运行状态为 `unknown/error/stale`，技术健康为
  `unhealthy/error`；
- lifecycle error、execution/risk 错误或源交易边界为 true：技术健康为 unhealthy；
- 运行中身份合同消失：停止工件仍更新，并记录身份错误；
- 旧合同无法清理：节点启动前失败，不继承旧证据；
- 同一工作区已有活动节点：拒绝清理或覆盖其身份与状态合同；
- 周期状态合同写入失败：服务退出并停止节点；
- Dashboard 绑定失败：节点停止；
- Unified Read Model 缺失或非法：交易就绪保持 `blocked`，availability 分别为
  missing 或 error。
