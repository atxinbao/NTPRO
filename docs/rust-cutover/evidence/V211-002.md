## Summary

This patch separates three read-model health semantics:

- `component_snapshot`: local component health may be `healthy`, but the
  top-level snapshot cannot claim unified `healthy`.
- `unified_snapshot`: top-level `health_status=healthy` requires every
  required component to be present, fresh, redacted, sourced, linked, and
  `component_status=healthy`.
- `dashboard_view`: partial display state must expose degraded, missing, or
  unavailable evidence instead of hiding it behind healthy.

Plain Chinese summary: 本任务修正 read model 健康状态语义。单组件可以 healthy，
但不能冒充完整 unified snapshot healthy；Dashboard 可以展示局部状态，但必须明确显示
degraded / missing / unavailable；缺来源、血缘、新鲜度或脱敏证据的 unified snapshot
必须 fail closed。

## Behavior Impact

Local component snapshots no longer create unified top-level healthy. Full
unified healthy and dashboard complete healthy remain valid only when the
required evidence is complete. Missing unified evidence remains fail-closed.

## Public API Impact

The schema now includes optional `snapshot_kind` with values
`component_snapshot`, `unified_snapshot`, and `dashboard_view`. Existing
snapshots without this optional field are not rejected by the schema.

## Rollback

Revert this PR to restore the previous v0.21 fixture expectations and remove
the V211 health-status semantics gate.
