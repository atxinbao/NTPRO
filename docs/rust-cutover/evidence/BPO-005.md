## Summary

BPO-005 removes 18 source-unreachable direct dependency edges from 17 workspace
crates. Sixteen implicit optional-dependency features remain available as
explicit no-op compatibility features, so existing `--features` invocations do
not break. Databento retains its real `nautilus-system` dependency through the
`live` feature.

中文摘要：本任务只清理 Rust manifest 和构建图。共删除 18 条没有源码调用的直接
依赖边，但保留原有 feature 名称和全部 target。Databento 的 live 路径仍显式依赖
`nautilus-system`。同时把 workspace-root 测试从已退役的 `pyproject.toml` 哨兵改为
Rust workspace 的 `Cargo.toml`。没有新增交易、实盘、重试、恢复或控制能力。

The repository's standard `verify_full.sh` isolates 13 common logger-global
tests because the Rust test harness shares a process-wide logger. The first
combined `cargo test` reproduced that known conflict. The final result uses the
same standard split: 938 common tests pass together, all 13 logger-global tests
pass in separate exact invocations, and the remaining affected crates pass.

The initial core run also exposed a stale assertion that required the already
retired `pyproject.toml`. The test and its documentation now use the top-level
Rust `Cargo.toml` workspace marker; `nautilus-core` passes 970/970 tests.

All direct Cargo build and test commands used external
`/tmp/ntpro-bpo005-*` target directories. The governance wrapper recreated a
297.5 MiB repository `target/` while building `ntpro-governance`; `cargo clean`
removed all 1,490 generated files before commit, and repository `target/` is
absent.
