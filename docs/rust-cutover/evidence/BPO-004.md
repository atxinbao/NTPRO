## Summary

BPO-004 adds checked interpolation and yield-curve APIs, rejects malformed
curves at cache ingestion, propagates checked errors through production Greeks
lookups, and removes two runtime `unwrap` calls from the backtest event loop. A
reproducible inventory separates production, test, generated, and FFI signals.

不匹配、tenor 顺序错误和非有限计算结果现在通过 `try_*` API 返回结构化错误；无效
曲线不能写入 cache，Greeks 生产调用链会保留并传播原始错误。旧 API 签名继续保留。
没有增加重试、恢复、交易发送或实盘控制能力。

## Behavior And API Impact

Valid interpolation outputs and backtest ordering remain unchanged. Checked
callers now receive typed errors for malformed inputs. Existing panic-style APIs
remain source compatible, but reject unsorted and non-finite curve data more
explicitly through their checked implementation. `Cache::add_yield_curve`
rejects invalid data before persistence or insertion; production Greeks
lookups add curve-key context while retaining `InterpolationError` as source.

This is an additive public API change plus stricter cache admission behavior.
The required migration note is
`docs/rust-cutover/migration/BPO-004-checked-interpolation.md`. No existing
signature, config schema, persistence format, CLI syntax, or adapter contract
was removed.
