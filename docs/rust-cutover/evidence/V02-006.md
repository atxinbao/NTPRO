## Plain Chinese Summary

这次把本地 supervisor 的 start / stop / status 底座接起来了。

核心变化是：`ntpro-node` 新增了可选 `--stop-file` 参数。传入这个参数后，
节点会先启动到 `Running`，写出 running 状态文件，然后等待 stop file 出现；
supervisor stop 写入 stop file 后，节点会正常停止并把状态写成 `Stopped`。

同时，`supervisor` registry 模块新增了 start、stop、status 方法：start 会按
`ntpro-node` 参数协议启动本地子进程并等待 running status；stop 会写 stop file
并等待 stopped status；status 会读取本地 status artifact。

没有做 Dashboard，没有做 control API，没有接真实交易所，没有真实下单，也没有
发布 release。因为这是 high risk runtime-facing 任务，本 PR 必须停在
`REVIEW_REQUIRED`，不自动合并。

## Goal

Implement supervisor start, stop, and status support for registered local
sandbox nodes using the `ntpro-node` path.

## Behavior Impact

`ntpro-node` can now run in two modes:

- no `--stop-file`: same immediate start/stop smoke behavior as V02-004;
- with `--stop-file`: writes running status, waits for the stop file, then
  stops the sandbox `LiveNode` and writes stopped status.

The supervisor support module can now:

- start a registered node through an `ntpro-node` compatible command path;
- reject duplicate starts when the registry already marks the node running;
- read node status from `status.json`;
- write the stop file and wait for stopped status;
- reject duplicate stops when the registry no longer marks the node running.

## Public API Impact

This adds Rust support APIs in `nautilus-cli::supervisor` for start, stop, and
status behavior. It does not add a user-facing `nautilus` subcommand or an
`ntpro-supervisor` binary in this task; V02-008 owns CLI controls.

`ntpro-node` gains an optional CLI flag:

```text
--stop-file <PATH>
```
