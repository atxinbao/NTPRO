## Plain Chinese Summary

这次把 v0.2 的 supervisor 本地文件接到了 v0.3 dashboard 的后端数据模型上。

大白话说：dashboard 现在不用假数据，也不用直接碰 LiveNode 内部对象，而是读取已有的 `registry.json`、每个节点的 `status.json`、`metrics.json` 和日志路径，然后生成一个 `DashboardSnapshot`。如果文件缺失、内容无效、状态陈旧，snapshot 里会明确写出 gap 和 alert，不会把未知状态伪装成健康。

这次没有实现 HTTP server，没有做 UI，也没有修改交易语义或真实 adapter 行为。

## Implementation Notes

- Added `snapshot_from_supervisor_artifacts`.
- Reads supervisor registry and per-node artifacts through existing JSON DTOs.
- Populates dashboard overview, nodes, data sources, execution gateways, risk,
  runtime modules, logs, metrics, alerts, controls, and gaps.
- Preserves explicit `external_venue_connection=false` and
  `real_orders_submitted=false` visibility from node status artifacts.
- Adds explicit gaps for:
  - missing registry;
  - empty registry;
  - missing status artifact;
  - invalid status artifact;
  - missing metrics artifact;
  - stale process state;
  - stale status or metrics artifacts;
  - unsupported runtime module internals.
- Stabilized an existing supervisor fixture test by waiting for `metrics.json`
  to become parseable before reading it. This avoids racing against the shell
  fixture while it is still writing the metrics file.
