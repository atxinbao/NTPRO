## Plain Chinese Summary

本次给本地 sandbox Supervisor 增加了 `reconnect-execution` 控制。

大白话说：现在控制台可以记录“请求重连执行网关”这个动作，但 v0.3.0
没有接入真实交易所执行网关重连，所以结果会明确写成 `not_supported`。
这不会提交真实订单，也不会假装生产网关已经重连成功；它只把当前限制写进
status、metrics 和 events artifact，让 Dashboard 和 release gate 可以审计。

这次没有打开外部执行连接，没有读取真实凭证，没有提交、修改或取消真实订单，
也没有创建 tag 或 GitHub Release。

## Reconnect Execution Proof

- `start_status_stop_process_roundtrip` now proves:
  - a running sandbox node can receive `reconnect_execution_gateway`;
  - the process remains `SupervisorProcessState::Running`;
  - lifecycle remains `LifecycleStatus::Running`;
  - top-level execution connection becomes `ConnectionStatus::NotSupported`;
  - execution detail connection becomes `ConnectionStatus::NotSupported`;
  - execution detail records the unsupported reason;
  - metrics record the unsupported reason in `last_error_summary`;
  - metrics keep the lifecycle transition count unchanged;
  - events contain `phase=reconnect_execution status=not_supported`;
  - `external_venue_connection=false`;
  - `real_orders_submitted=false`.
- `supervisor_command_handlers_control_fixture_node` proves the CLI command
  handler can execute `ReconnectExecution` against the fixture node.

## No-Real-Order Proof

- The implementation only mutates local supervisor registry/status/metrics/events
  artifacts.
- It does not call execution adapter APIs, open venue sessions, create
  credentials, or submit orders.
- The observable reconnect result is explicit `not_supported` for the current
  local sandbox supervisor path.
