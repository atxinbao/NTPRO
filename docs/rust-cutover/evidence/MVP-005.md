## 实现结果

- 新增 `GET /api/mvp/v1/status`；
- 新增 `ntpro.mvp_shared_status_api.v1` 和版本化响应 schema；
- 聚合 MVP-003 身份合同、MVP-004 四轴状态合同和受控 Unified Read Model 摘要；
- 同一响应明确供 `institution_workbench` 和 `control_center` 使用；
- 对合同 schema、配置重建身份、运行来源、workspace 路径约束、边界、错误信封和
  时效进行请求时复核；
- 顶层或单轴陈旧时旧 healthy 会降级，不依赖源文件中的静态 freshness 声明；
- Unified Read Model 顶层及组件时效会从原始时间戳重新计算；
- Unified Read Model 顶层或 account/positions 组件账户、Venue 串线时不返回业务摘要；
- status、metrics 与 Unified Read Model 的真实 canonical 目标不得逃逸节点产物目录；
- Unified Read Model 缺失时返回 missing，交易就绪保持 blocked；
- 原始 Event Store、原始 Venue payload、写操作、重试和补救能力保持关闭。

覆盖场景：

- 两个门户共享同一合同；
- Unified Read Model 缺失；
- status contract identity 不一致；
- 身份字段缺失或 contract ID 伪造；
- 只读边界字段被改为 true；
- 顶层状态合同陈旧；
- 单轴状态陈旧；
- 顶层或单轴时间戳为零；
- 顶层未来时间戳；
- error 与 availability 自相矛盾；
- Supervisor 运行来源路径被篡改；
- registry 或节点 artifact root 逃逸当前 workspace；
- 合法 artifact root 下 status/metrics 子路径改写到外部；
- Unified Read Model 文件通过 symlink 指向外部；
- identity contract 与实际节点配置重建结果漂移；
- Unified Read Model 账户/Venue 身份不一致；
- Unified Read Model account/positions 组件账户身份不一致；
- Unified Read Model positions/orders/fills 组件 Venue 身份不一致；
- Unified Read Model 成功投影为 available/healthy；
- Unified Read Model 单组件陈旧时整体降级且其他组件保持独立 freshness；
- Unified Read Model 非法 JSON 或 capability boundary 为 true 时 fail closed；
- POST、PUT、PATCH、DELETE 返回 405。
