## Summary

V200-008 adds local Rust post-submit readback reconciliation evidence in
`nautilus-risk`. It consumes a local submit expectation, V200-007 redacted
submit response evidence, and a redacted venue order readback snapshot. It
classifies matched, mismatched, missing, ambiguous, readback_failed, and blocked
states while preserving the no-auto-cancel and read-only Dashboard boundary.

Plain Chinese summary: 本任务把 production submit 之后的 readback reconciliation
落到 Rust 代码里。它对齐本地 submit expectation、脱敏 response evidence 和 venue
readback snapshot，识别订单存在且一致、不一致、缺失、未知或 readback 失败，并为
后续 cancel/audit 提供只读证据输入。它不会自动撤单、重试、改单、补单、平仓，也不会
启用 Dashboard 订单操作控件。

## Behavior Impact

The new reconciler is local Rust evidence logic only. It does not call adapters,
open network connections, submit, cancel, retry, replace, amend, flatten, store
raw readback bodies, persist response headers, or enable Dashboard order
controls.

## Public API Impact

New Rust module:

```text
nautilus_risk::v20_submit_readback_reconciliation
```

New public entry:

```text
reconcile_post_submit_readback(expectation, response, readback)
```

No Python, PyO3, Cython, CLI, or Dashboard public API is changed.

## Migration Note

No user migration is required. Downstream V200-009 through V200-012 tasks can
consume `SubmitReadbackReconciliationEvidence` as the post-submit readback
input for cancel routing, dashboard audit, golden traces, and release gates.

## Rollback Plan

Revert this PR to remove the V200-008 readback reconciliation API, tests,
release contract, and evidence. V200-009, V200-010, V200-011, and V200-012
should remain blocked until replacement readback reconciliation evidence is
available.
