## Summary

V221-002 hardens the Trader Terminal Workbench operation boundary from
optional-false rendering to required-false runtime validation. Missing or true
operation/control fields now fail closed at runtime; explicit false remains
accepted.

Plain Chinese summary: 本任务修复 v22 boundary 不够硬的问题。runtime 不再把
`dashboard_submit_controls_enabled`、`manual_operation_submit_allowed`、
`trader_terminal_order_ticket_enabled` 等字段缺失当作普通 unknown；缺失或 true 都会
产生诊断并让 runtime fail closed。它不启用任何真实交易操作。

Initial broad validation found two v13 fixture tests that expected healthy
production-shadow artifacts but did not set `new_submit_capability=false`.
The fixture writer was updated to keep those artifacts explicit under the
stricter required-false contract, and both tests passed before the full lib
rerun passed.

## Behavior Impact

Runtime behavior is stricter for incomplete Workbench artifacts. Complete
artifacts with explicit false boundary fields keep the same healthy/ready
status. The change does not enable submit, cancel, retry, replace, amend,
flatten, auto-repair, funds transfer, production mutation, or product-grade
live terminal behavior.

## Public API Impact

`TraderTerminalReadModelStatus` now includes `new_submit_capability` as a
serialized dashboard field. This is additive dashboard evidence and does not
create a trading API.

## Rollback Plan

Revert this PR to return to optional/unknown boundary behavior. Do not roll
back by enabling any operation controls.
