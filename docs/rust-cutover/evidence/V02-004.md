## Plain Chinese Summary

这次新增了一个 `ntpro-node` 命令入口，用来跑本地 sandbox-only
节点冒烟流程。它不再只写模拟文字，而是通过已有 Rust `LiveNode`
真正完成 build、start、stop，然后输出 `summary.txt`、`events.log`
和 `status.json`。

这不是生产 live 交易入口，也没有接真实交易所、Dashboard、control API、
手动下单或分布式部署。当前只证明一件事：本地 sandbox 节点可以启动到
`Running`，再停止到 `Stopped`，并且证据里明确
`external_venue_connection=false`、`real_orders_submitted=false`。

因为 V02-004 是 high risk runtime-facing 任务，本 PR 只停在
`REVIEW_REQUIRED`，不自动合并，也不把任务标成 `DONE`。

## Goal

Create a real sandbox-only `ntpro-node` runtime entry that builds, starts,
reports status for, and stops a Rust `LiveNode` without relying on
`simulated_demo` output.

## Behavior Impact

`ntpro-node` now provides a real local sandbox-only LiveNode start/stop smoke.
The command validates the existing live-init smoke config, constructs a
`LiveNode`, registers a simulated sandbox execution client, starts the node,
verifies it reached `Running`, stops it, verifies it reached `Stopped`, and
writes owner-visible artifacts.

The existing `live run` smoke path also writes a `status.json` artifact, but it
keeps `process_mode=test_harness` so it is distinguishable from the spawned
`ntpro-node` process path.

## Public API Impact

This adds a new Rust CLI binary target:

```text
cargo run -p nautilus-cli --bin ntpro-node -- --config <path> [--run-id <id>] [--output <dir>]
```

The new command is sandbox-only. It does not expose production exchange
connectivity, manual order submission, Dashboard control, or distributed node
coordination.

## Migration Note Status

No migration note is required for Python/PyO3/Cython removal. This is an
additive Rust CLI binary for the v0.2 local multi-node runtime foundation.

## Rollback Plan

Revert this PR to remove the `ntpro-node` binary target, the `run_ntpro_node`
wrapper, the `status.json` writing addition in `live.rs`, and this evidence.
The rollback does not require persistence migration because the artifacts are
local run outputs only.
