## Summary

V200-007 adds local Rust production submit response redaction evidence in
`nautilus-risk`. It consumes V200-006 submitted attempt evidence and emits
whitelist-only accepted, rejected, unknown, malformed, or blocked response
evidence without recording raw exchange payloads, headers, credentials,
signatures, tokens, signed query strings, or signed URLs.

Plain Chinese summary: 本任务把 submit response 的脱敏规则落到 Rust 代码里。
evidence 保留后续 readback/audit 需要的最小关联字段和 digest，但不保存 raw response、
header、secret、signature、token 或 Dashboard 原文展示。accepted/rejected/unknown/
malformed 都有固定状态和测试覆盖；redacted response 不是 readback 成功证明。

## Behavior Impact

The new redactor is local Rust evidence logic only. It does not call adapters,
open network connections, parse unrestricted exchange payloads, infer readback
success, retry failed submits, mutate orders, or enable Dashboard raw-response
or order controls.

## Public API Impact

New Rust module:

```text
nautilus_risk::v20_submit_response_redaction
```

New public entry:

```text
redact_production_submit_response(request, submit_attempt)
```

No Python, PyO3, Cython, CLI, or Dashboard public API is changed.

## Migration Note

No user migration is required. Downstream V200-008 through V200-012 tasks can
consume `SubmitResponseRedactionEvidence` as the redacted response input for
readback, failure evidence, dashboard audit, golden traces, and release gates.

## Rollback Plan

Revert this PR to remove the V200-007 response redaction API, tests, release
contract, and evidence. V200-008, V200-009, V200-010, V200-011, and V200-012
should remain blocked until replacement redacted response evidence is
available.
