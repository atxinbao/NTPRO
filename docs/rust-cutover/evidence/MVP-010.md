# MVP-010 - 控制中心单节点生命周期动作产品化证据

Date: 2026-08-04
Executor: Codex
GitHub issue: #1225
Status: REVIEW_REQUIRED

## 中文摘要

控制中心现在只允许运维角色对唯一的本地 sandbox 节点执行启动和停止。页面不会直接
修改节点，也不会开放暂停、恢复、重连或任何交易动作；它调用版本化 API，由既有
Supervisor 路径完成状态转换，再重新读取共享状态和运维投影确认结果。

## 实现结果

- 运维快照升级为 v2，服务端只投影 start/stop、目标节点、POST 方法、enabled 和稳定
  reason code；
- 新增两个 operator-only 版本化 POST 路由，复用既有 `control_action_response`；
- 动作 envelope 显式关闭外部 Venue、外部网络、订单提交/变更、自动重试/补救和真实订单；
- 控制中心要求二次点击确认，动作期间禁用全部生命周期按钮；
- 浏览器不信任 action 响应，严格校验 schema、contract、node、action、状态和边界；
- 动作完成后以 200ms 间隔、最多 5 秒等待 MvpRuntime 四轴状态合同与 Supervisor 工件
  对齐，并要求最终状态等于本次动作目标；超时或反向状态即阻断并移除动作按钮；
- Dashboard 所有生命周期入口共享单一串行锁，直接并发 stop 恰好一个成功、一个 409；
- Supervisor 在 registry 文件锁内拒绝已存在的 `stop.request`，不同 store/process 入口也不能
  重复写入同一次 stop；
- 版本化 action 在锁内重新验证单节点、sandbox-only 及全部外部/真实交易 false 边界，
  不能绕过 GET 投影直接操作额外节点；
- shared status 与 event correlation 继续保持 read-only，机构工作台继续无 action。

## 负向边界

- 无会话或机构角色调用 action：403；
- action 端点 GET/HEAD/PUT/PATCH/DELETE 等：405；
- pause 等未注册 action：404；
- 错误节点：404，错误生命周期：409；
- schema、contract、node、action、状态或任一 false 边界漂移：浏览器 fail closed；
- 控制中心状态读取失败时清空旧节点、组件和动作能力；
- 不包含 submit、cancel、replace、amend、flatten、retry 或 remediation 控件。

## 行为影响

新增本地 operator-only start/stop 产品入口。没有交易语义、订单状态机、adapter、外部
Venue、数据格式或 v0.32.0 冻结面变化。旧 Dashboard unversioned action 保持兼容。

## 公共 API 与回滚

新增 v2 运维投影和版本化 action API，迁移说明见
`docs/rust-cutover/migration/MVP-010-control-center-lifecycle-actions.md`。回滚本任务提交即可
恢复 v1 只读控制中心，不需要迁移 Supervisor registry。

## 独立审查修复

独立 Gatekeeper 对首个 head `a0ad1ea9f9` 给出 `REVIEW_REQUIRED`，指出三个 P1：版本化
action 可绕过单节点 sandbox 投影、并发 stop 存在重复成功窗口、动作后未验证目标最终状态。
修复结果如下：

- action 路径与 GET 投影复用同一 scope validator，并在串行锁内执行；
- 旧 Dashboard 与版本化 action 共用同一锁；Supervisor 同时在 registry 锁内拒绝重复 stop
  marker，并发 stop 回归固定为 1 个 200、1 个 409；
- 浏览器刷新接受 `expectedLifecycleState`，投影虽一致但不等于动作目标时继续 fail closed；
- 增加多节点 503、错误目标 404、并发 stop 和错误最终状态回归。

首个 head 的 hosted 14/14 及 artifacts 只证明当时提交，修复后必须对新 head 全部重跑，不能
沿用旧 head 的通过状态。

修复后第一次 Chrome 负向场景回放暴露测试自身的按钮时序竞争：页面先写入“已阻断”，
`finally` 随后才重新启用刷新按钮，测试在两者之间点击会被浏览器忽略。browser smoke 已改为
等待 `refreshControlCenter()` Promise 完成并直接核对标题/诊断；产品 fail-closed 逻辑未放宽，
随后双门户完整回归通过。
