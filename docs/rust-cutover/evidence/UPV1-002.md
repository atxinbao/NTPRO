## 实现结论

- 产品标准目录固定为 `<workspace>/catalog`；服务端从 workspace 父目录 capability 使用
  `open_dir_nofollow` 固定根目录，并逐级复制到进程私有临时快照；现有 Rust
  `ParquetDataCatalog` 只解析该快照，没有建立第二套数据引擎；
- Product API 新增策略版本兼容数据集读取合同，只返回品种、Venue、完整时间范围、记录数、
  文件统计和内容 SHA-256，不暴露宿主机绝对路径；
- 创建 Backtest 时，服务端重新解析数据引用和 SHA-256，再把该数据集的 instrument 与
  QuoteTick Parquet 文件复制到 Run 自有的 `catalog-snapshot/`；复制过程逐级 no-follow，
  快照内容与原数据指纹不一致即失败；
- 不可变 `request.toml` 只绑定 Run 自有快照、指纹、范围与记录数；Rust
  `ParquetDataCatalog` 在执行前把快照解析成固定的 instrument 与 QuoteTick 内存对象，真实
  `BacktestNode + BacktestEngine` 只消费这些对象，不持有或重新打开 catalog 路径；
- Run 目录由事务式 guard 管理；快照、配置、工件或清单写入中途失败会自动删除不完整 Run，
  只有已记录明确执行失败或已完成全部验证的 Run 才持久保留；
- 页面默认选择兼容的已验证本地数据，并把 `data_ref` 与 `data_sha256` 一起提交；内置
  `synthetic-quotes` 仍作为明确标识的确定性流程来源；
- 服务重启后，Run 继续从不可变工件读取相同数据引用与来源指纹。

## Fail-closed 证据

- catalog 缺失返回 `product_source_unavailable`；
- Parquet 解析前使用固定 capability 句柄递归复制；每级目录和文件均 no-follow，根目录、
  中间目录或文件符号链接、目录类型异常、文件逃逸及复制错误返回
  `product_source_invalid`；
- 根目录句柄固定后，即使 workspace `catalog` 路径被替换成外部 symlink，私有快照仍只包含
  原句柄指向的数据；Parquet 和 Run 快照均不读取替换后的路径；
- 数据指纹不匹配不能进入 BacktestEngine；
- 策略版本不是 QuoteTick、品种/Venue 不兼容或数据引用不唯一时不列出可用数据；
- 历史 Venue `BINANCE` 可显式匹配策略运行环境 `BINANCE_TESTNET`，不会放宽到其他 Venue；
- 记录数不在 `30..=1_000_000` 的数据集不进入 Product API 成功响应；
- 引擎执行前校验 Run 快照的记录数、SHA-256 和完整起止时间，并把该次解析结果固定在内存；
  执行后再次校验同一快照，路径替换不能改变本次引擎输入；
- Product API 和页面继续保持外部 Venue、真实订单、订单 mutation、自动重试和自动补救为
  `false`。

## 行为与迁移

- 行为影响：Backtest 新增可选择的本地真实历史数据来源；已有内置确定性来源继续有效；
- 公共 API：新增兼容数据集 GET 路由，并为 Backtest 创建请求增加可选 `data_sha256`；
- 迁移说明：已有工作区由 `mvp prepare/serve` 创建空 `catalog/`；需要真实历史数据时，将
  标准 Rust Parquet catalog 放入该目录，禁止直接放 CSV 或手工编辑 Parquet；
- 回滚：回退本 PR 即恢复 synthetic-only 产品面；已创建的本地数据 Run 工件必须保留用于
  审计，不能由旧代码伪装成可复现来源。

required-false 边界均未改变。
