这次没有改交易逻辑，也没有改运行时代码。改动只是在 GitHub smoke 里增加一个“产品路径 lint 警告检查”，把 Rust 产品入口相关包里已有的 `unwrap`、`expect`、可能 panic 的索引、以及 `.ok()` 丢弃错误这些风险先暴露出来。当前阶段只报警、不阻断合并；后续再按 `PPL-*` 登记项逐个清理。

## Goal

Start a warning-only rollout for product-reachable panic and silent-error lint coverage without turning existing legacy hits into immediate blockers.

## Files Changed

- `.github/workflows/rust-cutover-smoke.yml`
  - Runs `scripts/ai/check_product_path_lints.sh` for heavy Rust PRs after the existing workspace cargo check and strict clippy gate.
- `scripts/ai/check_product_path_lints.sh`
  - Adds a package-scoped clippy warning sweep for `nautilus-cli`, `nautilus-live`, `nautilus-backtest`, and `nautilus-sandbox`.
  - Uses warning-only lint levels for `clippy::unwrap_used`, `clippy::expect_used`, `clippy::indexing_slicing`, and `clippy::unused_result_ok`.
  - Does not pass workspace feature flags by default, because the preceding workspace clippy step already validates the full configured feature set.
  - Clears external `RUSTFLAGS` and `CARGO_ENCODED_RUSTFLAGS` before running the warning-only sweep so CI-level strict flags do not turn this advisory rollout into a blocking gate.
- `docs/rust-cutover/quality/product_path_lint_register.md`
  - Records the lint rollout scope, warning policy, and follow-up cleanup register.
- `docs/rust-cutover/evidence/P1-003.md`
  - Records this evidence.
