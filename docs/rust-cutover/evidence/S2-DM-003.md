## 验收合同

- 模拟成交必须来自仓库现有模拟执行引擎，不从订单意图推断或伪造；
- 交易、持仓和权益必须绑定 Run、StrategyVersion、输入数据、manifest 和 checksum；
- running 与 frozen snapshot 必须消费同一严格工件；
- Backtest/Demo 比较必须分别验证两侧来源，不允许缺失工件时降级；
- 所有真实交易、自动动作和外部连接边界继续为 false。

## 验证记录

### 运行时与工件

- `StrategySession` 复用仓库现有 `BacktestEngine`、`SimulatedVenue` 与 `EmaCross`，不从
  订单意图伪造成交；
- Demo 每次发布 12 个策略工件，新增 `simulation_summary.json`、
  `simulated_fills.jsonl`、`simulated_positions.jsonl` 与 `equity_curve.jsonl`；
- manifest 对每个工件绑定规范路径、记录数、字节数与 SHA-256；Golden fixture
  `tests/golden/demo_simulation_schema.jsonl` 证明相同输入可重放出相同模拟结果；
- summary、成交、持仓、权益四层都必须显式 `simulation_only=true`。任一层缺失、为 false，
  或任何真实交易边界为 true，Product API 均 fail closed。

### Product API 与前端

- Demo snapshot 升级为 `ntpro.product_api.demo_run_snapshot.response.v2`，running/frozen
  结果返回严格校验后的模拟摘要和明细；
- Run comparison 升级为 `ntpro.product_api.run_comparison.response.v2`，支持已完成
  Backtest 与已停止 Demo，分别校验两侧不可变来源后再计算可比性；
- `behaviorally_comparable` 要求策略、版本、标的和币种一致；`directly_comparable` 还要求
  数据哈希一致；Demo 不支持确定性复现；
- 策略工作台 Run 详情展示 Demo 模拟成交、持仓和资金曲线；比较页明确显示两侧环境和来源，
  生产页面消费真实 Product API，测试 fixture 不进入生产路径；
- 迁移说明位于 `docs/rust-cutover/migration/S2-DM-003-demo-simulation-comparison.md`。
