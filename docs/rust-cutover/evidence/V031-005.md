# V031-005 Evidence - Process Identity Hardening

Date: 2026-06-12
Executor: Codex

Task: process identity hardening

## Plain Chinese Summary

这次修的是本地 Supervisor 判断“节点进程还活着”的依据。之前主要看 pid：
只要系统里还有这个 pid，就容易被当成原来的节点还在跑。

现在 pid artifact 里会多写一份 `process_identity`，包含 node id、
artifact root、status path 和启动标记。后续刷新进程状态时，如果 pid 还活着，
但 status artifact 显示的启动标记或工件路径对不上，就会把这个节点标成
`stale`，不会继续把它当成健康 running。

## Implementation Summary

- Added `SupervisorProcessIdentity` to the local pid artifact.
- Added optional `process_identity` to `SupervisorPidArtifact`.
- Rewrites the pid artifact after startup reaches running status so the runtime
  status `started_at` marker can be recorded.
- Extends `pid_artifact_is_stale` to verify:
  - pid artifact node id;
  - pid value;
  - artifact root;
  - status artifact path;
  - status artifact node id;
  - status artifact artifact root;
  - status artifact `started_at` when both sides provide it.
- Preserves old pid artifacts by treating missing `process_identity` as legacy
  rather than parse failure.
- Adds deterministic identity match and mismatch tests.

## Process-Identity Hardening Result

Covered by `refresh_process_state_accepts_matching_process_identity`:

```text
pid is alive
pid artifact node_id / pid match registry
process_identity started_at matches status artifact started_at
refresh_process_state keeps process_state=running
```

Covered by `refresh_process_state_marks_identity_mismatch_stale`:

```text
pid is alive
pid artifact node_id / pid match registry
process_identity started_at does not match status artifact started_at
refresh_process_state marks process_state=stale
```

## Behavior Impact

Local supervisor process-state refresh is stricter:

- a matching node identity still stays `running`;
- a pid that is alive but points to mismatched status identity becomes `stale`;
- legacy pid artifacts without `process_identity` remain readable.

No trading semantics changed.

## Public API Impact

No public Rust library API changed.

The local pid artifact gains an optional `process_identity` field. Existing
legacy artifacts without the field are still accepted.

## Migration Note

No user migration step is required.

## Rollback Plan

Revert this PR to restore pid-only refresh behavior. If reverted, PID reuse can
again make a mismatched local process look like the original node process.
