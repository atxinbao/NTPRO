## Hosted CI Follow-up

The first PR smoke run failed in `cargo test -p nautilus-cli --lib` because the
new reconnect response assertions were placed inside the real fixture-process
Dashboard test. In the full parallel test suite, that test could observe a
lifecycle/process refresh race and report `invalid_lifecycle_state`.

The fix keeps behavior unchanged and moves the reconnect response assertions to
a deterministic artifact-backed Dashboard HTTP test. That test now writes a
matching status artifact, registry `last_known_status`, process PID, and PID
identity artifact before calling reconnect APIs. The real fixture-process test
now focuses on start/pause/resume/stop behavior and shares the same process
test lock as Supervisor tests.

The Dashboard smoke also exposed a browser-side race: after a reconnect click,
the script could click the next control before the frontend `refresh()` had
re-rendered the controls. The smoke now waits for refreshed enabled buttons and
for the post-action refresh cycle before moving to the next control.

## Reconnect Contract Cleanup Result

The CLI, Dashboard API, Dashboard UI wording, local artifacts, and docs now use
one consistent interpretation: reconnect requests in the local sandbox
Supervisor path record an explicit `not_supported` result. They do not perform
production reconnect, real adapter reconnect, real account recovery, or real
order recovery.

## Behavior Impact

No trading behavior changed. Dashboard reconnect controls still call the same
local Supervisor actions and still return `not_supported`.
