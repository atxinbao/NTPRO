## 当前实现

- 新增独立外部锚点客户端、五项部署配置、HTTPS-only 生产策略和显式 loopback 测试策略；
- compare-and-append 与 latest 均要求 Bearer 认证，token 不进入投影或工件；
- Ed25519 回执严格绑定 namespace、run、run/workspace revision、state/commit SHA、前一全局
  回执、时间和 key id；
- 每个 state revision 保存不可覆盖签名回执，v2 head 绑定 canonical receipt SHA；
- namespace 级全局历史链、本地 workspace head 和远端 latest 在每次读取及动作前重新验证；
  完整工作区回滚到旧快照或候选创建前、远端追加后本地发布失败均可识别；
- Product API 与策略工作台展示锚点状态、run/workspace revision、回执引用和 key id，同时保持
  `trading_authority_granted=false`；
- Runtime、外部行情和全部订单能力仍关闭。

## Hosted 安全公告修复

- PR #1297 首个 head `ff42ab64df2d8f8bd68f42bd0bda2ba18d73eab8` 的
  `security-audit / osv-scanner` 因新公告 `RUSTSEC-2026-0253` 失败；同一 run 的
  cargo-audit、cargo-deny 和 cargo-vet 均通过；
- 公告影响 `lru 0.16.4` 的 `LruCache::pop()` panic safety。该依赖经
  `alloy-provider 2.0.5` 进入 workspace；最新 `alloy-provider 2.3.0` 仍要求 `lru 0.16`，
  暂无兼容升级到修复版 `lru 0.18.2` 的路径；
- 上游实际 `pop()` 缓存键为 `BlockNumber`（整数），另一 LRU 缓存键为 `B256`；二者都没有
  公告触发所需的可 panic `Drop`，且本项目没有用自定义键替换该类型；
- `.cargo/audit.toml`、`deny.toml`、`osv-scanner.toml` 已登记相同的精确临时例外；
  `alloy-provider` 采用 `lru >=0.18.2` 后必须删除，不允许扩展为通配忽略；
- 本地 OSV Scanner 2.3.8：`No issues found`；全新 RustSec database 的 cargo-audit 和
  cargo-deny 均通过。corrective head 的 hosted 结果在最终审查后补齐。

## 行为与回滚

- 缺少或部分配置锚点时，Live Run 创建在发布候选前返回 422；
- 远端 latest 与本地最高回执不一致时，list/detail/action 均 fail closed；
- v1 候选不自动补签，迁移方式见 `S3-LV-005-live-run-audit-anchor.md`；
- 回滚不删除远端回执，且不能开放 Runtime 或订单作为降级路径。
- 外部 append 已成功但本地写入失败时，远端 revision 不回退；运维必须按签名回执恢复或
  隔离本地工作区，禁止删除远端记录或跳过验证。
