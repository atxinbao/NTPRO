Date: 2026-06-11

Task: P1-001 Disconnect Timeout Result

## Plain Chinese Summary

这次修的是 live node 停止流程里的一个结果表达问题：以前等待 data/execution client 断开超时只会打日志，外层仍可能把 stop/finalize 当成成功。现在如果超时后仍有 engine client 显示 connected，`finalize_stop` 会在完成清理和状态落到 `Stopped` 后返回错误。这样以后真实 adapter 接入时，不会把“没断干净”误报成成功。

没有接真实交易所，没有提交订单，没有改交易撮合、风控、账户或 adapter 行为。测试里只加了一个本地 mock execution client，用来证明超时错误能被调用者看到。

## Behavior Impact

- Stop/finalize no longer hides engine disconnection timeout behind logs only.
- Cleanup behavior is preserved: kernel finalization still runs and the handle state still becomes `Stopped`.
- If `disconnect_clients` itself fails, that disconnect error remains the returned error.
- If client disconnect calls succeed but a client still reports connected until timeout, callers now receive an explicit timeout error.

## Public API Impact

- No public CLI, config, dashboard, control API, or adapter API change.
- The changed method is private to `LiveNode`.
- Observable behavior changes only for callers of live node stop/finalize paths that previously received `Ok(())` despite a disconnect wait timeout.

## Migration Note Status

No migration note required. This is a runtime correctness fix for an internal stop/finalize path and does not change a public API contract.

## Rollback Plan

Revert this PR to restore the previous log-only disconnect timeout behavior. Rollback would remove the timeout regression test and the P1-001 risk override note from the task file.
