## 实现结果

- 新增 `/institution-workbench` 独立机构业务入口；
- 新增专属 HTML/CSS/JS，不复用运维 Dashboard 的节点控制脚本；
- 页面只请求 `GET /api/mvp/v1/status`；
- 展示策略与回测身份、账户/Venue、四轴状态、六个业务组件、阻断原因、来源和边界；
- 刷新前清空旧数据，schema、consumer、provenance、合同关联、枚举、业务值、三层边界
  或交易准备度异常时 fail closed；
- 四个读取路由显式拒绝 HEAD 和其他非 GET 方法；
- 仅保留刷新命令，不含节点生命周期、交易、审批、重试或补救控件；
- Dashboard CLI 输出同时给出机构工作台 URL。

## 真实浏览器验证

使用 `configs/nodes/btc-ema-shadow.toml` 启动真实 `nautilus mvp serve` 和
`ntpro-node`，再由系统 Chrome 与 Playwright Core 访问机构工作台。真实 API 成功响应、
边界违规和 HTTP 503 均已验证；异常刷新会先清空旧业务数据，再进入阻断状态。桌面
1440x1000 与移动端 390x844 均无横向溢出。服务关闭后节点正常停止，进程日志确认
`external_venue_connection=false`、`real_orders_submitted=false`。

PR #1212 首次 hosted browser run 暴露测试脚本内联配置缺少真实节点必填字段，节点在
浏览器启动前退出。修复后 browser smoke 改为复用 MVP-005 已验证的 canonical fixture，
并在成功或失败时都上传服务端日志、节点 stdout/stderr 和结构化 `result.json`。最终
hosted 结论以 PR 当前 head 的 `Rust Cutover Smoke` check 和 browser artifact 为准。
Hosted runner 显式安装 Noto Sans CJK，并在截图前用 canvas 像素签名验证关键中文字符
不是同一个缺字方框；PASS 仅在浏览器关闭、MVP 服务优雅退出和节点停止证据验证后写入。

新增测试改变了受控风险扫描统计；已通过同一 canonical scanner 把
`backend_runtime_risk_inventory.json` 从 29,132 / 1,217 更新为 29,289 / 1,221，
production ownership 仍为 2,697，变化仅属于 test / test_inline。

生命周期或交易引擎。M2 仍保持开放，必须等待 MVP-007 控制中心也消费同一共享 API。
所有提交、变更、外部 Venue、重试、补救和真实订单能力继续为 false。
