## 实现结果

- `mvp serve` 与 `dashboard serve` 接受显式 Vite `dist` 目录；
- Cargo 不运行 npm，生产只运行 Rust/Axum；
- Axum 使用 `tower-http` 提供 React 入口、hash 资产和限定范围的 SPA fallback；
- 深层策略工作台 URL 沿用机构访问权限并在 bootstrap 后清除 token；
- 未知 API、未知静态资产和非 GET 请求保持 404/405；
- 已删除旧 Rust 内嵌策略工作台及其自定义 JavaScript VM replay；
- 交易、Live、真实 Venue、重试和自动补救边界未改变。

浏览器视觉复核曾发现右侧抽屉重开时内容区可被 Playwright 自动滚动到左侧菜单下方。
将工作区容器改为 `overflow: clip` 后，桌面截图和 E2E 坐标断言均确认内容区不再位移。

独立审查发现干净检出的运行手册缺少前端构建步骤，以及入口资产校验可能接受部分缺失的
bundle。现已更新正式运行/回滚说明，并改为逐项验证入口引用的全部资产；新增“存在有效
chunk 但主脚本缺失”的负向测试。

final-head 复审指出仅前端改动时 `heavy_rust=false`，真实浏览器 smoke 的 Rust 二进制构建
前置条件不够显式。原 workflow 已在 browser step 内构建二进制，本次将其拆为独立条件
步骤，确保 clean runner 的依赖关系可以直接审查且不会被后续脚本编辑遗漏。

首次 hosted `cargo-vet` 检查识别出启用 `tower-http/fs` 后新增的三个传递依赖尚未登记：
`http-range-header 0.4.2`、`mime_guess 2.0.5`、`unicase 2.9.0`。现已按仓库既有策略补充
三项 `safe-to-deploy` exemption；该修复只更新供应链审计登记，不改变运行时或交易边界。

Hosted checks 与独立 Verification & Release Gatekeeper 审查仍待 PR final head 完成；
在此之前本任务保持 `REVIEW_REQUIRED`。
