## Implemented Behavior

`process_trade_tick` now distinguishes the disabled-execution behavior by book
type:

- L1 retains its existing market-state-only early return;
- L2 updates `core.last`, leaves book bid/ask and trade-size execution state
  unchanged, and runs `iterate` against the current book;
- L3 behavior is unchanged.

The restored trailing test consumes
`tests/golden/execution_l2_trailing_stop.jsonl`. The first trade updates the
LastPrice BUY trail from `1510.00` to `1485.00`; a second trade at `1484.00`
does not trigger even though the unchanged L2 ask is `1500.00`; a third trade
at `1490.00` triggers from `core.last` and fills `1.000` from the book at
`1500.00`. A separate negative control proves that a trade at `90.00` cannot
fill a BUY limit at `95.00` while the L2 ask remains `100.00`.

The same LastPrice source selection now applies before iteration. A BUY stop is
accepted and its trigger can be modified while last is below the trigger even
when ask `1500.00` has crossed it; the order fills from that ask only after
last reaches the amended trigger. A trailing stop with explicit activation
also remains inactive until last reaches the activation price. Other book
types, enabled trade execution, and non-LastPrice trigger types retain the
existing quote-based validation behavior. The LastPrice-aware policy is chosen
by the shared `iterate` entrypoint, so trade, quote, depth, and order-book
updates cannot bypass it. Order type independently selects stop versus touched
comparison direction, and trailing-stop modifications use stop inequalities.
Each disabled-L2 maintenance iteration captures one bid/ask/last snapshot before
matching either side. Trigger checks and trailing recomputation use that
snapshot, so a fill on the first side cannot replace the LastPrice observed by
the second side. BidAsk trailing calculation requires only ask for BUY or bid
for SELL; if required market data is absent, the update is logged and skipped
instead of panicking.

The public backtest contract now distinguishes disabled trade-price execution
from L2 maintenance: L1/L3 continue to skip matching on disabled trade ticks,
while L2 uses last only for LastPrice conditions and the unchanged book for
matching and fills.
