# V091-003 Evidence - Persistent StrategySession Lifecycle

Date: 2026-06-18
Executor: Codex
Task: V091-003 Persistent StrategySession Lifecycle
Risk level: high

## Goal

Keep the StrategySession lifecycle in `running` while the node is still running,
and transition to `stopping` / `stopped` only after an explicit node shutdown
trigger.

## Files Changed

- `crates/cli/src/strategy_session.rs`
  - Changed `run_ema_cross_demo` so it leaves the session in `running` after the
    deterministic fixture batch has produced signals, order intents, risk
    decisions, and summary artifacts.
  - Added `stop_after_shutdown` to make the terminal lifecycle transition
    explicit.
  - Updated unit tests to assert that demo execution does not stop the session
    before shutdown input.
- `crates/cli/src/live.rs`
  - Calls `session.stop_after_shutdown(...)` only after
    `wait_for_strategy_shutdown_trigger` returns.
  - Added a node-level stop-file test that observes `strategy/session_status.json`
    as `running` before writing the stop request, then verifies final `stopped`
    artifacts.

## Behavior Impact

- `node running -> strategy session running` is now represented in the persisted
  strategy session artifact.
- `node stopped -> strategy session stopped` remains true after shutdown.
- The deterministic EMA-cross fixture batch no longer makes the session
  terminal by itself.
- The v0.9.1 no-order boundary is preserved:
  `external_venue_connection=false`, `real_orders_submitted=false`, and order
  submission remains disabled.

## Public API Impact

No CLI command shape changed. `StrategySession::run_ema_cross_demo` behavior is
stricter around lifecycle semantics: it now represents runtime work completion
while leaving the session `running` until explicit shutdown. A new crate-local
shutdown method records the terminal transition.

## Migration Note

Consumers reading `strategy/summary.json` immediately after fixture processing
may now see `state = running` until the node shutdown path completes. Final node
artifacts still end in `stopped` after shutdown.
