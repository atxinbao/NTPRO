## Plain Chinese Summary

这次不是做完整交易系统，而是把用户最容易看到的 CLI 入口补成“真的能跑一小段”的 Rust 路径：

- `backtest run` 现在可以跑一个受限的 Rust 回测 smoke：合成 AUD/USD quotes + Rust `EmaCross` 策略 + Rust `BacktestEngine`。
- `live validate/run` 现在可以验证并启动/停止一个 sandbox `LiveNode` smoke，不连接真实交易所，不下真实订单。
- `data load` 现在可以把本地 QuoteTick CSV fixture 复制进配置里的 catalog 目录，并写 summary。

没有做的事也很明确：没有实现任意策略加载、没有真实交易所 live 连接、没有 adapter 数据加载、没有 Parquet 行级编码、没有 dashboard/control API。

## Implementation Summary

### Backtest

- Added a scoped `engine-smoke` mode for `nautilus backtest run`.
- The mode requires:
  - `run.mode = "engine-smoke"`;
  - `strategy.name = "ema-cross"`;
  - `data.source = "synthetic-quotes"`;
  - `data.instrument_id = "AUD/USD.SIM"`.
- The CLI builds a Rust `BacktestEngine`, adds a simulated venue and AUD/USD
  instrument, generates deterministic synthetic quotes, registers Rust
  `EmaCross`, runs the engine, and writes `summary.txt`.
- `--dry-run` still remains a metadata-only path.

### Live

- Added `crates/cli/src/live.rs`.
- `nautilus live validate` validates the scoped `live-init-smoke` TOML config.
- `nautilus live run` builds a Rust `LiveNode` in `Sandbox` mode, registers the
  `nautilus-sandbox` simulated execution client, starts the node, stops it, and
  writes `summary.txt` plus `events.log`.
- The accepted config explicitly disables:
  - order submission;
  - startup reconciliation;
  - external venue connection.

### Data

- `nautilus data load` now supports a scoped fixture loader:
  - `source.kind = "fixture"`;
  - `source.schema = "quote_tick_csv_v1"`;
  - `mapping.data_type = "QuoteTick"`;
  - `mapping.timestamp_column = "ts_init"`.
- The CLI validates the CSV header and copies the fixture into the configured
  catalog directory.
- It writes owner-visible summary output and rejects unsupported schemas.

## Behavior Impact

- `backtest run` without `--dry-run` no longer returns a blanket
  not-implemented blocker for the scoped engine-smoke config.
- `live validate/run` no longer returns blanket not-implemented blockers for
  the scoped live-init smoke config.
- `data load` no longer returns a blanket not-implemented blocker for the
  scoped QuoteTick fixture config.
- Unsupported combinations are rejected explicitly instead of being silently
  accepted.

## Public API Impact

CLI behavior changed for scoped configurations only:

- new accepted `backtest` mode: `engine-smoke`;
- new accepted `live` mode: `live-init-smoke`;
- new accepted `data load` fixture schema: `quote_tick_csv_v1`.

No Rust public library API signatures changed. No persistence format is claimed
as stable. No adapter behavior changed.

## Migration Note Status

Product docs and example README files were updated in this PR. A separate
external migration note is not required because this is a new scoped CLI
capability rather than a breaking change to an existing supported runtime path.

## Remaining Boundaries

- No arbitrary Rust strategy loading from config.
- No adapter/catalog-backed backtest data load into the engine.
- No production live adapter behavior.
- No real venue connection.
- No real order submission.
- No Parquet row encoding or row-level catalog semantic decode in `data load`.
- `sandbox run` remains a deterministic simulated demo; DRG-005 promotes
  `live run` as the real minimal LiveNode start/stop smoke.

## Rollback Plan

CLI paths. If reverted, reset `DRG-005` to `TODO` or `RUNNING`, mark G4 as not
passed in v0.2 readiness tracking, and remove the DRG-005 examples from the
