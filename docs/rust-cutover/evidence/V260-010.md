## Summary

V260-010 fixes the second `ntpro-rust-only-v0.26.0` hosted release gate failure.
The failure was in `verify-release (release-v26-release-gates)` for run
`28837721770`, job `85524998240`.

Plain Chinese summary: v26 release gate 会把 v25.1 当作历史前置证据重新校验。
v25.1 自己发 tag 时必须要求 HEAD 等于 v25.1 tag commit；但从 v26 tag 调用时，
HEAD 必然是 v26 commit，所以这个校验必须显式进入 historical prerequisite 模式。
这次修复只增加该模式，不放松 v25.1 直接 tag gate。

## Root Cause

`scripts/ai/verify_v26_intake_gate.sh` invoked
`scripts/ai/verify_release.sh v25.1-release-gates` while the hosted workflow
was running on `ntpro-rust-only-v0.26.0`. The nested v25.1 gate still enforced
`HEAD == ntpro-rust-only-v0.25.1`, which is correct for direct v25.1 tag-stage
execution but incorrect for v26 historical prerequisite validation.

## Change

- Added `NTPRO_V251_RELEASE_HISTORICAL_PREREQ=1`.
- `verify_v25_1_release_gates.sh` skips only the tag-head assertion when that
  explicit historical-prerequisite flag is set.
- `verify_v26_intake_gate.sh` sets the flag for its nested v25.1 prerequisite
  call.
