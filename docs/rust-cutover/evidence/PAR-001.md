## Review Correction

The first pushed implementation re-read cache immediately after dispatching
`OrderUpdated`. PR review identified that sandbox execution queues these events,
so cache can still contain the pre-update quantity at that point. The final
implementation does not rely on synchronous event consumption: `update_order`
passes its already validated effective quantity into the contingent helper.
The quantity-propagation regression now uses an event recorder that
intentionally does not update cache before the contingent decision.
