GitHub PR: pending

## Problem

The required PR smoke ran `v33-maintenance-release` after v0.33.0 publication.
The guard required the frozen release tag commit to equal the checked-out PR
commit, so every later governance PR failed. A first attempted bypass also
allowed arbitrary mismatches and caused strict provenance to describe the PR
HEAD as v0.33.0 source.

## Resolution

`NTPRO_V33_ALLOW_POST_RELEASE_HEAD=1` now permits a mismatch only when
`ntpro-rust-only-v0.33.0` is an ancestor of the checked-out commit. The default
still requires equality.

PR smoke no longer invokes `v33-strict-provenance`. Strict provenance belongs
to the frozen tag/release tree and must not be regenerated from a later PR
HEAD. The PR still validates current governance, the v0.32.0 backend freeze,
the v0.33.0 maintenance contract, and publish-after-gate behavior.

`release-tag.yml`, `release-publish.yml`, and all v0.32.0/v0.33.0 release
artifacts remain unchanged.

## Behavior And Rollback

This changes repository verification behavior only. It does not change the
runtime, public API, adapters, schemas, trading behavior, or published release.

Rollback is a Git revert. Reverting before replacing the check would restore a
required PR gate that cannot pass after v0.33.0 publication.
