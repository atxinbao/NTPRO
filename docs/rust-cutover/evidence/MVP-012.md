## 首轮独立审查修正

Rust Product Surface Agent 对 head `e60386c152ecca53cea31937def15c85897e4096` 输出
`CHANGES_REQUESTED`：stale 恢复仍接受不完整身份、无自动恢复观察窗口不足、失败清理未
追踪全部 PID、cargo build 失败前没有 artifact。修正后：

- stale 恢复额外要求 PID artifact/status 完整、running + spawned_process、artifact root、
  started_at 与 OS 进程启动时间全部一致；14 类反例均保持 stale；
- SIGTERM 和 SIGKILL 各执行超过 6 秒、12 个样本的无动作观察，registry/PID/共享状态和
  lifecycle events 均保持不变，再允许人工 start；
- 每个 session 追踪所有观察过的节点 PID，删除临时 workspace 前逐个确认退出；
- hosted step 在 cargo build 前预创建 fail evidence，构建失败也能由 `always()` 上传。

第二次复审对 head `6f412a4986bab3a468b40bf05a75edef90ad7ba1` 指出首次启动补全
可能被运行后裁剪 `started_at` 重新触发。最终修正要求 PID identity 自身也必须处于从未
建立 `started_at` 的 initial pending 状态；已建立身份后，status 缺失或更换 started_at
都会保持 stale，且 PID identity 保留原值。完整序列回归已通过。

首个获批 head `3b643a5e50` 的 hosted smoke run `30924697127` 在 Linux hard-kill
投影超时。失败 artifact 已成功上传并脱敏。根因是 Linux zombie 仍可由 sysinfo 返回 OS
启动时间，而 stale 严格 matcher 尚未同时调用 `process_is_alive`；该函数已明确把 Zombie
判为不存活。最终修正要求“存活检查 + OS 启动时间 + 完整身份”同时成立，并为等待失败
增加最后一次共享投影诊断。修正后本地 11-case 矩阵再次通过，等待新 hosted run。

第四次独立复审对 head `32ce9b1795` 指出 `process_is_alive` 与启动时间来自两次 sysinfo
快照，仍有 TOCTOU；通用检查也接受 Dead。最终实现改为单次 sysinfo 快照同时取得状态和
启动时间，并仅允许 Idle、Run、Sleep、Wakekill、Waking、UninterruptibleDiskSleep 进入
严格再验证；Zombie、Dead、Unknown、Stop、Tracing、Suspended 等均由单元测试确认拒绝。

首次构建由 shell 中 Homebrew Rust 1.87.0 拒绝；随后将
`/Users/mac/.rustup/toolchains/1.95.0-aarch64-apple-darwin/bin` 置于 `PATH` 首位，使用仓库固定
Rust 1.95.0 完成全部 Rust 验证。该失败不属于产品代码失败。
