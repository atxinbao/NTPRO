## 实现状态

- 新增标准 Node.js 故障矩阵验收器，只调用真实 `nautilus` 和 `ntpro-node`；
- 每个进程案例使用独立、初始不存在的临时 workspace；
- 工件案例在真实节点 SIGSTOP 后注入，随后恢复原始可信工件并 SIGCONT；
- 外部 SIGTERM 使用既有 operator start，hard-kill 使用既有 Supervisor CLI 显式 start；
- hard-kill 后先验证 registry stale、共享状态 fail closed、控制中心 stop 失败，以及观察窗口
  内没有自动新 PID；
- 初次真实运行确认 invalid status 会按预期把仍存活节点标记 stale，但可信 status 恢复后
  从不重新验证，导致节点永久卡死；任务已提升为 high risk，并限定修复为原 PID 存活且
  PID/进程/status 身份全部匹配时重新归类 running，不放宽 hard-kill 或身份失败边界；
- 所有结果写入 `ntpro.mvp_fault_matrix_evidence.v1`，日志和 JSON 写入前执行 token/cookie
  脱敏检查。
