# V091-006 Evidence - Kill Switch Enabled And Active Semantics

Date: 2026-06-19
Executor: Codex
Task: V091-006 Split Kill Switch Enabled And Active Semantics
Risk level: medium

## Goal

Separate kill-switch configuration from active kill-switch state so Strategy
Runtime risk artifacts no longer overload a single `kill_switch` boolean.

## Files Changed

- `crates/cli/src/strategy_session.rs`
  - Replaced `kill_switch` risk decision output with
    `kill_switch_enabled` and `kill_switch_active`.
  - Added `StrategyRiskControls`.
  - Emits `kill_switch_active` rejection reason only when the active state is
    true.
- `crates/cli/src/live.rs`
  - Reads `risk.kill_switch_enabled` and `risk.kill_switch_active` from
    strategy node config.
  - Passes those controls into `StrategySession`.
- `crates/cli/src/config.rs`
  - Updates strategy-session config fixtures and validation error wording.
- `configs/nodes/btc-ema-shadow.toml`
  - Uses `kill_switch_enabled = true` and `kill_switch_active = false`.
- `crates/cli/src/dashboard.rs`
- `crates/cli/src/supervisor.rs`
  - Updates test fixtures to the explicit kill-switch fields.

## Behavior Impact

- Default v0.9.1 strategy runtime config expresses kill switch as enabled but
  inactive.
- Risk decisions no longer contain ambiguous `kill_switch`.
- Active kill switch state still rejects intents with `kill_switch_active`.
- No order submission path was enabled; `actual_submission=false` and
  `actual_submission_count=0` remain enforced.

## Public API Impact

The Strategy Runtime risk decision artifact schema changes from:

```text
kill_switch: bool
```

to:

```text
kill_switch_enabled: bool
kill_switch_active: bool
```

CLI command shape is unchanged.

## Migration Note

Consumers should read `kill_switch_enabled` for configured capability and
`kill_switch_active` for active blocking state. `kill_switch_active` appears in
`reasons` only when the active state is true.
