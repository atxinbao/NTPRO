## 交付边界

- 比较接口只接受 2 至 4 个唯一 Run ID，并逐个加载可信 completed/available Backtest；
- 响应保持请求顺序和首项基准身份，报告版本、数据、标的、币种与 `directly_comparable`；
- 静态历史 fixture 与动态引擎 Run 的 `data_ref` 相同但数据 SHA 不同，因此正确标记为仅可
  并列查看，不生成误导性的直接比较结论；
- 复现只能由用户显式提交 `deterministic_replay=true` 触发，创建新 Run 且不覆盖源文件；
- 服务端从源 `request.toml` 重建输入，真实重跑 `BacktestEngine`，对参数、数据、交易、持仓、
  权益、风险、回撤和运行事件计算去除 Run 身份后的语义指纹；
- 每个新 Run 写入 `strategy-version.json` 并由 manifest 绑定 SHA-256；读取和复现时按 Run
  自己的版本定义、内容哈希、参数 schema、数据要求和禁止能力验证，版本升级后旧 Run 仍可读；
- `reproduction.json`、Run manifest 和 Product Run 互相绑定 SHA-256；读取证明时重新加载并
  校验源/目标全部产物和指纹；
- 工作台支持选择 2 至 4 个 Run、展示兼容性和比较矩阵、显式确认复现并跳转新 Run；
- 历史 Run 通过 `reproduction_ref=null` 保持兼容；所有 Demo、Live、Venue、订单、自动重试、
  自动补救和交易控件能力继续关闭。
