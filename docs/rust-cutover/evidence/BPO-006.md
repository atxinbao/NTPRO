## Scope And Threshold

BPO-006 selects one benchmark-proven hotspot family: the default-quota path in
`RateLimiter::check_key`. No other runtime path is changed.

The acceptance threshold was fixed before the implementation:

```text

required improvement = at least 10%
baseline and candidate CV = at most 5%
correctness = default, keyed, dynamic-add, boundary, property, and concurrency tests pass
```

## Implementation

`RateLimiter` records whether any keyed quota has been published. The common
default-only path uses one acquire load and directly evaluates the default
GCRA. `add_quota_for_key` inserts the GCRA before publishing the flag with a
release store, so a completed add remains visible before keyed lookup is
enabled.

The rate algorithm, clock read, state-store CAS, quota values, waiting behavior,
public method signatures, and keyed lookup behavior remain unchanged.
