## Plain Chinese Summary

这次做的是“联网前的保险栓”，不是正式联网。

大白话说：以后 Binance testnet 想真的打开网络，必须同时满足命令行开关、
环境变量和配置里的只读条件。少任何一个条件都会 fail-closed，artifact 里会写
`network_gate_status=blocked`，并且保持 `network_attempted=false`。

即使所有门禁条件都满足，V070-001 也不会真的发 HTTP 请求；真实 HTTP 只读 probe
留给 V070-003。这个 PR 不下单、不读写真实资金、不改 Dashboard 控制行为。

## Goal

Add a fail-closed v0.7 network opt-in guard for the Binance testnet workflow
before any future HTTP/WebSocket probe code can open a socket.

## Behavior Impact

Default behavior remains offline. The testnet workflow now records a v0.7
network gate result in `testnet/connectivity_probe.json`.

Blocked cases are owner-visible through:

- `env_network_permission`;
- `network_gate_status`;
- `network_gate_reasons`;
- `diagnostic`.

No HTTP client or WebSocket client is created by this task.

## Public API Impact

The local workflow artifact schema changes additively for the connectivity
probe artifact. Existing Dashboard/manifest readers can continue to deserialize
because the added fields have serde defaults.

CLI help text is updated, but the command shape is unchanged.

## Migration Note

`testnet/connectivity_probe.json` to use
`ntpro.v07_binance_testnet_connectivity_probe.v1` and include gate fields.
