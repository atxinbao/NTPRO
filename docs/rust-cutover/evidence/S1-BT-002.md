## 交付边界

- 新增机构用户专用 `POST /api/product/v1/runs`，匿名与运维角色均 fail closed；
- 请求仅允许当前登记的 StrategyVersion、数据集、模拟 Venue 和 `backtest` 环境；
- 服务端在 blocking worker 中运行真实 `BacktestEngine`，不启动外部进程、不接收文件路径；
- 每个 Run 使用服务端 ID 和独占目录，依次写入不可覆盖的 `request.toml`、`summary.json`、
  `run-manifest.json`，清单最后落盘；
- 动态 Run 通过既有 list/detail/metrics 合同读取，配置、输入、结果和身份哈希逐项验证；
- Backtest 创建是唯一开启的创建能力；Demo、Live、外部 Venue、真实订单、订单变更、自动重试、
  自动补救、自动恢复和交易控件继续关闭。

## 纠正记录

- 首轮前端验证发现 `AppShell.tsx` 仅有 Prettier 格式漂移；格式化后完整前端验证通过；
- 一次使用了 Vitest 不支持的 Jest 参数 `--runInBand`，改用仓库标准 `npm test` 后通过；
- 旧真实浏览器 Smoke 仍把新 POST 路由预期为 405；已改为验证合法创建，并以 `PUT` 验证
  collection 的 `Allow: GET, POST` 405 合同。
- 最终自审发现回测产物根目录本身也需要 containment；创建、动态读取和指标读取现统一通过
  canonical root 校验，符号链接指向工作区外时 fail closed，并新增直接回归测试。
- Gatekeeper 首轮复审发现 manifest 最终文件可能被并发读取到半写状态；现改为同目录临时
  文件完整写入并同步，再以 hard link 原子且不可覆盖地发布，残留临时文件不会进入读取面；
- Gatekeeper 首轮复审发现并发 POST 会在 blocking pool 排队；现于进入 worker 前使用单许可
  `try_acquire_owned`，第二个并发请求立即返回 409，测试确认只发布一个 Run；
- Gatekeeper 首轮复审发现公开 `trade_size` schema 比服务端宽；OpenAPI 与生成 Zod 现统一要求
  六位小数，合同测试确认 `0.001` 在客户端边界即被拒绝。
- Gatekeeper 二轮复审发现最终 `cargo fmt` 改变了 canonical 风险行号哈希；统计数量与 production
  ownership 不变，已回写最终稳定 SHA 并重新通过风险清单 gate。
