## Plain Chinese Summary

这次修的是本地 Supervisor 注册表锁。之前如果命令写下了
`registry.json.lock` 后进程异常退出，后面的 supervisor 命令只能一直等到超时
再失败，容易让本地控制面卡住。

现在锁文件会写成带 schema、pid 和 acquired_at 的 JSON 工件。新的命令看到锁
以后会先检查锁里的 pid 是否还活着：如果持锁进程已经不存在，就清理旧锁并重新
获取锁；如果持锁进程还活着，就继续明确阻塞，避免两个命令同时写注册表。

## Implementation Summary

- Added `SUPERVISOR_REGISTRY_LOCK_SCHEMA_VERSION`.
- Added JSON `RegistryLockArtifact` with:
  - `schema_version`
  - `pid`
  - `acquired_at`
- Kept parsing support for the previous legacy text lock format:
  - `pid=... acquired_at=...`
- Added stale-lock inspection:
  - dead owner pid -> recover by deleting the stale lock and retrying;
  - live owner pid -> wait and then return a clear timeout error;
  - unreadable / unknown owner lock -> treat as active unknown owner, not blindly delete.
- Added deterministic tests for:
  - stale dead-owner lock recovery;
  - active lock timeout/refusal.

## Stale Lock Recovery Result

Covered by `stale_registry_lock_owned_by_dead_process_is_recovered`:

```text
dead pid lock exists
next acquire detects owner pid is not alive
old lock is removed
new lock is acquired with current process pid
lock is removed on guard drop
```

Covered by `active_registry_lock_is_refused_after_timeout`:

```text
current process pid lock exists
next acquire treats it as active
timeout error includes active pid and acquired_at
active lock remains in place
```

## Behavior Impact

Local supervisor registry writes are more recoverable:

- stale locks from dead local owner processes no longer wedge the control plane;
- live competing owner processes still block conflicting registry access;
- lock files are now inspectable JSON artifacts.

No trading semantics changed.

## Public API Impact

No public Rust library API changed.

The local lock artifact format changed from text to JSON, but the old text lock
format is still parsed for recovery and active-owner detection.

## Migration Note

No user migration step is required. Existing stale text locks with a parseable
`pid=...` field are still understood.

## Rollback Plan

Revert this PR to restore the previous text lock behavior. If rollback happens,
stale dead-owner registry locks may again require manual deletion of
`registry.json.lock`.
