## Plain Chinese Summary

这次改动把 v0.2 发布门禁从“快速检查”升级成“真正接近发布前检查”：先跑完整验证，再做 release 构建，再检查 release 产物里的 `nautilus` 和 `ntpro-node` 是否存在，并确认 CLI help 里有 supervisor、sandbox-only、config、stop-file 等关键入口。最后把双节点 supervisor smoke 也接进 release gate，并禁止 release gate 使用跳过构建的快捷开关。

这次没有创建 tag，没有发布 GitHub Release，没有连接真实交易所，也没有提交真实订单。过程中 release gate 暴露了 `nautilus-cli` 的 clippy 问题，所以同步做了小范围 clippy 清理，不改变 dashboard/supervisor 行为。

## Goal

Upgrade `scripts/ai/verify_release.sh` so v0.2 release decisions depend on the real full validation path, release binaries, Rust-only/Cython gates, CLI product-surface help checks, and v0.2 two-node supervisor smoke.

## Behavior Impact

- Release validation is stricter.
- A release tag or manual release-gate workflow now fails if:
  - full verification fails;
  - release binaries are missing;
  - release CLI help does not expose required v0.2 product-surface commands;
  - Rust-only or Cython removal checks fail;
  - the v0.2 two-node smoke fails;
  - release mode tries to skip the smoke build.
- Dashboard and supervisor behavior are unchanged; CLI source edits were clippy-only cleanup.
- No trading semantic changes.
- No real exchange connection.
- No real order submission.

## Public API Impact

- No Rust public API change is intended.
- No CLI command contract was added or removed.
- A new GitHub Actions release-tag gate was added for release tags and manual dispatch.

## Migration Note

No migration note is required. This is release-gate hardening and local validation cleanup only.

## Rollback Plan

Revert this PR to restore the previous release gate behavior. If the release-tag workflow itself causes operational problems, remove `.github/workflows/release-tag.yml` first, then revert the release gate script changes.

## Residual Risk

- Release build is slow because the current workspace release build compiles many binaries with release optimization. This PR intentionally keeps the strong build path because the task goal is release confidence, not speed.
- GitHub Actions runtime may be longer than local fast smoke because the new tag workflow runs the full release gate.
