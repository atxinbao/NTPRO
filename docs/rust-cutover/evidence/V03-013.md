## Plain Chinese Summary

本次给本地 sandbox Supervisor 增加了 `reconnect-data` 控制。

大白话说：现在控制台可以记录“请求重连数据源”这个动作，但 v0.3.0
还没有接入真实交易所数据源重连，所以结果会明确写成 `not_supported`。
这不是失败隐藏，也不是假成功；它会把结果写进 status、metrics 和 events
artifact，方便 Dashboard 和发布检查看到真实状态。

这次没有打开外部交易所连接，没有读取真实凭证，没有提交真实订单，也没有创建
tag 或 GitHub Release。

## Reconnect Data Proof

- `start_status_stop_process_roundtrip` now proves:
  - a running sandbox node can receive `reconnect_data_source`;
  - the process remains `SupervisorProcessState::Running`;
  - lifecycle remains `LifecycleStatus::Running`;
  - data connection becomes `ConnectionStatus::NotSupported`;
  - status records the unsupported reason;
  - metrics record the unsupported reason in `last_error_summary`;
  - metrics keep the lifecycle transition count unchanged;
  - events contain `phase=reconnect_data status=not_supported`;
  - `external_venue_connection=false`;
  - `real_orders_submitted=false`.
- `supervisor_command_handlers_control_fixture_node` proves the CLI command
  handler can execute `ReconnectData` against the fixture node.

## No-Real-Venue Proof

- The implementation only mutates local supervisor registry/status/metrics/events
  artifacts.
- It does not open sockets, create credentials, call adapter APIs, or submit
  orders.
- The observable reconnect result is explicit `not_supported` for the current
  local sandbox supervisor path.

## Behavior Impact

Local sandbox supervisor users gain an auditable data-source reconnect control
result. Production adapter reconnect behavior is unchanged and still outside
v0.3.0 scope.
