## Plain Chinese Summary

本任务只修本地 Dashboard 浏览 workflow artifact 的路径，不连接 Binance、不下单、
不读取真实密钥，也不改变 supervisor 控制语义。

大白话说：以前 Dashboard 主要从 supervisor registry 推导 workflow artifact
位置。如果 registry 文件缺失，页面/API 容易只看到一个空快照。现在 `dashboard
serve` 可以显式传 `--workflow-root runs/workflows`，即使 supervisor registry
缺失，也能只读展示已经生成好的 `v06-smoke` workflow artifact。节点控制仍然只看
registry，不会因为 workflow artifact 存在就假装有可控制节点。

## Behavior Impact

- `dashboard serve` now accepts an explicit `--workflow-root` for read-only
  workflow artifact discovery.
- Missing supervisor registry still produces a `supervisor.registry` gap.
- Workflow artifact browsing no longer depends on a valid supervisor registry
  when `--workflow-root` is provided.
- Dashboard node controls remain registry-backed.
- No network behavior changed.
- No order behavior changed.
- No Binance testnet connectivity was attempted.

## Public API Impact

- CLI addition: `nautilus dashboard serve --workflow-root <PATH>`.
- Dashboard metadata API now includes `workflow_root`.
- Dashboard snapshot API can include `workflow_artifacts` even when supervisor
  registry is missing, but only when an explicit workflow root is configured.

## Migration Note Status

No separate migration note is required. The new option is additive and local-only.
Existing `dashboard serve --registry <path>` usage keeps the previous automatic
workflow artifact discovery behavior.

## Rollback Plan

Revert this PR to remove `--workflow-root` and return Dashboard workflow artifact
discovery to registry-derived paths only.

Rollback is local UI/API behavior only. No exchange state, secret, order, or
persistent database migration is involved.
