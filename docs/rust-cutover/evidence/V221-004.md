## Summary

V221-004 adds a controlled Rust-only release publication path. The public
GitHub Release can now be published only after a successful hosted
`Rust Cutover Release Gate` run is supplied for the same tag commit.

Plain Chinese summary: 本任务把 v0.22.1 的公开发布入口改成 gate-before-publish。
可以先准备 draft release；但公开发布必须先证明对应 tag 的 hosted release gate 已
成功，并且 gate run 的 `headSha` 与 tag commit 一致。失败 gate、未完成 gate、或
早于 gate 成功时间的公开 release 都会被拒绝。

## Hosted Check Follow-up

The first PR run for `#722` failed `cargo-audit`, `cargo-deny`, and
`osv-scanner` because the live advisory databases reported `quick-xml 0.39.4`
as vulnerable through the existing `object_store 0.13.2` dependency path.
`DataFusion 53.1.0` depends on `object_store 0.13.x`; `object_store 0.14.0`
still depends on `quick-xml 0.40.1`, below the advisory fix target
`quick-xml >= 0.41.0`. V221-004 therefore records a temporary, documented
ignore for `RUSTSEC-2026-0194` and `RUSTSEC-2026-0195` in all three audit
configs until DataFusion/object_store can resolve a compatible upgrade.

The first hosted smoke run for `#722` also revealed a workflow classification
gap: `verification.md` evidence updates were not treated as documentation, so
the run entered the heavy Rust path and skipped the release verification script
checks. The classifier now whitelists `verification.md`; local simulation of
the Actions classify step reports `heavy_rust=false` and `release_verify=true`.

## Behavior Impact

No runtime behavior changes. This changes release governance only. It does not
create a tag, publish v0.22.1, change strict provenance semantics, or enable
any trading capability.

## Public API Impact

No public API changed.

## Migration Note

No user migration note is required. Release operators must use
`Rust Cutover Publish Release` or `scripts/ai/publish_ntpro_release_after_gate.sh`
after the hosted release gate succeeds.

## Rollback Plan

Revert this PR to restore the previous tag-gate-only publication governance. If
a public release is accidentally published before the gate succeeds, delete the
premature release object without moving the tag, wait for the hosted gate to
succeed, then recreate or publish the release through the controlled entrypoint.
