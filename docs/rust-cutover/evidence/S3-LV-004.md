## 当前交付

- Product API 已实现候选 list/create/detail/action 四个端点和
  `created -> preflight_ready -> stopped` / `created -> stopped` 状态机；
- 候选绑定不可变 StrategyVersion 内容哈希、生产 Binance Spot Venue、账户引用、风险配置
  内容哈希和准入来源；
- 五项候选运行门禁独立于 Backtest、Demo 和生产账户只读门禁，并要求当前风险配置的
  kill switch 已启用且未触发；
- preflight 会重新验证版本、准入、凭证、账户连接和 `can_trade`，但不会启动 Runtime；
- request、manifest、preflight、stop、每个状态 revision 和工作区状态 commit 均不可覆盖；
  状态与 commit 各自形成 SHA-256 前向链，`state-head.json` 以 capability-based 原子替换固定
  最高 revision；单一状态、commit、head 或动作工件的删除、篡改和不完整写入均 fail closed；
- `.live-run-mutation.lock` 通过 `create_new` 串行化跨进程创建、陈旧指针替换和动作竞争，
  `.active-candidate.json` 再声明工作区单活候选；陈旧锁一律 fail closed，不自动接管；
- 读取投影严格拒绝单链状态/动作工件删除或回滚、超过 64 KiB、身份漂移、未知字段、非法时间、
  来源漂移和任何订单访问/发送尝试；
- 工作台仅在显式账户检查成功且 `can_trade=true` 后启用候选创建，并明确展示 Runtime 未启动、
  订单准入已阻断；
- OpenAPI、生成 SDK、严格客户端、fixture、mock server 和页面状态已同步；页面刷新后从集合
  GET 恢复未停止候选，`created` 状态也允许人工停止。

## 边界与回滚

- `runtime_started=false`，市场数据连接、订单 endpoint、submit/cancel/replace、成交对账、
  自动重试、自动补救和自动恢复全部关闭；
- 默认环境缺少独立候选门禁，创建必须返回 422 且不生成工件；
- 本地哈希链不是 WORM：拥有整个 workspace 写权限的主体若同步恢复候选、commit 和 head 的
  完整旧快照，本任务不能检测；外部不可回滚审计锚点是后续真实 Runtime 与订单准入的硬前置；
- 进程异常退出若遗留 `artifacts/.live-run-mutation.lock`，系统保持拒绝写入；运维确认没有
  候选写进程后才可人工删除该锁文件，禁止自动超时接管；
- 回滚删除候选路由、工件投影、OpenAPI/前端入口和五项候选门禁，不涉及外部账户或订单状态。
