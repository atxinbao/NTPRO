## 缺陷复现

- 全新 `mvp serve` 工作区的 Run API 返回 `503 product_source_unavailable`，字段为
  `result_root`；手工创建 `artifacts/backtests` 后立即恢复 200；
- node 运行时 Demo 创建按合同返回 `409 supervisor_node_state`；通过控制中心停止 node 后，
  Run 与 Demo 创建均返回 `503 product_source_stale`，字段为 `node_status`；
- 1280x720 浏览器中，Backtest 的“创建并运行”按钮被底部活动区拦截；1440x1000 可点击；
- 手工绕过目录问题后，真实 BacktestEngine 成功生成 120 条行情、5 笔成交、5 个持仓与完整
  收益/风险/事件结果，证明引擎本身可用，阻塞位于产品启动和页面布局合同。

## 修复边界

- 初始化空 Backtest 根目录不伪造任何结果；
- MVP prepare 现在显式创建空 `artifacts/backtests`，不生成或伪造任何 Run 结果；
- stopped node 仅在全部 Run 所有权均已终态、不存在，或恰好一个与 Demo create 输出一致的
  标准未启动 claim 时跳过时间 freshness；原先“任意一个终态”即通过的混合所有权缺口
  同时被收紧；
- 独立审查发现该标准 claim 仍只依赖 registry 形态，可能由伪造 ownership 绕过 freshness；
  corrective 将 claim 绑定到真实 `run-manifest.json`、request、StrategyVersion snapshot、Sandbox、
  node、策略实例、身份合同和精确 SHA-256，缺失或漂移统一返回 `demo_run_ownership` fail closed；
- ownership 与 immutable manifest 共同冻结 Supervisor `process_generation` 基线；真实进程启动
  成功后 generation 恰好增加 1。创建流程仍先收口旧 ownership，再捕获新 Run 基线；时间字段
  只用于展示和终态时间，不再决定状态属于哪一个 Run；
- 独立审查第二轮发现，旧 status artifact 在新 claim 后再次刷新时，历史 started/stopped 仍可能
  把 Created Run 投影为 Stopped 并写入终态锚点；corrective 现在同时按当前 Run 创建时间核对
  `process.updated_at`，并通过完整 Runs API、真实 start/stop 回归证明旧时间不会发布 terminal
  anchor 或 `terminal-state.json`；
- 独立审查第三轮进一步发现，上一 Run 与新 claim 可能落在同一毫秒，单纯比较 `>=` 仍有歧义；
  corrective 改为单调 process generation 合同：未启动为 delta 0，当前 Run 已启动为 delta 1，
  回退或跨越多代均 fail closed。新增旧工件时间恰好等于新 claim 的回归，证明新 Run 仍为
  Created、无 terminal anchor/terminal-state；真实同毫秒 start/stop 则因 generation 已推进而
  正确投影 Stopped；
- generation corrective 复审确认常规 Runs API 的 P1 已关闭，同时发现 MVP shutdown 的 Running
  分支未复用代际校验；第四轮 corrective 保持“先停止进程”的安全顺序，再要求 stopped record、
  ownership 与 immutable manifest generation 三方一致且 delta 恰好为 1，generation 回退、跨代
  或 manifest baseline 漂移均停止节点但拒绝 terminal anchor/terminal-state；
- Backtest 页面先显示 Run 数据源错误和验证中状态，不再把 503 误写成“没有数据集”；
- AppShell 主工作区与画布显式允许收缩，并提供 64px 底部滚动安全区，1280x720 下按钮
  完整位于活动区上方；
- Backtest 提交区同时固定为画布内粘性操作栏，消除 Linux CJK 字体度量变化导致按钮落到
  底部活动区之后的问题；
- hosted CLI 全量测试首次暴露 Live Runtime 外部退出 fixture 在 Supervisor stop 前已退出的竞态；
  用例改为直接终止并等待 fixture 进程，测试锁可从单项 panic poison 恢复，生产 Live 逻辑不变；
- hosted fault matrix 暴露“Demo 已创建但尚未启动”的标准 ownership 被误判为运行中；现在仅允许
  无 PID、没有当前 claim 启动时间且恰好一个 manifest-bound active claim 的标准创建态继续启动，
  曾启动 ownership 和多 active ownership 仍 fail closed；
- hosted Ubuntu/Noto CJK browser smoke 暴露 1280x720 下按钮底部 594px、活动区顶部 509px 的
  字体相关遮挡；粘性提交区加入 12px 明确安全距离，低高度桌面模式同时把活动区缩为 144px，
  其内容仍保持独立滚动；
- running、stale、unknown、活动 Run 所有权和所有真实交易能力继续 fail closed。
