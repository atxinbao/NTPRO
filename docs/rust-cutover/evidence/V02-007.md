## Plain Chinese Summary

这次给本地节点补上了最小日志和 metrics artifact。

大白话说：`ntpro-node` 现在除了 `status.json`，还会写 `metrics.json`
和 `logs/events.log`。metrics 里记录节点当前生命周期、启动/停止次数、
状态切换次数、连接状态计数、最后错误摘要、启动/停止时间、日志路径，
并明确标记 `external_venue_connection=false` 和
`real_orders_submitted=false`。

supervisor 启动子进程时也不再把 stdout/stderr 丢掉，而是落到每个节点的
`logs/stdout.log` 和 `logs/stderr.log`。supervisor 还新增了读取
`metrics.json` 的方法，方便后续 V02-008 CLI 控制命令查询。

没有做 Dashboard，没有做完整 observability 服务，没有接真实交易所，
没有提交真实订单，也没有实现 control API。

## Goal

Expose per-node basic logs and minimal metrics JSON artifacts for local
supervisor consumption without implementing Dashboard UI or a full telemetry
service.

## Behavior Impact

`live run` and `ntpro-node` now produce these node artifacts under the selected
output directory:

- `status.json`
- `metrics.json`
- `logs/events.log`
- legacy `events.log` retained for compatibility with existing local smoke
  checks

When supervisor starts a registered node process, stdout/stderr are now written
to:

- `logs/stdout.log`
- `logs/stderr.log`

The metrics JSON contains only local runtime lifecycle and artifact metadata.
It does not include secrets, raw venue payloads, account credentials, or
production order data.

## Public API Impact

This adds Rust CLI crate support types and methods:

- `NodeMetrics`
- `NodeConnectionCounts`
- `NodeMetricArtifacts`
- `NodeMetricCounts`
- `SupervisorRegistryStore::node_metrics`
- `write_node_metrics_artifact`

No user-facing supervisor subcommand is added in this task. V02-008 owns CLI
controls for supervisor.

## Migration Note Status

No Python/PyO3/Cython migration note is required. This is additive Rust-only
local runtime foundation work.

Existing `events.log` at the output root is preserved alongside the new
`logs/events.log`, so no local smoke consumer migration is required in this PR.
