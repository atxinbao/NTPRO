## 中文摘要

本任务处理 `project.html` 的 Event Store Medium 审查项。Event Store 仍是
Early alpha 的单实例嵌入式权威日志，但 README 现在明确规定：Trader Terminal

拒绝行为继续由同一测试覆盖。

本任务没有修改 Event Store 持久化、编码、回放或 kernel 语义；没有修改
v0.32.0 冻结文件，也没有增加任何交易写能力。

## Negative HTTP Boundary

The following representative paths must remain unmounted:

```text
GET /api/event-store
GET /api/event-store/entries
GET /api/event_store/raw
GET /api/REDB/status
GET /api/runs/example/events
GET /api/runs/example/raw-events
GET /event_store/trader-001/run.redb
GET /downloads/run.REDB
```

Expected result for every path and each of GET, POST, PUT, PATCH, and DELETE:
an exact `HTTP/1.1 404 Not Found` status line.

The guard-specific test registers `/api/event-store/probe` as an otherwise
successful route and proves that the middleware changes every common method to
404. It also registers `/api/nodes/redb` and `/api/nodes/run.redb` and proves
those valid dynamic node IDs remain available with 200 responses.

## Independent Review Corrections

The first Verification & Release Gatekeeper review requested three changes:

- replace fixed-path-only checks with a Router-level forbidden namespace guard;
- compare the exact HTTP status line instead of searching the whole response;
- remove the unsupported claim that this boundary provides authorization.

The second review found that the first matcher was too broad and that
unregistered-path tests did not prove middleware enforcement. The matcher is
now limited to explicit route structures, and a registered-route test proves
both blocking and valid dynamic node-ID pass-through. Independent re-review
remains required.
