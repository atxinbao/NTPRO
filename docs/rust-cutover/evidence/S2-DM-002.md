# S2-DM-002 - Demo 实时状态与运行结果产品化证据

Status: REVIEW_APPROVED

## 交付边界

- snapshot 是只读投影，不提供启动、停止、订单或恢复动作；
- Demo 只允许 Sandbox，真实 Live、外部 Venue、真实订单、撤改、自动重试、自动补救和
  交易控件继续关闭；
- 本任务不伪造尚未交付的模拟成交、持仓和资金曲线，相关字段留给后续独立任务；
- 任何缺失、未知、身份漂移、路径逃逸、记录数/字节数/校验和不一致或禁止能力漂移都
  fail closed。

## 实现证据

- Product API 新增 `GET /api/product/v1/runs/{run_id}/demo-snapshot`，统一返回
  `not_started`、`running` 或 `frozen` 三种快照状态；
- running 快照从 Supervisor 实际记录、节点 metrics 和策略八类工件重建，返回市场事件数、
  信号数、订单意图数、风险拒绝数、连接状态和最近事件；
- 策略 manifest 必须精确包含八项工件，逐项绑定路径、格式、记录数、字节数和 checksum；
  macOS `/var` 与 `/private/var` 路径别名按规范化后的同一文件比较，目录逃逸与 symlink
  读取仍由 nofollow 工件读取拒绝；
- Demo start 只有在严格策略快照可读取后才返回成功；启动后校验失败会 owner-aware 停止
  node；来源缺失、来源非法或禁止边界错误不会签发或锚定终态，只有可信运行时才能发布
  failed 结果；
- events、market events、signals、order intents 和 risk decisions 的每一条 JSONL 记录都校验
  schema、身份、时间和值域，早期非法记录不能被末条合法记录掩盖；
- stopped/failed 终态先 create-only 发布 `demo-result.json`，再将其 SHA-256 写入
  `terminal-state.json`，最后由 Supervisor terminal anchor 锚定终态文件哈希；
- 读取终态时同时验证 terminal anchor、result SHA、Run/StrategyVersion 身份、生命周期、
  结果引用和禁止能力；结果被改动一个字节即拒绝；
- 策略工作台只在 `running` 时每 2 秒刷新；created 和 terminal Run 停止轮询，生命周期动作
  完成后失效并重读快照；浏览器测试直接统计请求次数，证明 running 会继续轮询、frozen 会
  停止轮询；
- `not_started` 必须同时没有 market、session、signal、intent 和 risk 数据；快照观察时间在完成
  工件读取后刷新，且所有公开 Unix 毫秒时间必须大于零；
- 页面展示 Demo 市场、信号、意图、风险、连接和来源信息，不把订单意图冒充成交，也不
  显示不存在的持仓。
- 全量测试暴露并修复两个集成阻塞：MVP 通用测试节点缺失策略工件，以及 GET 在等待
  生命周期锁前捕获时间、导致长 Stop 后用旧时间验证新状态合同；现由测试节点生成严格
  八工件快照，并在取得锁后刷新合同验证时间；原失败用例均直接回归通过。
