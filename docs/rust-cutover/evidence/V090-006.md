## Goal

Define and persist a local-only order intent artifact for the v0.9.0 Strategy
Runtime Foundation. The artifact records what a strategy would like to do after
signal generation, while keeping v0.9.0 away from execution adapters, exchange
order APIs, Binance testnet order submission, real funds, and production
trading claims.

Plain Chinese summary: 这次只是把“策略想下什么单”写成本地 JSONL 文件，方便后续接
risk decision。它不是交易所订单，不会调用 Binance，也不是 testnet 下单证明。

## Boundary Check

The implementation was reviewed against the v0.9.0 boundary:

- order intents are generated from local demo signals only;
- `strategy/order_intent.jsonl` is a local artifact;
- every record sets `submission_allowed=false`;
- every record uses `submission_status=blocked_by_v09_strategy_runtime_boundary`;
- records do not include `exchange_order_id` or `venue_order_id`;
- no submit, cancel, replace, amend, execution adapter, exchange API, or Binance
  testnet call was added.

## Behavior Impact

The demo strategy session now writes:

```text
strategy/order_intent.jsonl
```

Each line is a JSON object using:

```text
schema_version = ntpro.v09_order_intent.v1
```

This is additive behavior for the local Strategy Runtime demo path. It does not
change live execution, adapter behavior, order submission, account state, or
trading semantics.

## Migration Note

No migration is required. This is an additive v0.9.0 artifact contract. Existing
strategy session consumers can ignore the new order intent artifact until they
need the risk-decision input.

## Rollback Plan

Revert the PR. That removes the `StrategyOrderIntent` type, the
`strategy/order_intent.jsonl` output, release contract documentation, and this
evidence file while preserving the earlier signal artifact contract.
