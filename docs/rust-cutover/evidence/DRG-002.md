# DRG-002 Evidence - Toolchain default convergence

Date: 2026-06-05
Executor: Codex
Task: DRG-002
Risk: medium
Status: REVIEW_REQUIRED

## Goal

确保在 `/Users/mac/Documents/NTPRO` 里直接运行普通 `cargo` 和 `rustc` 时使用 Rust `1.95.0`，而不是 Homebrew 的 Rust `1.87.0`。

## Initial Finding

Before the fix, `rustup` already had a directory override for NTPRO, but the shell resolved `cargo` and `rustc` from Homebrew first:

```text
which cargo: /opt/homebrew/bin/cargo
which rustc: /opt/homebrew/bin/rustc
cargo 1.87.0 (Homebrew)
rustc 1.87.0 (17067e9ac 2025-05-09) (Homebrew)
rustup active-toolchain: 1.95.0-aarch64-apple-darwin (directory override for '/Users/mac/Documents/NTPRO')
```

This meant `rustup override set 1.95.0` was present, but ordinary commands still bypassed rustup because `/opt/homebrew/bin` appeared before rustup-managed binaries.

## Fix Applied

Installed local path-scoped wrappers:

```text
/Users/mac/.local/bin/cargo
/Users/mac/.local/bin/rustc
```

These wrappers only switch to Rust `1.95.0` when `PWD` is inside:

```text
/Users/mac/Documents/NTPRO
```

Outside NTPRO, they delegate back to Homebrew, so other projects keep their previous toolchain behavior.

## Repository Documentation

Updated:

- `docs/rust-cutover/verification/toolchain.md`

The document now records the wrapper pattern for local shells where Homebrew must stay on `PATH` for unrelated projects.

## Rollback Plan

Remove the two local wrappers:

```bash
rm /Users/mac/.local/bin/cargo /Users/mac/.local/bin/rustc
```

Then either prepend the Rust `1.95.0` toolchain manually before every NTPRO command or run commands through `scripts/ai/toolchain_env.sh` / `rustup run 1.95.0`.
