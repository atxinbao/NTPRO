## Task ID

`V04-008` - mock order lifecycle

## Plain Chinese Summary

这次给 v0.4 Binance sandbox 补了一条本地 mock 订单生命周期。它不是生产交易所撮合，也不会连接 Binance，更不会真实下单；它只是用仓库里提交的 JSONL fixture，把 submit、accept、fill、cancel、reject 这些关键状态整理成 Rust 可以加载、校验和总结的确定性数据。

后续 V04-009 的风险拒单、V04-006/V04-007 的策略 smoke、V04-010 的 dashboard 面板可以复用这份稳定的订单状态，不需要每个任务各自造一套不一致的 mock。

## Behavior Impact

- Adds a local mock order lifecycle data source that can be loaded from Rust without network access.
- Validates fixture shape before constructing the lifecycle:
  - valid JSONL rows;
  - strictly increasing sequence and timestamp;
  - required lifecycle event types;
  - explicit status for each event;
  - venue order ID for accepted, filled, and canceled events;
  - trade ID for filled events;
  - reason for rejected events;
  - positive quantity and non-negative filled/leaves quantities.
- Produces a stable summary artifact that later strategy, risk, and dashboard tasks can consume.
- Does not change real Binance execution behavior, order manager semantics, risk behavior, matching behavior, live-node startup, or CLI behavior.

## Public API Impact

Public Rust adapter API additions under `nautilus_binance::mock_lifecycle`:
