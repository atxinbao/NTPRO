# V201-003 Evidence - durable single-shot attempt ledger and atomic approval consumption

Date: 2026-06-30
Executor: Codex

Milestone: v0.20.1
Status: LOCAL VALIDATION PASSED

## Summary

V201-003 upgrades guarded single-shot production submit dedupe from
caller-supplied prior attempt digests to a typed durable attempt ledger read
model. The submit candidate gate now requires a present, trusted, current
ledger with matching lifecycle and v20 runtime provenance before preview,
dry-run, or submit evidence can be recorded.

Plain Chinese summary: 本任务把 V20 single-shot submit 的去重依据从调用方传入的
`prior_attempt_digests` 改成 durable attempt ledger。candidate gate 现在必须读取
可信、未过期、同 lifecycle、同 v20 provenance 的 ledger；缺失 ledger、stale ledger、
lineage mismatch、provenance mismatch、重复 request digest、重复 attempt id、以及
ledger 中已消费的 approval 都会 fail closed。submit 成功证据会记录 atomic approval
consumption 已完成，但不会新增 retry、replace、amend、flatten、bulk submit 或策略驱动
生产提交能力。

## Behavior Impact

V20 submit candidate evidence now fails closed without a durable attempt ledger
or when the ledger is stale, untrusted, mismatched, or already records the same
request digest, attempt id, or consumed approval id. Preview and dry-run remain
evidence-only. Submit mode still requires manual online gate and records a
single approval consumption before submit evidence.

## Public API Impact

`GuardedSubmitCandidateRequest` now uses
`attempt_ledger: Option<SubmitAttemptLedgerSnapshot>` instead of
caller-supplied `prior_attempt_digests`. New Rust evidence types:

```text
SubmitAttemptLedgerSnapshot
SubmitAttemptLedgerEntry
```

No Python product API is added or expanded.

## Rollback Plan

Revert this PR to restore the previous caller-supplied duplicate-digest check
and remove the durable ledger read-model requirement. Downstream v0.20.1 tasks
that depend on durable submit attempt dedupe should remain blocked until a
replacement ledger contract is available.
