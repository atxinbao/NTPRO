# S2-DM-001 - Demo Run 创建与 Supervisor 生命周期证据

Date: 2026-08-10
Executor: Codex
GitHub issue: #1280
Status: REVIEW_APPROVED

## 交付边界

- Demo Run 仅绑定当前不可变 StrategyVersion 和唯一 Sandbox node；同一时刻最多一个活动
  Demo Run，但已停止或失败的 Run 必须保留为不可变历史，并允许创建新的 Run；
- manifest 只记录不可变创建身份，生命周期必须从 Supervisor 实际状态重建；
- start/stop 必须由机构用户显式确认，不允许客户端自动重试；
- Live、外部 Venue、真实订单、撤改、自动重试、自动补救和交易控件继续关闭。

## 实现证据

- Product API 新增 `POST /api/product/v1/demo-runs` 和
  `POST /api/product/v1/demo-runs/{run_id}/actions`；写操作仅允许机构用户；
- 创建产物包含不可变请求、StrategyVersion 快照和最后发布的 manifest，目录打开禁止跟随
  symlink；中断发布不进入 Run 列表，已发布产物缺失或篡改时 fail closed；
- 活动 Demo 生命周期从 Supervisor 注册表、节点状态和指标重建；终态写入绑定 manifest 哈希的
  `terminal-state.json`，并由 Supervisor registry 保存 manifest/terminal 双哈希锚点；历史 Run
  不会被后来复用同一 node 的运行状态改写，合法形状的重签终态也会 fail closed；
- Supervisor registry 为每个 Demo Run 保存通用 Run ownership；活动 ownership 存在时，控制中心、
  CLI 和其他非 Product API 的 start/stop/pause/resume/reconnect 入口均不能旁路控制该 node；
- 新 Run 取得 ownership 时会清空上一运行会话的 `started_at`/`stopped_at` 快照；同毫秒内完成的
  旧 Run 不会把新 Run 提前投影为终态，而已有启动证据的同毫秒停止仍会正确发布为 `stopped`；
- node 自然停止或异常退出时，在产品来源健康检查前先依据已确认的进程退出状态发布并锚定
  `stopped`/`failed` 终态；修复节点后可创建新 Run，旧终态保持不变；
- Demo 创建会先收口已确认停止的 active ownership，再校验 status/metrics freshness；因此自然
  停止后的陈旧运行工件不会阻塞创建新 Run，但 `stale` 硬杀状态仍保持 fail closed，并要求先
  锚定失败终态再执行人工 Supervisor 恢复；
- 正式 `nautilus mvp serve` 只执行 prepare，不预启动 node；Demo start 显式启动，进程退出会
  owner-aware 停止并终态化活动 Run；退出清理先只依据 registry ownership 停止运行进程，
  再校验不可变 manifest 并发布终态，不会因 status contract、完整产品来源或 manifest 异常
  而留下运行进程；
- 同一 workspace 重启会删除旧 status/metrics/pid 运行快照，以 NotStarted + Missing 重新登记；
  删除前精确校验 config、artifact root、三个运行文件和三条日志路径，registry 路径漂移时
  fail closed；实际删除通过 workspace capability 句柄逐层 `open_dir_nofollow` 后按固定相对名
  执行，artifact root symlink 同样 fail closed 且不触碰外部文件；旧 Run 保持终态、node
  不自动重启，延迟读取不会把旧快照误标为新鲜运行证据；
- 所有 Run 读取与 Demo lifecycle action 共享串行化锁；终态发布对 GET/GET 和 GET/stop 并发
  幂等，连续 8 轮真实并发启停通过；相同终态可重复确认，任何不同哈希或身份仍拒绝；
- 无 status/metrics 工件的正式 NotStarted 准备态，以及已有 Supervisor 终态锚点的 stopped
  快照，可在心跳窗口后继续读取策略和历史 Run；schema、路径、时间完整性和所有禁用边界仍
  逐项验证；
- 启动事务等待原子指标产物并执行完整 Product Run 投影校验；任一启动后校验失败时必须停止
  刚启动节点、确认 Supervisor 返回 `stopped`，再发布失败终态，清理失败不得被忽略；
- running 状态继续对 status contract、node status 与 metrics 执行 freshness fail-closed；每次
  Demo start/stop 后原子刷新状态合同，只有已锚定终态或正式 NotStarted + Missing 可豁免年龄；
- 策略工作台新增 Demo 页面和 Run 详情生命周期面板，创建、启动、停止都要求用户显式操作，
  mutation hook 不自动重试；
- 默认节点配置不再预置静态 `running` Sandbox Run；Live 占位与 Backtest 资源保持不变；
- MVP 冻结清单更新以下六个受控源文件哈希：`crates/cli/src/mvp.rs`、
  `crates/cli/src/supervisor.rs`、`crates/cli/src/dashboard/server.rs`、
  `configs/nodes/btc-ema-shadow.toml`、`scripts/ai/test_mvp_acceptance.mjs`、
  `scripts/ai/test_mvp_fault_matrix.mjs`；冻结拓扑及 19 项禁用边界未变；
- 后端风险清单从 29702 更新为 29836 signals；新增 134 项全部属于 test/test_inline，
  production 保持 2702，本任务未扩大生产风险基线。
