## Scope

Expose authenticated Binance testnet read-only proof state at the top level of
workflow summary and manifest artifacts. This prevents a public HTTP read-only
success from hiding whether the authenticated proof was successful, failed, or
deferred.

This task does not expand the v0.8 product scope. It adds no order submission,
cancel/replace/amend, account mutation, production Binance connectivity, real
funds, production trading, or Dashboard-started probes.

## Changes

- Added top-level summary fields:
  - `authenticated_probe_attempted`;
  - `authenticated_readonly_probe_status`;
  - `authenticated_response_shape_validated`;
  - `authenticated_connectivity_proof`.
- Added matching top-level manifest fields copied from summary.
- Kept the Binance testnet summary constructor within the clippy argument
  limit by reusing `WorkflowBoundary.credential_policy` instead of passing a
  duplicate policy argument.
- Added a regression test covering authenticated success, failure, and deferred
  states.

## Behavior Impact

Generated `summary.json` and `manifest.json` now expose authenticated proof
status directly:

```text
authenticated_probe_attempted
authenticated_readonly_probe_status
authenticated_response_shape_validated
authenticated_connectivity_proof
```

The fields distinguish:

```text
authenticated_readonly_probe_ok
authenticated_readonly_probe_failed
authenticated_readonly_probe_manual_not_run
```

Network behavior is unchanged. The authenticated proof remains manual-online
only and still requires `NTPRO_V08_MANUAL_ONLINE=1` from V081-002.

## Public API Impact

Artifact schema is extended with backward-compatible `serde(default)` fields for
older artifacts.

## Migration Note Status

No migration note required. The new fields are additive and default when older
artifacts are read.

## Rollback Plan

Revert this PR to remove the top-level summary/manifest fields. Existing
authenticated proof artifact files would remain the source of truth if reverted.
