## 实现结果

- 新增标准 Node.js 验收器，直接调用 Rust `nautilus` 和 `ntpro-node` 二进制；
- 回测和 MVP workspace 全部位于独立临时目录，不读取或写入仓库 `runs/`；
- 两次真实 engine-smoke 回测使用相同配置和 run id，并对输出执行字节比较；
- 通过真实 HTTP 角色 bootstrap 获取 HttpOnly / SameSite=Strict 会话，并确认跳转 URL
  不保留 token；
- 机构角色和无会话调用 lifecycle action 均为 403，operator GET 为 405；
- operator 完成 stop/start，随后通过共享状态与运维投影确认同一节点恢复运行；
- SIGINT 后读取 registry 和最终状态合同，确认 process/lifecycle 均为 stopped；
- 六个合同表面的关闭字段均为 required-false，字段缺失或变成 true 都会失败；
- 验收器输出结构化 `result.json` 和脱敏日志，并在写入前拒绝未脱敏 token/cookie。

## 本地闭环结果

固定 Rust `1.95.0` 冷构建两个二进制后，验收器连续运行两次均通过：

```text
mvp_acceptance=pass
deterministic_runs=2
summary_sha256=b02a41088acd06c317398e5d9fb29a082edf768023080cff3e3bf3c274bc8684
node_count=1
transitions=running,stopped,running,stopped
role_boundary=pass
graceful_shutdown=pass
```

`result.json` 进一步确认：

- `byte_equal=true`、`quotes_loaded=120`、`runtime_status=completed`；
- 初始 workspace 为 absent，运行期间只有 `mvp-node-001`；
- institution/unauthenticated lifecycle action 为 403，lifecycle GET 为 405；
- required-false validator 的 missing/true 两个负向自测通过，诊断脱敏自测通过；
- external venue、真实订单、订单提交/变更、retry、remediation 全部为 false；
- 最终 process state 与 lifecycle state 均为 stopped，trading readiness 为 blocked。

使用缺失节点配置执行负向验收时，进程按预期非零退出，同时仍生成
`status=fail` 的 JSON artifact，错误内容已脱敏且明确为 `MVP node config is missing`。
