## 实现结果

- 新增标准 Node.js 验收器，直接调用 Rust `nautilus` 和 `ntpro-node` 二进制；
- 回测和 MVP workspace 全部位于独立临时目录，不读取或写入仓库 `runs/`；
- 两次真实 engine-smoke 回测使用相同配置和 run id，并对输出执行字节比较；
- 两次真实 EMA 策略回放直接复用 CLI `run_ema_cross_engine` 产品函数，进一步固定事件、
  订单、持仓、PnL 和统计结果，避免只比较浅层 `summary.txt` 或维护平行回测实现；
- 通过真实 HTTP 角色 bootstrap 获取 HttpOnly / SameSite=Strict 会话，并确认跳转 URL
  不保留 token；
- 机构角色和无会话调用 lifecycle action 均为 403，operator GET 为 405；
- operator 完成 stop/start，随后通过共享状态与运维投影确认同一节点恢复运行；
- SIGINT 后读取 registry 和最终状态合同，确认 process/lifecycle 均为 stopped；
- 六个合同表面的关闭字段均为 required-false，字段缺失或变成 true 都会失败；
- 验收器输出结构化 `result.json` 和脱敏日志，并在写入前拒绝未脱敏 token/cookie。
- workflow 触发范围覆盖 `Cargo.*`、`.cargo/` 和整个 `crates/`，不再手工枚举可能遗漏的
  EMA、analysis、persistence 或 serialization 间接依赖。

## 本地闭环结果

固定 Rust `1.95.0` 冷构建两个二进制后，验收器连续运行两次均通过：

```text
mvp_acceptance=pass
deterministic_runs=2
summary_sha256=b9db514672acf8e34c61f053fee9b178e383d4e60f2f70932b6e3cfbe24b3d4e
strategy_result_sha256=5d1e0903a1060f75b28b30241d2f086c6d2dec1faf171ddf0fb40bf09d369e1c
node_count=1
transitions=running,stopped,running,stopped
role_boundary=pass
graceful_shutdown=pass
```

`result.json` 进一步确认：

- `byte_equal=true`、`quotes_loaded=120`、`runtime_status=completed`；
- 真实 EMA 策略 canonical result 两次字节一致，固定为 9 events、3 orders、3 positions，
  USD `PnL (total)=-3.920000000042`；
- 回测配置以仓库相对路径传给 CLI，避免本机绝对路径污染跨工作区 hash；
- 初始 workspace 为 absent，运行期间只有 `mvp-node-001`；
- institution/unauthenticated lifecycle action 为 403，lifecycle GET 为 405；
- required-false validator 的 missing/true 两个负向自测通过，诊断脱敏自测通过；
- external venue、真实订单、订单提交/变更、retry、remediation 全部为 false；
- 最终 process state 与 lifecycle state 均为 stopped，trading readiness 为 blocked。

使用缺失节点配置执行负向验收时，进程按预期非零退出，同时仍生成
`status=fail` 的 JSON artifact，错误内容已脱敏且明确为 `MVP node config is missing`。

使用包含真实 bootstrap token 的强制失败路径执行时，进程同样非零退出并生成
`status=fail` artifact；`result.json`、server log、stdout 和 stderr 均只保留
`access_token=[REDACTED]`，不再由未捕获异常输出原始 token。

## Hosted 证据状态

PR 创建后由 Rust Cutover Smoke 执行同一验收器，并上传
`mvp-acceptance-<PR_NUMBER>` artifact。当前不得把本地通过写成 hosted 完成或 M4 冻结。

## 独立审查修正

独立审查在 head `249506b1b87b80f9904ac6d9d43ca4f64bcc9969` 指出三个问题：浅层
summary 不能证明策略结果、workflow 触发范围过窄、含 token 的失败路径无法稳定写出
证据。head `710f3ec78f34d603dbb72585bce185a69c73dfe9` 复审进一步指出间接依赖仍可能
漏触发，以及 canonical test 没有绑定 CLI 产品函数。最终修正改为所有 `crates/` 触发，
并由 CLI 单元测试直接调用 `run_ema_cross_engine`。等待对新最终 head 复审。

## 保持关闭的能力

本验收只覆盖本地单节点 sandbox 闭环，不开放真实交易、多节点、外部 Venue、生产 IAM、
自动重试、自动补救或交易控件。M4 仍需后续独立任务收口。
