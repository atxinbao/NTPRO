## Goal

Wire the v0.11 offline release gate bundle into local release verification, PR
smoke, and tag-triggered release gate workflows without requiring credentials,
network access, or production order mutation.

Plain Chinese summary: 这次只把 v0.11 离线发布检查接进自动验证。它会本地跑账户快照契约、
Dashboard 只读状态测试和 release 文档边界检查。它不会联网，不用生产 API key，不下单、
不撤单、不改单，也不创建 tag 或发布 Release。

## Files Changed

- `scripts/ai/verify_v11_offline_release_gates.sh`
  - Adds the v0.11 offline release gate bundle.
  - Runs the authenticated account snapshot contract gate.
  - Runs the Dashboard read-only production shadow status test.
  - Checks release docs for no-mutation/no-production-trading boundary markers.
  - Uses system `grep` for CI portability; no extra `rg` installation is
    required on GitHub-hosted runners.
- `scripts/ai/verify_release.sh`
  - Adds the `v11-offline-release-gates` stage.
  - Includes the v0.11 gate in the default `all` release path.
- `.github/workflows/rust-cutover-smoke.yml`
  - Classifies v0.11 gate changes and runs the offline v0.11 smoke in
    lightweight mode only when relevant files change.
  - Includes the new script in shell syntax checks.
- `.github/workflows/release-tag.yml`
  - Adds the `release-v11-offline-release-gates` matrix stage.
- `docs/rust-cutover/tasks/V110-009.md`
  - Records the task contract and acceptance criteria.
- `docs/rust-cutover/evidence/V110-009.md`
  - Records this evidence.

## Behavior Impact

Release validation now has an explicit v0.11 offline gate stage. It only checks
local contracts, local test fixtures, release documents, and no-mutation
markers. It does not change runtime trading behavior.

Pull request smoke uses `NTPRO_V11_LIGHTWEIGHT=1` to avoid a full CLI binary
build on every PR. The full CLI-binary contract still runs in
`scripts/ai/verify_release.sh v11-offline-release-gates` and the tag-triggered
release workflow.

## Public API Impact

No Rust library API, CLI command contract, Dashboard API, adapter API, or
trading semantic changed.

## Migration Note

No migration note is required because this task only adds verification wiring
for existing v0.11 release contracts.
