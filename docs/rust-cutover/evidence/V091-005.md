# V091-005 Evidence - Strategy Runtime Counters Snapshot

Date: 2026-06-19
Executor: Codex
Task: V091-005 Add Strategy Runtime Counters Snapshot
Risk level: medium

## Goal

Prevent Strategy Runtime heartbeat and status updates from resetting runtime
counters after the deterministic strategy batch has already produced market
events, signals, order intents, risk decisions, rejections, and zero actual
submissions.

## Files Changed

- `crates/cli/src/strategy_session.rs`
  - Added `StrategyRuntimeCounters`.
  - Added `StrategySession::counters()` as the shared counter snapshot.
  - Made `StrategySessionSummary` and `DemoStrategyRuntimeSummary` use the same
    counter source.
- `crates/cli/src/live.rs`
  - Passes `StrategyRuntimeCounters` into running heartbeat and final node
    status/metrics generation.
  - Writes summary text and event log counter fields from the same snapshot.
  - Adds tests proving running heartbeat status/metrics keep non-zero counters.
- `docs/rust-cutover/tasks/V091-005.md`
- `docs/rust-cutover/tasks/V091-006.md`
- `docs/rust-cutover/tasks/V091-010.md`
  - Recorded the owner-approved medium-risk automation override for the
    remaining V091 queue.

## Behavior Impact

- Running heartbeat no longer writes strategy signal/rejection counters as zero
  after strategy runtime artifacts exist.
- Final `NodeStatus`, `NodeMetrics`, text summary, strategy summary artifact,
  and event log now read counters from the same snapshot.
- `actual_submission_count` remains `0`; no real order submission path was
  added or enabled.

## Public API Impact

No CLI command shape changed. `DemoStrategyRuntimeSummary` now carries a nested
`counters` object for internal callers. Existing top-level count fields remain
present.

## Migration Note

Consumers should treat the top-level count fields as stable and may use the new
`counters` snapshot when they need all Strategy Runtime counters from a single
source.
