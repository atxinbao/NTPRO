## Goal

Make the local supervisor manage the actual OS process lifecycle instead of
trusting lifecycle artifacts alone.

## Implementation Notes

- Startup success now requires a live child process and a `running` lifecycle
  artifact.
- Startup failure cleanup uses the retained `Child` handle, then waits for the
  child to be reaped before recording the registry failure.
- Stop remains cooperative first: the supervisor writes `stop.request` and
  waits for the node to publish `stopped` and exit.
- If cooperative stop times out, the supervisor sends TERM when supported,
  waits briefly, then requests a forced kill if the process is still alive.
- A process that exits without publishing `stopped` is not reported as a
  successful stop. The registry records it as `stale` with an explicit error.
- Artifact names and JSON schemas are unchanged.

## Behavior Impact

- Supervisor status no longer treats a dead recorded PID as a healthy running
  process.
- Startup now fails deterministically when the child exits early or never
  reaches `running`, and it cleans up the child process.
- Stop success now means both the lifecycle artifact and the OS process agree
  that the node stopped.
- An unresponsive local node receives bounded TERM/KILL escalation instead of
  being left running after a timeout.
- Incomplete lifecycle transitions are surfaced as `stale` instead of a false
  success.
- No trading semantic behavior changed.
- No real venue connection or real order submission was introduced.
