## Plain Chinese Summary

这次实现的是 `ntpro-supervisor` 的本地 registry 底座，不是完整
supervisor 命令。

新增 registry 能把一个本地节点的 `node_id`、config 路径、artifact
目录、pid 路径、status 路径、metrics 路径、日志路径和最后一次状态记录到
JSON 文件里。它支持注册/更新、列表、删除、读取 status artifact，以及把缺失
pid artifact 或缺失/损坏 status artifact 标成 stale/missing/invalid。

没有实现 start/stop/status 命令，没有启动子进程，没有接真实交易所，没有下单，
也没有 Dashboard/control API。V02-006 会继续做 start/stop/status，V02-008
再做用户 CLI 控制入口。

## Goal

Implement a local supervisor registry for node metadata, config path, pid/process
metadata, state path, log path, metrics path, and last known status.

## Behavior Impact

This adds a durable local registry support module. It does not change existing
CLI command behavior unless later tasks call the new module.

The registry writes and reads local JSON metadata only. It creates per-node
artifact directories and records paths for:

- `pid.json`
- `status.json`
- `metrics.json`
- `logs/stdout.log`
- `logs/stderr.log`
- `logs/events.log`

## Public API Impact

`nautilus-cli` now exposes a Rust `supervisor` support module. No new
user-facing `nautilus` subcommand or `ntpro-supervisor` binary is introduced in
this task.

## Migration Note Status

No Python/PyO3/Cython migration note is required. This is additive Rust-only
runtime foundation work.

## Rollback Plan

Revert this PR to remove `crates/cli/src/supervisor.rs`, the `supervisor`
module export, V02-005 evidence, and V02-005 agentflow/lease updates. No data
migration is needed because registry files are local development artifacts.
