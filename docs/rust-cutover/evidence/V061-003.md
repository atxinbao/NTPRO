# V061-003 Evidence - workflow run_id single source of truth

Date: 2026-06-14
Executor: Codex

## Plain Chinese Summary

本任务只修 workflow artifact 的身份字段，不连接 Binance、不下单、不读取真实密钥。

大白话说：以前 `binance-testnet` workflow 可能同时出现两个 run id：
命令行 `--run-id` 一个，配置文件 `run.id` 一个。现在规则固定为：命令行传了
`--run-id` 就以命令行为准；没传时才用配置里的 `run.id`。对外主字段只显示一个
`run_id`。配置里原始写的值仍保存在 `config_declared_run_id`，只用于审计。

## Behavior Impact

- `binance-testnet` workflow now uses a single effective run id.
- CLI `--run-id` takes precedence over `config.run.id`.
- If CLI `--run-id` is absent, `config.run.id` remains the run id.
- No network behavior changed.
- No order behavior changed.
- No Dashboard control behavior changed.

## Public API Impact

Workflow artifact identity semantics are tightened:

- `manifest.json.run_id`
- `manifest.json.summary.run_id`
- `summary.json.run_id`
- `testnet/config.json.run_id`
- every `events.jsonl` event `run_id`

all use the same effective run id.

`testnet/config.json` adds `config_declared_run_id` to preserve the original
configuration value for audit.
