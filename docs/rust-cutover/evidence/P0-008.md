## Plain Chinese Summary

这次修的是 LiveNode 启动时 execution client 连接卡住的问题。

以前 data client 启动阶段已经会响应 stop/shutdown/Ctrl-C，但 execution client 启动阶段还只是普通等待。如果某个 execution adapter 的 connect future 一直不返回，LiveNode 可能停在 Starting，外部 stop/shutdown 不能及时把它拉下来。

现在 execution client 启动阶段也接入了同一类启动控制：

- 收到 stop 请求会中止启动；
- 收到 shutdown 请求会中止启动；
- `run()` 入口收到 Ctrl-C 会中止启动；
- execution connect 阶段超过 `timeout_connection` 会中止启动；
- 中止或超时不会把 LiveNode 标成 Running。

没有改真实交易所连接逻辑，没有新增实盘交易能力，也没有提交真实订单。

## Goal

Make LiveNode execution client connection startup cancellable and timeout-bound like data client startup.

## Files Changed

- `crates/live/src/node.rs`
  - Added bounded startup awaiting for execution client connection.
  - Replaced the generic startup event-buffering driver with an execution startup driver that watches stop/shutdown/Ctrl-C/timeout.
  - Treats connection timeout as startup abort instead of entering `Running`.
  - Added execution-client cancellation probe tests for stop, shutdown, and timeout.

## Behavior Impact

- `LiveNode::start()` now wraps `connect_exec_clients()` with startup stop/shutdown/timeout checks.
- `LiveNode::run()` now drives execution-client startup while buffering startup events and watching stop/shutdown/Ctrl-C/timeout.
- If execution startup times out, LiveNode finalizes startup abort and remains stopped instead of transitioning to `Running`.
- Data-client startup ordering and instrument-cache draining remain unchanged.
- Existing running-phase shutdown behavior is unchanged.

## Public API Impact

No public Rust API signature changes.
