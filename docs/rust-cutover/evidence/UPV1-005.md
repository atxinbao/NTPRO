## 实现结论

- `scripts/ai/build_ntpro_local_delivery.sh` 从已验证源码产物生成自包含交付目录，并拒绝覆盖
  无交付标记的未知目录；
- 原生 Rust `start-ntpro` 是普通用户唯一入口，复用冻结的 `nautilus mvp serve` 合同；
- 用户数据默认写入系统用户数据目录，不写入可删除、可升级的交付目录；
- 启动前验证主程序、node、节点/回测配置、production frontend、绑定地址和超时参数；
- PID 所有权锁通过预写候选文件再 hard-link 原子发布，拒绝同一工作区重复启动；死 PID 对应的
  失效锁通过原子重命名接管；
- guardian 在服务启动前取得运行锁所有权并直接持有 NTPRO 子进程；launcher-only 异常由
  guardian 向 NTPRO 发送 `SIGINT`，且只在确认服务退出后清理匹配 owner/child 的锁；
- 原生启动器在启动服务前注册 Ctrl-C/HUP/TERM，并统一映射为 MVP 可处理的 `SIGINT`；服务不再
  经过 Bash 异步后台命令，因此不会继承被忽略的 SIGINT；
- 中文说明分别描述普通用户操作和交付构建命令，不要求用户理解 Cargo、crate 或进程编排；
- CI 在 Cargo、任意 workspace crate、两个配置、frontend、toolchain、LICENSE 或交付层变化时增加
  package/browser lifecycle smoke，并继续运行完整策略工作台 Backtest + Demo production 验收；
- manifest 只接受当前工作区使用 `--locked` 构建的二进制，并要求构建前后 Git 状态完全一致；
  它记录 dirty 状态、OS、CPU、Rust target、关键文件、完整前端和完整 payload 哈希，正式 clean
  build 与开发 dirty build 不会混淆。

## 独立审查整改

第一次独立审查结论为 `CHANGES_REQUESTED`：

- P1：launcher-only 退出可能遗留服务；现已加入独立守护进程，父进程消失后向服务发送 SIGINT，
  等待统一收口并只清理 owner/child 完全匹配的锁；
- P1：TERM/HUP 原样转发会绕过只监听 Ctrl-C 的 MVP；现由 launcher 把三种停止信号统一映射
  为 SIGINT，同时保留服务和 node 的标准信号语义；活动 Demo 终态和 node PID 由真实验收验证；
- P2：失效锁 `rm + mkdir` 存在并发窗口；现改为原子移动到唯一 quarantine，竞争测试证明两个
  恢复者只允许一个启动；
- P2：旧测试只杀整个进程组；现增加 launcher-only SIGKILL、活动 Demo、服务 PID、node PID、
  guardian 锁清理和全进程组异常矩阵；
- P2：CI 遗漏真实交付输入；现覆盖 Cargo、全部 CLI/Product API、两个配置、frontend、toolchain
  和交付脚本；
- P2：manifest 缺平台和可信来源；构建器现强制从当前工作区编译，不再接受任意外部二进制，
  clean/dirty source binding 分离，并记录 OS、CPU、Rust target 与关键文件哈希；第二次复审后又
  增加 `--locked`、构建前后 Git 状态一致性和完整前端/payload tree 哈希。
