## 实现结论

- `scripts/ai/build_ntpro_local_delivery.sh` 从已验证源码产物生成自包含交付目录，并拒绝覆盖
  无交付标记的未知目录；
- `start-ntpro` 是普通用户唯一入口，复用冻结的 `nautilus mvp serve` 合同；
- 用户数据默认写入系统用户数据目录，不写入可删除、可升级的交付目录；
- 启动前验证两个二进制、节点/回测配置、production frontend、绑定地址和超时参数；
- PID 所有权锁拒绝同一工作区重复启动，死 PID 对应的失效锁通过原子目录移动接管；
- launcher-only 异常由独立守护进程向 NTPRO 发送 `SIGINT` 并清理匹配 owner/child 的锁；
- Ctrl-C/HUP/TERM 均映射为 MVP 可处理的 `SIGINT`，随后由现有编排停止仍在运行的 node；
- 中文说明分别描述普通用户操作和交付构建命令，不要求用户理解 Cargo、crate 或进程编排；
- CI 在 Cargo、CLI、Product API、两个配置、frontend、toolchain 或交付层变化时增加
  package/browser lifecycle smoke，并继续运行完整策略工作台 Backtest + Demo production 验收；
- manifest 只接受当前工作区构建的二进制，并记录 Git dirty 状态、OS、CPU、Rust target 和关键
  文件哈希；正式 clean build 与开发 dirty build 不会混淆。

## 独立审查整改

第一次独立审查结论为 `CHANGES_REQUESTED`：

- P1：launcher-only 退出可能遗留服务；现已加入独立守护进程，父进程消失后向服务发送 SIGINT，
  等待统一收口并只清理 owner/child 完全匹配的锁；
- P1：TERM/HUP 原样转发会绕过只监听 Ctrl-C 的 MVP；现由 launcher 把三种停止信号统一映射
  为 SIGINT，同时保留服务和 node 的标准信号语义；活动 Demo 终态和 node PID 由真实验收验证；
- P2：失效锁 `rm + mkdir` 存在并发窗口；现改为原子移动到唯一 quarantine，竞争测试证明两个
  恢复者只允许一个启动；
- P2：旧测试只杀整个进程组；现增加 launcher-only SIGKILL、活动 Demo、服务 PID、node PID、
  guardian 锁清理和全进程组异常矩阵；
- P2：CI 遗漏真实交付输入；现覆盖 Cargo、全部 CLI/Product API、两个配置、frontend、toolchain
  和交付脚本；
- P2：manifest 缺平台和可信来源；构建器现强制从当前工作区编译，不再接受任意外部二进制，
  clean/dirty source binding 分离，并记录 OS、CPU、Rust target 与六项关键 SHA-256。

全部整改已在本地重新通过，等待同一独立审查者复审新 head。
