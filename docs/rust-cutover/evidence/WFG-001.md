## Removed Workflows

```text
.github/workflows/build-docs.yml
.github/workflows/build.yml
.github/workflows/cli-binaries.yml
.github/workflows/copilot-setup-steps.yml
.github/workflows/dst.yml
.github/workflows/nightly-docs-features-check.yml
.github/workflows/nightly-merge.yml
.github/workflows/nightly-miri.yml
.github/workflows/nightly-tests.yml
```

The live GitHub audit established:

- `build-docs` only skipped because it was guarded to the upstream repository;
- `build`, `cli-binaries`, and `nightly-merge` targeted absent branches or
  optional tooling outside the current release contract;
- `dst`, `nightly-docs-features-check`, and `nightly-miri` required unavailable
  self-hosted runners; the repository has zero registered self-hosted runners;
- the last ten `nightly Rust tests` runs failed, including a shallow-checkout
  failure that could not resolve the frozen backend baseline commit;
- `copilot-setup-steps` was an unused optional agent bootstrap workflow.

The DST implementation and `make cargo-test-sim` remain in the repository.
Only the unreachable scheduled workflow was removed.

The current automation overview now lists the exact five-workflow authority
surface. The 38 crate README badges that referenced deleted `build.yml` were
mechanically rebound to the required `rust-cutover-smoke.yml` workflow.

The first hosted smoke exposed an existing post-release validation conflict:
the v0.33.0 tag is correctly frozen to its published commit, so it cannot also
equal a later governance PR head. `check_backend_maintenance_release.sh` now
accepts an explicit `NTPRO_V33_ALLOW_POST_RELEASE_HEAD=1` mode. Only PR smoke
sets this mode. Tag-push release gates do not set it and continue to require
the checked-out commit to equal the release tag.
