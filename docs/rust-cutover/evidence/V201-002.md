## Summary

V201-002 hardens V20 runtime submit provenance so current submit evidence must
use the v0.20 runtime release tag and v20 release gate. It removes v0.19.1 /
v19 gate values from V20 positive test fixtures, adds fail-closed negative
tests for stale v19 provenance, and makes production order lifecycle golden
traces carry explicit `runtime_release_provenance`.

Plain Chinese summary: 本任务修复 V20 测试和 golden trace 里旧的 v19 provenance
残留。现在 V20 运行期提交证据必须使用 `ntpro-rust-only-v0.20.0` 和
`v20-release-gates`；v0.19.1 只代表前置 closeout 证据，不能冒充当前运行期
provenance。旧 v19 tag/gate 输入会在 pre-submit、request builder 和 submit
candidate 链路 fail closed。

## Behavior Impact

V20 runtime submit evidence now fails closed when stale v19 / v0.19.1 runtime
provenance is supplied. The change does not expand trading capability, does not
enable automatic retry, automatic cancel, automatic remediation, bulk order
execution, strategy-driven production execution, multi-account execution,
multi-venue execution, or Dashboard order controls.

## Public API Impact

`PreSubmitRiskPolicy` now carries `required_release_tag` alongside
`required_release_gate`. This is a V20 runtime evidence contract hardening; no
Python public product API is added or expanded.

## Rollback Plan

Revert this PR to restore the previous V20 provenance checks and fixtures if
the v20 runtime provenance requirement is found inaccurate. Do not change the
published `ntpro-rust-only-v0.20.0` tag or GitHub Release as part of rollback.
