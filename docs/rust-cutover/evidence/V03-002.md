## Plain Chinese Summary

本任务新增了 v0.3 Dashboard 的统一数据包 `DashboardSnapshot`。

大白话说：后续本地 Dashboard 页面不应该到处读零散文件，也不应该直接碰 `LiveNode`、engine、cache、message bus 这些运行时内部对象。页面应该先读一个干净、稳定、可序列化的 JSON 数据包。这个 PR 就是先把这个数据包和顶层结构定下来。

这次没有实现 HTTP server，没有写 UI，没有读取 supervisor artifacts，也没有实现 start/stop 控制。

## Goal

Define the stable Dashboard read-model DTO consumed by later local HTTP API and static UI work.

## Files Changed

- `crates/cli/src/dashboard.rs`
  - Adds `DashboardSnapshot`.
  - Adds `DashboardValue` and explicit `DashboardAvailability`, including `unknown`, `not_configured`, `not_supported`, `stale`, and `redacted`.
  - Adds top-level sections for overview, nodes, data sources, execution gateways, risk, runtime modules, logs, metrics, alerts, controls, and gaps.
  - Adds `DashboardNodeSummary::from_status` to derive a safe node summary from the existing `NodeStatus` DTO.
  - Adds unit tests for empty, one-node, two-node, gap availability, and forbidden field absence.
- `crates/cli/src/lib.rs`
  - Exposes the new `dashboard` module.
- `.agentflow/state/task_status.json`
  - Marks V03-001 as `DONE` and V03-002 as `RUNNING` for this branch.
- `.agentflow/leases/V03-002.json`
  - Records the V03-002 lease.

## Tests Added Or Updated

Added five `nautilus-cli` unit tests:

- empty snapshot serializes stable top-level sections;
- one-node snapshot counts a running node;
- two-node snapshot counts running and stopped nodes;
- unavailable states survive JSON serialization;
- snapshot JSON does not expose forbidden secret/raw payload keys.
