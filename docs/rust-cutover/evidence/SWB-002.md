## 交付边界

- 生产页面只消费 Rust/Axum 提供的只读 Product API；
- fixture 只允许出现在测试代码；
- 所有 mutation、真实 Venue、真实订单、自动重试、自动补救和交易控件继续关闭；
- v0.32.0 后端冻结基线与 Rust Product API 不变。

## 实现证据

- `OverviewPage` 通过 TanStack Query 依次读取 Strategy、策略详情、不可变版本列表和按策略/
  版本筛选的 Run 列表；
- `/runs/$runId` 通过 URL 恢复 Run 详情，并验证所属 Strategy 与 StrategyVersion；
- AppShell 顶部上下文、右侧栏、底部 Dock 和状态栏统一跟随当前 Product API Run，不再把
  Sandbox 技术实例冒充选中的 Backtest 或 Live Run；
- 生产源码不导入测试 fixture，不直接调用 `fetch`，不复制生成 DTO；
- 合同错误、403、404、网络失败和已验证空列表使用不同状态，错误时不保留旧产品内容；
- 请求路径与响应身份、列表筛选与返回项必须一致；Run、Strategy 和 StrategyVersion 错配
  均 fail closed；
- Product Query 使用零 stale/GC 时效策略，后台刷新、路由切换或重访期间先清空 Shell 和
  页面产品上下文，完整验证后才重新显示；
- 默认版本通过精确详情 API 读取，分页数量明确标记为当前页；三模式状态由 lifecycle 和
  risk 推导；移动 Run 表格使用内部滚动保留可读列宽；
- 桌面 1440x1000 与移动 390x844 无页面级横向溢出，Run 深链布局和禁止能力可见。
