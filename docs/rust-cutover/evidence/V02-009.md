## Plain Chinese Summary

这次给 v0.2 的本地多节点底座补了一条可重复的两节点 smoke。

大白话说：现在有一个本地验证脚本会注册 `sandbox-a` 和 `sandbox-b`
两个节点，分别启动两个独立的 `ntpro-node` 进程，查询两个节点的
status、connections、execution、risk、logs 和 metrics，然后把两个节点都停掉，
最后检查它们确实都停了。

这条 smoke 只使用 sandbox live-init 配置，不连真实交易所，不需要 API key，
也不会提交真实订单。它重点证明两个本地节点的 registry id、进程 pid、status、
metrics 和日志路径不会互相覆盖。

执行过程中发现一个小问题：节点停掉后，registry/status/metrics 都已经是 stopped，
但 `pid.json` 还保留旧的 running 内容。这个 PR 顺手修掉了这个状态不一致，停止节点
后会同步清理 pid artifact，避免用户看到互相矛盾的 artifact。

## Goal

Add repeatable local evidence that the supervisor can manage two independent
sandbox nodes: register both, start both, query running status and artifacts,
stop both, and verify both are stopped.

## Changed Files

- `scripts/ai/v02_two_node_supervisor_smoke.sh`
  - Adds a repeatable local two-node smoke command.
  - Builds `nautilus` and `ntpro-node` unless `NTPRO_V02_009_SKIP_BUILD=1`.
  - Registers `sandbox-a` and `sandbox-b` with distinct artifact roots.
  - Starts both local `ntpro-node` processes through `nautilus supervisor`.
  - Queries status, connections, execution, risk, logs, and metrics for both
    nodes while running.
  - Stops both nodes, then verifies final stopped status and metrics.
  - Uses JSON assertions to prove artifact path isolation and no real venue or
    real order activity.
- `crates/cli/src/supervisor.rs`
  - Clears the pid artifact when `stop_node_process` moves a record to stopped.
  - Extends `start_status_stop_process_roundtrip` so stopped supervisor records
    must not leave stale pid artifacts behind.
- `.agentflow/state/task_status.json`
  - Closes V02-008 as DONE after PR #199 merged.
  - Moves V02-009 to REVIEW_REQUIRED because this is high-risk work.
- `.agentflow/leases/V02-009.json`
  - Records touched paths and validation summary.
- `docs/rust-cutover/evidence/V02-009.md`
  - This evidence file.

## Behavior Impact

This adds a local-only verification script. It does not change trading
semantics, adapter behavior, order submission, or external connectivity.

The only runtime-control behavior change is that supervisor stop now removes the
stale pid artifact after the registry record moves to stopped. This keeps local
artifacts consistent: registry stopped state, stopped status, stopped metrics,
and no leftover running pid artifact.

## Public API Impact

No new public CLI command is added. Existing `nautilus supervisor` commands are
used by the new smoke script.

The observable artifact behavior improves after `supervisor stop`: stale
`pid.json` is removed instead of being left behind with an old running state.

## Migration Note Status

No Python/PyO3/Cython migration note is required. This is Rust-only local smoke
evidence for v0.2 local multi-node runtime foundation.

## Rollback Plan

Revert this PR to remove the V02-009 smoke script, the pid artifact cleanup
change, the additional supervisor unit assertion, the evidence file, and the
agentflow state updates. Reverting returns supervisor stop behavior to the
previous state where stopped registry/status/metrics could coexist with a stale
running `pid.json`.
