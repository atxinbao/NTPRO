# V091-007 Evidence - Strategy Session Manifest And Artifact Audit

Date: 2026-06-19
Executor: Codex
Task: V091-007 Add Strategy Session Manifest And Artifact Audit
Risk level: medium

## Goal

Add a Strategy Session manifest so v0.9.1 strategy artifacts can be audited as
one coherent artifact set.

## Files Changed

- `crates/cli/src/strategy_session.rs`
  - Added `strategy/manifest.json` with schema version
    `ntpro.v091_strategy_session_manifest.v1`.
  - Records session state, created/updated timestamps, child artifact names,
    paths, formats, presence, record counts, byte lengths, and `blake3:`
    checksums.
  - Writes child artifacts first, summary next, and manifest last.
  - Adds tests proving manifest checksums detect corrupted child artifacts.
- `crates/cli/Cargo.toml`
  - Adds the existing workspace `blake3` dependency for artifact checksums.
- `Cargo.lock`
  - Updates the `nautilus-cli` package dependency list for `blake3`.

## Behavior Impact

- Strategy Session output now includes `strategy/manifest.json`.
- The manifest contains metadata only; it does not embed signal, intent, risk,
  exchange order, or venue order payloads.
- Missing artifacts are represented with `present=false`.
- Corrupted artifacts are detectable by recomputing the recorded checksum.
- No order submission path was enabled; `actual_submission=false` and
  `actual_submission_count=0` remain enforced.

## Public API Impact

The `session_status.json` artifact list now includes a `manifest` path. A new
manifest file is emitted under `strategy/manifest.json`. Existing child artifact
paths and CLI command shapes are unchanged.

## Migration Note

Consumers that need artifact completeness should read `strategy/manifest.json`
after a Strategy Session run and compare each child artifact's `present`,
`record_count`, `byte_len`, and `checksum` fields against the file system.
