# V141-004 Clarify openOrders Empty Response

Date: 2026-06-22
Executor: Codex
Risk: medium

## Goal

Clarify that an empty Binance `GET /api/v3/openOrders` response can validate
the endpoint response shape, but it does not prove order lifecycle readiness.

Plain Chinese summary: `openOrders=[]` 只能说明“这个只读接口返回格式对了，而且当前没有未完成订单”。
它不能证明系统已经跑通过下单、成交、撤单、拒单这些订单生命周期。

## Scope

Included:

- add `endpoint_shape_validated`;
- add `order_entries_observed`;
- add `non_empty_order_state_observed`;
- add `order_lifecycle_readiness`;
- expose those fields in the order-state read-only proof report and stdout;
- require the fields in v14/v141 verification scripts;
- add empty-array, non-empty-array, and invalid-shape tests for
  `GET /api/v3/openOrders`;
- update v0.14.1 owner evidence wording.

Not included:

- production order submission;
- production order mutation, cancel, replace, amend, retry, or correction;
- listenKey lifecycle;
- Dashboard order controls;
- automatic remediation;
- real funds or real orders.

## Acceptance

- Empty `openOrders=[]` produces:
  - `endpoint_shape_validated=true`;
  - `order_entries_observed=0`;
  - `non_empty_order_state_observed=false`;
  - `order_lifecycle_readiness=false`.
- Non-empty valid `openOrders` produces lifecycle readiness fields as true.
- Invalid `openOrders` shape produces all readiness fields as false.
- Verification scripts reject missing or inconsistent fields.
- No production mutation or execution capability is added.
