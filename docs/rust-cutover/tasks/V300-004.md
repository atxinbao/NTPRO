## Goal

Define operator approval, freeze, and change-window lifecycle for backend
go-live candidate operations.

Plain Chinese summary: 本任务把 go/no-go approval、freeze、unfreeze、emergency
stop 和 change-window lifecycle 建模为带 audit 的候选证据。它要求 owner/operator
identity provenance 和 immutable audit trail，但 approval lifecycle 不等于交易操作授权，
不会开放 submit、cancel、replace、amend、flatten、adapter send、live exchange
request 或 automatic remediation。

## Dependency

- Depends on `V300-001` backend go-live candidate boundary contract.
- Depends on `V300-003` runtime enablement boundary and controlled feature
  flags.
- Hard-blocked by published v0.29.1 release evidence and closed v0.29.1
  milestone.

## Scope

Included:

- Model go/no-go approval, freeze, unfreeze, emergency stop, and active preview
  change window as audited candidate evidence.
- Require owner/operator identity provenance and immutable audit trail
  references.
- Prove candidate operations fail closed without approval and active change
  window.
- Prove approval evidence cannot authorize trading operation mutation or
  automatic remediation.
- Add deterministic JSON and executable verifier.

Not included:

- production runtime enablement;
- default production submit;
- production order mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal operation controls or trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Candidate operations fail closed without approval and active change window.
- Missing identity provenance or immutable audit trail fails closed.
- Freeze bypass, missing emergency stop, or automatic unfreeze fails closed.
- Approval evidence does not authorize submit, cancel, replace, amend, flatten,
  adapter send, live exchange request, or automatic remediation.
