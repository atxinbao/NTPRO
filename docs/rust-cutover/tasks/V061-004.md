# V061-004 - Decouple workflow artifact browsing from supervisor registry

Milestone: v0.6.1 offline hardening
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Allow the local Dashboard to display workflow artifacts even when the
supervisor registry is missing or not configured.

## Scope

- Add an explicit `dashboard serve --workflow-root <path>` input.
- Keep supervisor node controls backed only by the local supervisor registry.
- Keep workflow artifact rendering read-only.
- Preserve the existing supervisor registry gap when the registry is missing.
- Do not start workflow probes from the Dashboard.

## Non-goals

- Do not connect to Binance testnet.
- Do not submit orders.
- Do not read secrets.
- Do not implement v0.7 online connectivity proof.
- Do not change supervisor control semantics.

## Required Evidence

- Dashboard snapshot can show a `v06-smoke` workflow artifact when the registry
  path is missing and `--workflow-root` points at `runs/workflows`.
- `cargo test -p nautilus-cli dashboard --lib` passes.
- `cargo test -p nautilus-cli workflow --lib` passes.
- `scripts/ai/verify_fast.sh` passes.
- `git diff --check` passes.
