# V070-000 - Define v0.7 real testnet read-only boundary, threat model, and artifact schema

Milestone: v0.7.0 deferred queue
Priority: P0
Owner role: Verification & Release Gatekeeper
Review role: Control & Scope Agent
Risk: high

## Goal

Define the v0.7.0 boundary before any real Binance testnet network code is
implemented. v0.7.0 may prove real read-only connectivity, but it must not
submit orders, handle real funds, or claim production trading readiness.

## Scope

- Define the real testnet read-only proof boundary.
- Define fail-closed network opt-in conditions.
- Define secret handling and artifact redaction rules.
- Define HTTP and optional WebSocket probe artifact schemas.
- Define Dashboard read-only display rules.
- Define offline default gate and manual online gate responsibilities.

## Non-goals

- Do not implement HTTP networking.
- Do not implement WebSocket networking.
- Do not add order submission.
- Do not add production trading behavior.
- Do not add Dashboard buttons that initiate network probes.
- Do not create a tag or GitHub Release.

## Required Evidence

- `docs/rust-cutover/release/v0_7_0_readonly_testnet_boundary.md`
- `scripts/ai/verify_fast.sh`
- boundary keyword scan for read-only/no orders/no secrets/fail-closed/manual
  online gate
- `git diff --check`

## Acceptance

- The boundary document explicitly states read-only connectivity only.
- The document explicitly states no orders, no real funds, no production
  trading claim, and no secret persistence.
- The document lists all fail-closed opt-in conditions:
  `--allow-testnet-network`, `NTPRO_ALLOW_TESTNET_NETWORK=1`,
  `environment=testnet`, `order_submission=disabled`, and
  `real_orders_submitted=false`.
- The document separates default offline CI from manual online gate behavior.
- The document keeps WebSocket proof optional/manual and not a default release
  blocker.
