# V03-015 - Dashboard controls and API smoke

Milestone: v0.3.0 Local Supervisor Control Console
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Update the local Dashboard controls and smoke coverage for start, stop, pause,
resume, reconnect data, and reconnect execution.

Plain language: the Dashboard should no longer merely show pause/resume and
reconnect as disabled if v0.3.0 claims a local Supervisor control console.
It must show the real supported sandbox controls and clear unsupported reasons
where a deeper adapter path is still out of scope.

## Dependencies

- `V03-012`
- `V03-013`
- `V03-014`

## Scope

- Update Dashboard control state for pause/resume/reconnect actions.
- Add or update local HTTP API handlers for supported controls.
- Keep unsupported paths explicit and disabled.
- Extend Dashboard smoke to verify the new controls.
- Preserve static no-framework Dashboard implementation.

## Non-goals

- Do not add manual order controls.
- Do not add order modification or cancellation controls.
- Do not add production reconnect controls.
- Do not add remote or multi-user Dashboard operation.
- Do not introduce a frontend framework.
- Do not create a release tag or GitHub Release.

## Related files

- `crates/cli/src/dashboard.rs` (TO_MODIFY): UI/API/control state.

- `docs/rust-cutover/evidence/V03-015.md` (CREATE): task evidence.

## Implementation guidance

Keep the UI dense and operational. Controls must have clear enabled/disabled
states and clear reasons. Browser smoke must verify no obvious overlap at
desktop and mobile widths.

## Verification criteria

- Dashboard renders start/stop/pause/resume/reconnect data/reconnect execution
  controls.
- Supported controls return success in sandbox mode.
- Unsupported controls return explicit unsupported results.
- Browser smoke verifies desktop and mobile layout.
- No manual order controls appear.
