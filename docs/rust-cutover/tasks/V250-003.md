## Goal

Define the v0.25.0 incident lifecycle and operator acknowledgement evidence
contract. Incidents are read-only operational evidence: they link alerts to a
state machine, owner/assignee records, acknowledgement proof, audit trace,
lineage, freshness, provenance, and redaction without triggering any real
operation.

Plain Chinese summary: 本任务定义 v0.25.0 的 incident lifecycle 和 operator
acknowledgement 证据合同。incident 可以从 opened、triaged、acknowledged、
mitigated、resolved 到 postmortem 留下可审计链路；但它只记录证据和人工确认，不会
自动停止策略、撤单、提交订单、调用 adapter send、访问 live exchange，也不开放交易
操作入口。

## Scope

Included:

- incident states and allowed transitions;
- owner, assignee, timestamps, source alert linkage, audit trace, lineage,
  source provenance, redaction, and freshness contract;
- operator acknowledgement lifecycle and required evidence;
- golden trace and verifier coverage for valid lifecycle, invalid transition,
  missing owner/source alert, missing acknowledgement, stale incident,
  redaction breach, and automatic-action boundary violations;
- release replay scope entries as validator executable replay.

Not included:

- real incident ticket system integration;
- automatic strategy stop, cancel, submit, retry, replace, amend, or flatten;
- adapter send or live exchange requests;
- Dashboard trading controls or order operation controls.

## Acceptance Criteria

- Invalid incident state transitions fail closed.
- A resolved or postmortem incident without owner acknowledgement fails closed.
- Missing owner, assignee, source alert, source provenance, lineage, audit
  trace, freshness, or redaction evidence fails closed.
- Stale incident evidence fails closed.
- Incident artifacts must not contain secret, raw credential, signed payload,
  signature, raw order id, or unredacted trading-sensitive field values.
- Incident evidence cannot directly trigger order mutation, strategy stop,
  adapter send, live exchange request, external ticket mutation, or automatic
  remediation.
