# V151-004 - Tighten v0.15 dry-run order gate to LIMIT only

Date: 2026-06-23
Executor: Codex
Milestone: v0.15.1 mutation dry-run semantics / order gate hardening
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Harden the v0.15 production live-alpha dry-run order gate so it accepts only a
tiny scoped `LIMIT` order intent. `MARKET` order intents must fail before any
request-preview artifact can be built from the order gate.

Plain Chinese summary: v0.15 的 dry-run order gate 只能记录 `LIMIT` 意图，不能再接受
`MARKET`。这只是收紧本地 dry-run 合同，不会联网、不调用生产 adapter、不真实下单。

## Scope

Included:

- default the dry-run order gate CLI option to `LIMIT`;
- reject any non-`LIMIT` order type at the dry-run order gate;
- add a `MARKET` fail-closed regression in the v0.15 request-preview verifier;
- align v0.14 release gate fixtures with the same `LIMIT` dry-run order gate
  contract;
- align v0.14 reconciliation golden traces with the same `LIMIT` dry-run order
  gate contract;
- keep the existing `LIMIT` request-preview path working.

Not included:

- production order submission;
- production order-test submission;
- production HTTP request execution;
- production execution adapter calls;
- trading engine semantic changes;
- real funds;
- production trading;
- Dashboard order controls.

## Acceptance Criteria

- `MARKET` dry-run order gate input fails before request preview.
- `LIMIT` dry-run order gate input still writes a ready dry-run-no-submission
  artifact when owner confirmations are present.
- Request-preview generation continues to require a `LIMIT` order gate.
- All paths preserve:
  - `request_sent=false`
  - `network_attempted=false`
  - `production_orders_submitted=0`
  - `production_order_mutations_attempted=0`
  - `execution_adapter_called=false`
  - `dashboard_order_controls_enabled=false`
