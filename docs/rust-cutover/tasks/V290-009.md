## Goal

Harden backend production readiness so partial readiness cannot be misread as
backend go-live readiness or trading readiness.

Plain Chinese summary: 本任务把 v0.29 backend production readiness 汇总层固化为
fail-closed replay。它横向检查 audit、telemetry、permission、read API、deployment
config、runbook、monitoring、canary、rollback/DR component；partial/stale/source
drift/missing component 不能被误读为 go-live 或 trading readiness，任何 submit、
mutation、adapter、remediation、trading control、backend go-live claim 或 live
trading claim 打开都会 fail closed。

## Dependency

- Depends on `V290-000` through `V290-008`.

- Builds on `V280-008` backend closure fail-closed hardening.

## Scope

Included:

- Add deterministic fail-closed checks across v29 readiness components.
- Keep backend production readiness health separate from backend go-live and
  trading readiness.
- Reject missing, stale, partial, source-drifted, malformed, ambiguous
  go-live, ambiguous live trading, forbidden control, and missing
  required-false boundary states.

Not included:

- backend go-live;
- live trading readiness;
- submit/order mutation/adapter/live exchange/retry/remediation execution;
- Dashboard/Admin/Trader Terminal trading controls;
- production deployment, rollback, canary, or DR execution.
