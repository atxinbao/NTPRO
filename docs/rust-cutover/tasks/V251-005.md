# V251-005 post-release gate split and closeout hardening

Date: 2026-07-06
Executor: Codex
GitHub issue: `#810`
Milestone: `v0.25.1`
Status: LOCAL VALIDATION PASSED

## Goal

Split v25 pre-release validation from tag/release-stage and post-release
closeout validation so missing-tag, offline, or current-issue-open states cannot
be mistaken for completed release evidence after publication.

Plain Chinese summary: 本任务把 v25 PR 阶段 gate 与发布后 closeout gate 拆清楚。PR
阶段的 missing tag / current issue open 只能作为历史 pre-release validation；在
`NTPRO_RELEASE_GATE=1` 或 post-release closeout 下，missing tag、offline
publication、open issue、open milestone、failed hosted run 都必须 fail closed。

## Scope

- Add the v25 post-release gate split contract.
- Add a `v25.1-post-release-gate-split` release verifier.
- Record the split and v0.26 start-blocking rule in the v25 release manifest,
  readiness report, and closeout evidence.
- Keep `#804` corrective issue and PR `#805` as required post-release closeout
  facts.
- Add negative self-tests for missing tag, HEAD/tag mismatch, offline
  publication proof, pre-publication state, open closeout issue, open corrective
  issue, open milestone, failed hosted run, draft release, and v0.26 start
  allowed while v0.25.1 release evidence is missing.

## Non-Goals

- No change to the basic release publication workflow.
- No v0.25.0 tag rewrite.
- No runtime behavior change.
- No production order submission or mutation.
- No execution adapter send, live exchange request, retry scheduler, automatic
  remediation, Dashboard trading controls, or product-grade live trading
  terminal claim.
