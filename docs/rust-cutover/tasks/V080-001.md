# V080-001 Migrate Credential Config Contract for Public vs Authenticated Probes

Date: 2026-06-16
Executor: Codex
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk level: medium
Status: PR_REQUIRED

## Goal

Split the Binance testnet credential config contract so public read-only probes
and authenticated read-only probes have explicit credential requirements.

## Scope

- Support `credentials.required_for_public_read_only_probe = false`.
- Support `credentials.required_for_authenticated_read_only_probe = true`.
- Keep legacy `credentials.required_for_network` readable for v0.7 artifact
  compatibility.
- Make the new split fields take priority over the legacy field.
- Emit migration-warning evidence when the legacy field is present.
- Update the checked-in Binance testnet dry-run config example.
- Update credential-policy artifact schema with the split contract fields.

## Non-Goals

- No network call implementation.
- No request signing implementation.
- No authenticated online probe.
- No order submission, cancel, replace, amend, or account mutation.
- No production Binance connectivity.
- No real funds.
- No production trading.
- No secret persistence or secret-value artifact fields.

## Acceptance

- Checked-in testnet config includes the new split credential fields.
- Legacy `required_for_network` remains accepted.
- Legacy field presence is recorded as a migration warning.
- Credential-policy artifacts expose:
  - `public_read_only_probe_requires_credentials = false`
  - `authenticated_read_only_probe_requires_credentials = true`
  - `required_for_public_read_only_probe = false`
  - `required_for_authenticated_read_only_probe = true`
- Public read-only probe behavior remains credential-free.
- Authenticated read-only probe remains manual-online-only and env-only.
