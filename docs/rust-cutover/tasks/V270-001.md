## Goal

Define the v0.27.0 Product Operations Runtime Integration Foundation boundary
contract before implementation. The contract declares what v0.27.0 may
integrate for product operations and makes the forbidden trading capability
boundary explicit, required, and fail-closed.

Plain Chinese summary: 本任务定义 v0.27.0 的 product operations runtime integration
边界合同。v0.27.0 只允许做 external identity/permission integration、persistent
operation audit storage、deployment/upgrade/rollback orchestration foundation、
long-run telemetry ingestion、admin workbench state bridge 和 fail-closed runtime
integration；不新增默认下单、订单变更、adapter send、live exchange request、retry
scheduler、automatic remediation、Dashboard trading controls，也不声明 product-grade
live trading terminal 已完成。

## Dependency

- Depends on `V270-000` intake gate and its `start_gate_status = satisfied`
  proof.
- Hard-blocked by v0.26.1 issue closeout and release publication evidence.
- Does not inherit any submit, mutation, adapter-send, remediation, or
  Dashboard trading-control capability from v0.26.1.

## Scope

Included:

- Define v0.27.0 product operations runtime integration foundation scope.
- Define allowed capability flags for identity, audit, deployment orchestration,
  telemetry ingestion, admin workbench state, and fail-closed integration.
- Define required source provenance, freshness, redaction, lineage, and failure
  semantics.
- Define required-false boundary flags for forbidden trading and mutation
  capabilities.
- Add golden trace rows that prove missing provenance, stale freshness,
  unredacted/unaligned lineage, forbidden trading boundaries, terminal claims,
  and missing required-false flags fail closed.
- Add a verifier that recomputes the effective boundary status from the trace.
- Record the trace rows in the release replay scope as validator executable
  replay.

Not included:

- production order submission;
- cancel, replace, amend, flatten, or any production order mutation;
- execution adapter call, adapter send, or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard operation controls or Dashboard trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Release docs identify v0.27.0 as Product Operations Runtime Integration
  Foundation, not a production execution runtime or product-grade trading
  terminal.
- All required source provenance and boundary fields are explicitly present in
  the passing fixture.
- Any missing provenance, stale freshness, unredacted payload, broken lineage,
  submit, mutation, adapter send, live exchange request, automatic remediation,
  Dashboard trading control, or product-grade terminal claim fails closed.
- Any missing required-false boundary field fails closed.
- `scripts/ai/verify_release.sh v27-product-operations-boundary-contract`
  passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V270-001 cases as validator executable replay.
