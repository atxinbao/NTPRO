## Goal

Add a post-publication closeout gate so a published release cannot remain
represented only as release_gate_ready.

Plain Chinese summary: 本任务给 v0.29.0 增加发布后的 closeout gate。发布已经公开后，
manifest、readiness report 和 release notes 不能继续只停留在 `release_gate_ready` /
`RELEASE GATE READY` 状态；gate 必须要求 GitHub Release 已公开、hosted release gate
成功、milestone/issue scope 已关闭、release body hash 与源码 notes 一致、tag commit
匹配，并且发布顺序是 gate 成功后再 publish。它不改变 runtime，不开放 backend go-live，
也不开放 submit、mutation、adapter send、live exchange request、retry、
automatic remediation 或任何交易控件。

## Dependency

- Depends on V291-001 source-controlled v0.29.0 closeout evidence.
- Depends on V291-002 v29 publish-after-gate current-release binding.
- Depends on V291-003 stale V290 evidence cleanup.
- Blocks v0.30.0 release/go-live candidate gates until post-publication proof
  rejects release-gate-ready-only and generated-evidence-only states.

## Scope

Included:

- Mark v0.29.0 release notes/readiness as `Status: RELEASED`.

  manifest.

  validation modes.

  release-gate-ready-only artifacts after publication.

Not included:

- production submit or production order mutation;
- execution adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal trading controls;
- product-grade live trading claim.
