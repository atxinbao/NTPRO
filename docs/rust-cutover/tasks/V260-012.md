# V260-012 - v26 prepublish publication guard split

Date: 2026-07-07
Executor: Codex
GitHub issue: #843
Milestone: v0.26.0

## Goal

Split current-release publication validation so tag-stage gates can validate the
local release notes and release tag before publication, while post-publication
checks still require the GitHub Release body to match the release notes.

## Context

After V260-011 corrected the v0.26.0 release notes, the existing public
GitHub Release still had the old body. The hosted tag gate for
`ntpro-rust-only-v0.26.0` failed because `release-publication-guard` required
the stale body to match before the release-publish workflow had a chance to
republish it.

## Scope

- Add an explicit `NTPRO_RELEASE_PUBLICATION_PREPUBLISH_TAG_GATE=1` mode.
- Use that mode only for current release tag-stage validation.
- Keep normal release publication validation strict after publication.
- Keep historical release publication checks strict.
- Do not change runtime, Dashboard, adapter, order, or public API behavior.

## Acceptance

- Prepublish publication guard mode passes with local release notes and tag
  reachability before republishing the current Release body.
- `NTPRO_RELEASE_GATE=1 scripts/ai/verify_release.sh v26-release-gates` passes
  locally before republishing the current Release body.
- Hosted `Rust Cutover Release Gate` succeeds after the corrective PR merges and
  the v0.26.0 tag is updated.
- `release-publish.yml` reruns after hosted gate success, and strict
  post-publication validation passes.
