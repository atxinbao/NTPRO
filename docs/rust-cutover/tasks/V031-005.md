# V031-005 - process identity hardening

Milestone: v0.3.1 Local Supervisor Control Console Hardening
Priority: P1
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Reduce false positives from bare PID reuse in local supervisor process-state
tracking.

Plain language: the control plane should know more than just "some process still
has this pid".

## Dependencies

- `V031-004`

## Scope

- Extend local process artifacts with stronger identity fields such as
  node id, start marker, executable path, or equivalent stable evidence.
- Validate that the live process still matches the recorded node identity before
  reporting it as running.
- Mark mismatches as stale or failed instead of silently trusting PID reuse.
- Add deterministic tests for identity match and mismatch cases.

## Non-goals

- Do not add OS-specific deep process introspection beyond what is needed.
- Do not build a distributed process supervisor.
- Do not broaden the product claim past local sandbox node control.

## Related files

- `crates/cli/src/supervisor.rs` (TO_MODIFY): process identity and pid artifact.
- `docs/rust-cutover/evidence/V031-005.md` (CREATE): task evidence.

## Implementation guidance

Favor portable identity evidence that can be written by the local process and
re-read by the supervisor without introducing a heavy dependency chain.

## Verification criteria

- PID reuse no longer reports a mismatched process as healthy running state.
- Matching identity still reports running state correctly.
- Tests cover match and mismatch cases.
