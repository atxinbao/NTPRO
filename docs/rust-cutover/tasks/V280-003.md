## Goal

Move persistent operation audit storage from contract evidence to a
deterministic backend closure artifact with replayable write/read semantics.

Plain Chinese summary: 本任务把 persistent audit storage runtime closure 固化成一个
可复放的 backend artifact。它验证 append-only sink、storage provenance、retention/
freshness、idempotency、read-after-write、redaction 和 source/store lineage；缺 storage、
source stale、lineage 断裂、payload 未脱敏或任何 operation/remediation/trading trigger
都会 fail closed。本任务不实现真实数据库，不触发自动修复或真实交易控制。

## Dependency

- Depends on `V280-001` backend closure boundary contract and readiness matrix.
- Depends on `V280-002` identity and permission runtime closure for actor role
  provenance.
- Uses `V270-003` persistent audit storage foundation and `V260-003` audit
  trail evidence as historical baselines.

## Scope

Included:

- Define deterministic persistent audit storage runtime artifact.
- Define storage sink contract, schema, retention/freshness, idempotency, and
  provenance checks.
- Replay write/read semantics through append-only records.
- Fail closed on missing storage, stale audit source, broken lineage,
  unredacted payload, and forbidden operation trigger.
- Promote `persistent_audit_storage_runtime_closure` to `runtime-closed` in the
  v0.28.0 backend closure readiness matrix.

Not included:

- external audit database implementation;
- order execution or production mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin operation or trading controls;
- product-grade live trading terminal readiness claims.
