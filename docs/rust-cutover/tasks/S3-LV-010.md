# S3-LV-010 - Live 风险预算与仓位 sizing 准入

Date: 2026-08-14
Executor: Codex
GitHub issue: #1308
Risk: critical
Owner role: Rust Product Surface Agent + Rust Core Runtime Agent + Frontend Agent
Review role: Verification & Release Gatekeeper
Status: DONE

## 目标

在 S3-LV-009 的不可变策略意图与单笔 Live 执行之间增加确定性的风险预算和仓位 sizing
决策。每笔订单必须同时绑定新鲜的账户可用资金、Venue 交易规则、策略原始数量和全局风险
上限，任何缺失、过期或漂移均 fail closed。

## 控制合同

- Live preflight 冻结脱敏账户资金快照和标的 `PRICE_FILTER`、`LOT_SIZE`、`MIN_NOTIONAL`；
- sizing 决策绑定 Run、StrategyVersion、Demo intent、账户快照、Venue 规则、价格和数量；
- 最终数量不得大于策略意图数量，并按 step size 向下规范化；
- 价格必须符合 tick size，数量必须处于 min/max quantity，名义金额必须达到 min notional；
- 订单名义金额不得超过账户可用 quote 资金预算，也不得超过全局单笔风险上限；
- 三角色审批、execution admission、Runtime config 和订单状态必须绑定同一 sizing 哈希。

## 强制边界

- 不开放策略自动连续下单、追加订单、改单、批量操作、自动重试、自动修复或自动恢复；
- 不从 Backtest/Demo 自动继承 Live 权限；
- 客户端不能改写策略方向或放大策略数量；
- 测试不得访问真实 Binance endpoint 或发送真实订单；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`，不关闭 S3 milestone。

## 完成条件

- Rust 覆盖资金、时效、step/tick、min/max quantity、min notional、预算和哈希漂移；
- Product API、OpenAPI、生成 SDK 和策略工作台展示同一 sizing 来源链；
- fmt、Clippy、Rust-only、风险 inventory、冻结治理与浏览器 smoke 通过；
- 独立 Gatekeeper 审批、hosted checks 全绿后手动合并，禁止 auto-merge。

## 非目标

本任务不开放无人值守策略执行、多账户组合预算、跨币种估值或多订单编排。
