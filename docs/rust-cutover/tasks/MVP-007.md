## 目标

新增独立控制中心浏览器入口，使平台运维通过 `ntpro.mvp_shared_status_api.v1`
确认单节点 MVP 身份、四轴状态、业务影响和关闭边界，同时通过现有本地运维投影查看
节点、组件、日志、指标、告警和来源。

## 接口与路由

```text
GET /control-center
GET /assets/control-center.css
GET /assets/control-center.js
GET /api/mvp/v1/status
GET /api/mvp/v1/control-center
```

新页面和静态资源严格 GET-only。页面不调用节点 action API，不读取原始 Event Store、
原始 Venue payload 或凭证。

## 合同边界

- 共享合同必须包含 `control_center` consumer；
- 共享 node ID 必须与唯一运维节点一致；
- 专用运维投影 registry path 必须包含在共享 `source_refs`；
- 专用运维投影 registry path 必须与共享状态 provenance 严格相等；
- 共享身份、状态、API 三层边界必须完整关闭；
- HTTP 200、进程存活和回测引用不能解释为技术健康、研究验收或交易准入；
- 任一合同、身份、provenance 或运维投影异常时先清空旧数据并 fail closed；
- 页面不得包含 Supervisor action、交易、审批、重试或自动补救控件。
- 浏览器不得接收完整 Dashboard snapshot、controls、订单/生产操作证据或原始错误文本。
