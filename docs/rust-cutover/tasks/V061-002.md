# V061-002 - Harden connectivity-probe semantics and offline-only messaging

Milestone: v0.6.1 offline hardening
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Make Binance testnet `connectivity-probe` mode clearly represent offline probe
intent in CLI output and artifacts, without opening any network socket.

## Scope

- Keep v0.6.1 strictly offline-only.
- Record `requested_mode=connectivity-probe` when that mode is requested.
- Record `network_permission_requested=true` when
  `--allow-testnet-network` is supplied.
- Keep `network_attempted=false` and `testnet_connection=false`.
- Make `runtime_status` distinguish probe intent from ordinary dry-run.
- Update CLI help to avoid implying real connectivity.

## Non-goals

- Do not connect to Binance testnet.
- Do not submit orders.
- Do not read or persist secret values.
- Do not implement v0.7 online connectivity proof.
- Do not change trading semantics.

## Required Evidence

- Connectivity-probe CLI output shows requested mode and offline network flags.
- `manifest.json`, `summary.json`, and `testnet/connectivity_probe.json` agree.
- `cargo test -p nautilus-cli workflow --lib` passes.
- `cargo test -p nautilus-cli dashboard --lib` passes.
- `scripts/ai/verify_fast.sh` passes.
- `git diff --check` passes.
- Migration note exists for offline connectivity-probe semantics.
