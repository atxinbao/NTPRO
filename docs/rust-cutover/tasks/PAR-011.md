# PAR-011 Ignored-Test Register And Risk Ownership Governance

Date: 2026-07-29
Executor: Codex
GitHub issue: #1179
Risk: medium
Classification: verification-governance
Status: LOCAL_VALIDATION_PASSED / REVIEW_REQUIRED

## Goal

Establish one current ignored-test authority and distinguish explicit inline
test modules from production signals in the backend runtime risk inventory.

中文摘要：本任务不恢复或删除测试，而是统一 ignored-test 的当前登记口径，
并防止 `src/*.rs` 中明确属于 `#[cfg(test)] mod ...` 的测试代码继续被统计为
生产风险。

## Scope

- make the quality register the sole `CURRENT` ignored-test authority;
- retain the older verification register as `HISTORICAL_EXTENSION`;
- automatically verify 18 direct and 6 conditional ignored attributes;
- require every active ignored-test source path to appear in the current
  register;
- classify explicit inline test-module signals as `test_inline`;
- preserve generated, FFI, dedicated-test, and conservative production
  ownership precedence;
- bind both validators and their negative self-tests into current governance.

## Non-Goals

- no ignored test is re-enabled, removed, or behaviorally changed;
- no production Rust runtime or public API changes;
- no edit to frozen `docs/rust-cutover/release/v0_32_0_*` files;
- no submit, mutation, adapter send, live exchange, retry, remediation, or
  trading-control capability.

## Acceptance

- exactly one register is marked `CURRENT`;
- direct, conditional, and total counts are reproducible;
- canonical risk inventory separates `test_inline` from production;
- synthetic fixtures prove module boundaries and ownership precedence;
- current governance, backend freeze, shell syntax, and document checks pass;
- independent review and final-head hosted checks approve before merge.
