# V221-004 - Gate-before-publish release governance

Date: 2026-07-02
Executor: Codex
GitHub issue: `#708`
Milestone: `v0.22.1`
Risk: critical release governance
Owner role: Verification & Release Gatekeeper
Review role: Control & Scope Agent
Auto-merge: allowed after local validation and hosted checks pass

## Goal

Harden the Rust-only release publication path so a public GitHub Release cannot
be published before the hosted `Rust Cutover Release Gate` succeeds for the
same release tag commit.

Plain Chinese summary: 本任务把发布顺序改硬：`ntpro-rust-only-v0.22.1` 可以先准
备 draft release，但公开发布必须在对应 tag 的 hosted release gate 成功之后执行。
发布入口会核对 gate run 已完成、结果为 success、workflow 名称正确，并且 run 的
`headSha` 等于 release tag commit。

## Scope

Included:

- add a scripted release publication entrypoint that requires a successful
  hosted release gate run id before publishing;
- add a `workflow_dispatch` GitHub Actions workflow that calls the same
  publication entrypoint with `contents: write` and `actions: read`;
- add a fake-`gh` verification script proving draft-after-gate passes,
  already-public-after-gate is idempotent, failed gates are blocked, and
  pre-gate public releases are rejected;
- add the verification stage to `release-tag.yml` and the PR smoke workflow;
- document the v0.22.1 operational release sequence and rollback plan.

Not included:

- creating the `ntpro-rust-only-v0.22.1` tag;
- publishing the v0.22.1 GitHub Release;
- weakening existing release or strict provenance gates;
- starting any v0.23.0 implementation before v0.22.1 is closed and published.

## Acceptance Criteria

- Public release publication requires a completed successful hosted release gate
  for the same tag commit.
- Draft releases may exist before the gate, but publishing the draft is blocked
  until the gate succeeds.
- Existing public releases are accepted only if `publishedAt` is not earlier
  than the hosted gate completion timestamp.
- Local and hosted smoke paths validate the publication-order guard without
  mutating real GitHub Releases.
