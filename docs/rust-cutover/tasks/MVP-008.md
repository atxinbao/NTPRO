## 目标

在机构工作台与控制中心之间建立同一运行实例的最小只读事件关联，使交易员从业务影响
跳转到技术根因，运维从技术状态返回业务影响，同时保持两个门户的一级导航和职责边界
独立。

## 接口与路由

```text
GET /api/mvp/v1/event-correlation
GET /institution-workbench?event_id=<encoded-id>#event-correlation
GET /control-center?event_id=<encoded-id>#event-correlation
```

新 API 独立于既有 `GET /api/mvp/v1/status` 和
`GET /api/mvp/v1/control-center`，不修改两者的 schema。关联投影只从已验证的共享身份
与状态合同生成，不读取原始 Event Store。

## 合同边界

- 事件 ID 由 node、strategy 与 strategy instance 三个身份字段分别做 URL 组件规范编码，
  再与 `technical_health` 事件类型确定性生成；字段中的分隔符不能造成跨实例碰撞；
- 关联必须严格匹配 identity contract、node ID 与 strategy instance ID；四轴、业务影响和
  技术状态由门户从同一次已验证的共享状态响应读取，不在关联响应中重复；
- 事件类型固定为 `technical_health_observation`，来源固定为
  `projected_status_contract`，不能冒充原始运行时事件；
- 目标路径固定为 `/institution-workbench` 与 `/control-center`；
- URL 中存在一个 `event_id` 时必须与当前关联严格相等；存在多个参数时无论值或顺序均
  清空旧状态并阻断；
- 响应不得包含 source path、原始事件 payload、错误正文、凭证、controls 或动作；
- read-only 与 projected-status 边界必须为 true，原始事件、错误、Supervisor action 和
  交易控件边界必须显式为 false；
- 新 API 与门户资源严格 GET-only，HEAD 和所有其他方法返回 405。

## 非目标

- 服务端角色授权与机构范围过滤；
- Supervisor 启停、暂停、恢复或重连动作；
- 下单、撤改、审批、重试、自动补救或外部网络；
- 修改 v0.32.0 冻结发布文件；
- 关闭 M3。
