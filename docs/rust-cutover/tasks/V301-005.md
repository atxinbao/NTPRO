## Goal

Resolve the v0.29.1 post-publication semantics mismatch inherited by v0.30.0
intake evidence.

Plain Chinese summary: 本任务把 v0.29.1 的 manifest、readiness report、release
notes 和 closeout evidence 收口成一个统一的发布后权威契约。v0.29.1 公开发布后，
source tree 不能同时表现为 `release_gate_ready` / `RELEASE GATE READY` 和
`RELEASED`。v0.30.0 intake 只能消费
`v0_29_1_authoritative_closeout_contract`，不能再从相互矛盾的 predecessor release
状态里挑选证据。

## Dependency

- Depends on published v0.29.1 release evidence.
- Depends on published v0.30.0 release evidence.
- Blocks all v0.31.0 capability work until the full v0.30.1 patch release is
  published and reconstructable.

## Scope

Included:

- Mark v0.29.1 release notes/readiness/manifest as published.
- Populate v0.29.1 `published_release`, `post_publication_closeout`, and
  `authoritative_predecessor_closeout_contract` manifest fields.
- Recompute v0.29.1 release body hashes and synchronize v30 intake evidence.
- Add a v30.1 verifier for predecessor closeout reconciliation.
- Harden v30 intake so it consumes the authoritative predecessor contract.

Not included:

- backend go-live;
- production submit or production order mutation;
- execution adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal trading controls;
- product-grade live trading claim.
