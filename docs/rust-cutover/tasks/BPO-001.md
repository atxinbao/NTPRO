# BPO-001 Reproducible Backend Performance And Resource Baseline

Date: 2026-07-20
Executor: Codex
GitHub issue: #1120
Milestone: v0.33.0-backend-maintenance
Risk: medium
Classification: v33-separately-scoped
Status: READY FOR PR

## Goal

Establish the fixed measurement contract used by later v0.33.0 backend
maintenance work before any optimization is implemented.

Plain Chinese summary: 本任务先固定测量对象、环境、采样方式、噪声预算和回归阈值，
再允许后续优化。它不修改运行时行为，不把本机数据描述为 hosted 权威，也不继承
v0.32.0 的生产提交、mutation、adapter send、live request 或交易控件能力。

## Scope

- release build time, peak RSS, and `nautilus` / `ntpro-node` binary size;
- representative core, model, data, execution, live, and network Criterion
  workloads;
- three process-level observations per workload using `bench-lto`;
- machine-readable environment, methodology, values, variance, and thresholds;
- fail-closed Rust validation and negative mutations;
- a separate `backend-performance-baseline` release verification stage.

## Measurement Contract

- compare only same-host, same-toolchain, back-to-back runs;
- use one-second warmup, two-second measurement, 20 Criterion samples, and
  three complete sessions;
- decide on the median of three sessions;
- warn at the configured warning percentage;
- fail at the greater of the configured failure percentage or three times the
  baseline coefficient of variation;
- treat this local capture as a reference, not a hosted merge gate;
- BPO-002 owns hosted runner materialization and comparison enforcement.

| live runner dispatch | rust_live_runtime_agent | `crates/live/benches/runner.rs` |
| network rate limiter | rust_network_runtime_agent | `crates/network/benches/ratelimiter.rs` |
| CLI release build and binaries | verification_release_gatekeeper | `crates/cli` |

## Not In Scope

- runtime, adapter, schema, public API, or trading-semantic changes;
- optimization implementation or performance claims;
- hosted benchmark workflow implementation;
- editing `docs/rust-cutover/release/v0_32_0_*`;
- production deployment or capability enablement.

## Acceptance Criteria

- all seven representative surfaces and owners are documented;
- environment, warmup, sample count, observations, variance, and thresholds
  are machine readable;
- benchmark source paths and commands are validated;
- eight negative mutations prove fail-closed behavior;
- current governance and backend freeze gates pass;
- the repository-local `target/` remains absent after validation.
