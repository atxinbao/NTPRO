## Goal

Define SLO, runbook, and long-run stability evidence so release gates and
Dashboard can inspect stability status, degradation reasons, restart
recommendations, and release drift without executing automatic recovery,
trading actions, or runtime remediation.

Plain Chinese summary: 本任务定义 SLO / runbook / long-run stability evidence。
它覆盖 long-run window、SLO objective、error budget、degradation reason、
stability sample provenance、freshness、redaction、missing components、restart
recommendation、runbook stale 和 release drift。所有证据只能被 release gate 和
Dashboard 只读展示，不能自动恢复、自动重启、停止策略、撤单、下单或触发任何 trading
operation。

## Dependency

- Depends on `V260-001` product hardening boundary contract.
- Depends on `V260-004` deployment provenance model.
- Depends on `V260-005` upgrade rollback runbook evidence.
- Keeps stability evidence and runbook recommendation only.
- Does not add real soak test infrastructure.
- Does not execute automatic recovery, restart, stop-strategy, cancel, or trade
  actions.

## Scope

Included:

- Define long-run window, SLO objective, error budget, degradation reason,
  stability sample provenance, sample freshness, and redaction evidence.
- Cover valid long-run window, stale/unredacted samples, missing components with
  restart recommendation, error budget exhausted, runbook stale, and release
  drift.
- Add a verifier that recomputes stability status from the trace.
- Register the trace rows in release replay scope as validator executable
  replay.

Not included:

- real soak test infrastructure;
- automatic restart or automatic remediation runtime;
- strategy stop, cancel, order submit, rollback execution, or trading recovery;
- live exchange requests;
- Dashboard execution controls.

## Acceptance Criteria

- Missing sample provenance, stale freshness, or missing redaction cannot render
  as healthy.
- Error budget exhausted fails closed and does not automatically recover.
- Missing components degrade and can only emit a restart recommendation preview.
- Runbook stale degrades without executing remediation.
- Release drift fails closed.
- Stability evidence can be release-gate checked and Dashboard displayed as
  read-only evidence.
- `scripts/ai/verify_release.sh v26-slo-runbook-stability-evidence` passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V260-006 cases as validator executable replay.
