# V161-003 - Bind response redaction to actual guarded-send result

Date: 2026-06-23
Executor: Codex
Milestone: v0.16.1 guarded production mutation hardening
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Distinguish offline synthetic response-redaction fixtures from owner-run
guarded-send HTTP result redaction evidence.

Plain Chinese summary: 这个任务只把 response redaction 的“来源”说清楚。大白话：CI
里用合成订单响应做脱敏验证仍然可以，但它只能算 fixture 证据；只有 guarded-send
artifact 明确记录了 HTTP send、交易所 ack 和 confirmed submission，才可以算 owner-run
mutation closure evidence。

## Scope

Included:

- keep response redaction offline and CI-safe by default;
- add response redaction source fields;
- record guarded-send run id and guarded-send artifact content hash;
- label synthetic fixture redaction as fixture-only;
- mark owner-run closure evidence only when the guarded-send artifact records an
  actual HTTP result acknowledgement and confirmed submission;
- keep raw response, headers, secrets, balances, fills, and unrestricted payload
  persistence disabled.

Not included:

- live network execution;
- new response body persistence;
- Dashboard order controls;
- order retry, cancel, replace, amend, flatten, or remediation;
- broad production trading platform capability expansion.

## Acceptance Criteria

- Synthetic CI redaction remains ready but records:
  - `response_redaction_source=synthetic_fixture`;
  - `redacted_response_derived_from_actual_http_result=false`;
  - `synthetic_fixture_redaction_only=true`;
  - `owner_run_mutation_closure_evidence=false`.
- Actual guarded-send HTTP result redaction records:
  - `response_redaction_source=actual_guarded_send_http_result`;
  - `redacted_response_derived_from_actual_http_result=true`;
  - `synthetic_fixture_redaction_only=false`;
  - `owner_run_mutation_closure_evidence=true`.
- Both paths preserve redaction safety:
  - no raw exchange response;
  - no response headers;
  - no secrets;
  - no balances;
  - no unrestricted payload.
