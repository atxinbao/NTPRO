## 目标

为当前不可变 StrategyVersion 建立独立的 Live Run 候选，使机构用户能够创建候选、显式
执行生产启动前检查并人工停止。候选状态必须如实表达：本任务不会启动真实 Runtime，也不会
连接实时行情或访问订单 endpoint。

## 产品合同

- `POST /api/product/v1/live-run-candidates`：创建一个不可变 Live Run 候选；
- `GET /api/product/v1/live-run-candidates`：恢复当前未停止候选，最多返回一项；
- `GET /api/product/v1/live-run-candidates/{run_id}`：读取候选及其来源绑定；
- `POST /api/product/v1/live-run-candidates/{run_id}/actions`：仅接受 `preflight` 或 `stop`；
- 生命周期仅为 `created -> preflight_ready -> stopped` 或人工 `created -> stopped`，不包含
  `running`；
- preflight 重新读取当前不可变 StrategyVersion，重新验证 Live 独立准入、五项候选运行门禁、
  生产凭证、认证账户连接和交易所 `can_trade=true`；
- 同一工作区通过 `create_new` 进程锁串行化候选创建、陈旧指针替换和生命周期动作，再以
  `create_new` 单活指针最多声明一个未停止候选；所有动作必须由 Institution 角色显式确认；
- request、manifest、preflight 和 stop 工件不可覆盖；每个状态 revision 与工作区 commit
  记录形成双位置 SHA-256 前向链，`state-head.json` 固定当前最高 revision，状态只允许
  单调递增；任一单独工件删除、单链回滚、超出 64 KiB、未知字段、身份漂移、时间倒退和
  任一真实订单尝试标志均 fail closed。

## 独立运行门禁

- `NTPRO_S3_LIVE_RUN_CANDIDATE_CREATE=1`；
- `NTPRO_S3_LIVE_RUN_OWNER_APPROVED=1`；
- `NTPRO_S3_LIVE_RUN_NO_ORDER_SEND=1`；
- `NTPRO_S3_LIVE_RUN_MANUAL_STOP=1`；
- `NTPRO_S3_LIVE_RUN_RISK_APPROVED=1`。

这些门禁不继承 Backtest、Demo 或生产账户只读门禁；同时必须从当前节点配置确认
`risk.kill_switch_enabled=true` 且 `risk.kill_switch_active=false`。缺失任一门禁或风险状态不满足
时，创建和 preflight 返回 422，且不得生成候选工件；`[risk]` 出现未绑定字段也必须拒绝，
内容哈希覆盖严格规范化后的完整风险结构。

## 强制边界

- `runtime_started` 与 `live_runtime_start_allowed` 必须保持 `false`；
- `external_market_data_connection_allowed`、订单 endpoint、submit、cancel、replace、fill
  reconciliation、自动重试、自动补救、自动恢复和交易控件全部保持关闭；
- 页面加载不自动创建、不自动 preflight、不自动检查账户，失败不自动重试；
- 不返回、记录或持久化 API Key、Secret、签名、原始账户响应或订单材料；
- 不把 Sandbox node、Demo Run 或历史 Live 占位 Run 冒充真实 Live Runtime；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`。

## 完成条件

- Rust 覆盖正常状态机、跨进程创建/陈旧指针替换/动作竞争、陈旧锁、越权、身份漂移、风险
  内容漂移、账户不可交易、单链状态删除/回滚、超大工件和工件篡改；
- OpenAPI、生成 TypeScript/Zod SDK、严格客户端、React 和浏览器合同一致；
- 真实 Rust + Chrome 证明默认环境创建返回 422、零工件、页面零自动命令和 405 方法矩阵；
- fmt、Clippy、Product API、Dashboard server、前端全套、风险 inventory、MVP freeze、
  current governance、backend freeze 和 Rust-only gates 通过；
- 独立 Gatekeeper 输出 `REVIEW_APPROVED`，hosted checks 全绿后手动合并，禁止 auto-merge。

## 非目标与后续

本任务不交付真实 Live Runtime 启动或真实订单发送，也不宣称本地文件哈希链能够检测拥有
整个 workspace 写权限的主体同步恢复候选、commit 和 head 的完整旧快照。后续真实 Runtime
和订单准入必须先引入 WORM、远程审计账本或单调 CAS 控制面，再建立独立 critical issue。
