## 目标

让完成独立 Live 准入、账户只读检查、候选 preflight 和外部审计锚定的 Run，由用户显式启动
一个真实 `Environment::Live` 节点。节点只注册 Binance Spot 生产行情客户端，通过 Supervisor
管理进程、心跳和人工停止；不注册执行客户端，订单 mutation 保持结构不可达。

## Runtime 合同

- `ntpro-node` 新增 `production-market-data` 配置模式；
- Runtime 使用 `LiveNodeBuilder` + `BinanceDataClientFactory`，环境固定为 Live、产品固定为 Spot；
- 凭证只从 `NTPRO_BINANCE_LIVE_API_KEY` 和 `NTPRO_BINANCE_LIVE_API_SECRET` 读取，配置和工件
  只记录 env 名称；
- 启动成功必须证明 node running、data client connected、execution client not configured；
- 运行中每秒刷新 status/metrics，Supervisor 继续校验进程身份、Run ownership 和工件身份；
- 人工 stop file、父进程退出、最大运行时间和 OS signal 都走同一优雅断开路径；
- Runtime 不自动重连；连接或心跳失败直接退出并由 Product API 标记 fail closed。

## Product API 状态机

```text
created -> preflight_ready -> starting -> market_data_running -> stopping -> stopped
                                   |                |
                                   +---- failed <---+
```

- `start_market_data` 只能由 `preflight_ready` 进入；
- 启动网络前先外部锚定 `starting`；连接成功后再锚定 `market_data_running`；
- `stop` 对 running 候选先锚定 `stopping`，进程确认退出后锚定 `stopped`；
- 启动失败必须确认进程退出，再锚定 `failed`；锚定不可用时保留最后权威状态并拒绝后续动作；
- `starting`、`stopping`、`stopped` 的持久化中间态必须由 active pointer 和 Supervisor ownership
  驱动恢复；缺失或错配身份时 fail closed，不得静默删除 pointer；
- list/detail 每次从 Supervisor 工件投影 Runtime，状态漂移、缺失或执行连接出现均 fail closed。

## 强制边界

- 不构造或注册 execution client；
- order endpoint、submit、cancel、replace、fill reconciliation 均为 `false`；
- automatic retry、remediation、recovery 均为 `false`；
- 页面加载不自动启动、停止或重连；
- 外部审计锚点不授予交易权限；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`，不关闭 S3 milestone。

## 完成条件

- Rust 覆盖 Runtime start/stop、凭证缺失、数据连接失败、执行客户端不可达和状态工件；
- Product API 覆盖正常生命周期、非法转换、并发动作、启动清理、进程/工件漂移和锚点失败；
- OpenAPI、生成 SDK、严格 TypeScript 客户端、React、Vitest、Playwright 和真实 Axum 浏览器一致；
- fmt、Clippy、Rust-only、风险 inventory、MVP/backend freeze、current governance 通过；
- 独立 Gatekeeper 输出 `REVIEW_APPROVED`，hosted checks 全绿后手动合并，禁止 auto-merge。

## 非目标

不启动策略订单流，不接入 execution adapter，不访问订单 endpoint，不进行真实订单提交、撤改、
成交对账、自动重试、自动修复或自动恢复；不声明 S3 已完成。
