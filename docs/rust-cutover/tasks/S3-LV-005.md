## 目标

在 S3-LV-004 本地状态链之外增加工作区外的权威单调锚点。每个 Live Run revision 必须完成
namespace 级远端 compare-and-append，并保存经过 Ed25519 验证的严格回执；每次 list、detail、
preflight 和 stop 都必须查询工作区远端 latest。完整本地旧快照恢复、远端回退、签名错误和
远端不可用全部 fail closed。

## 控制面合同

- `POST <endpoint>/anchors/<namespace>/workspace/compare-and-append`：提交严格 workspace
  revision、run revision、state SHA-256、commit SHA-256、前一全局回执 SHA-256、观察时间和
  幂等键；
- `GET <endpoint>/anchors/<namespace>/workspace/latest`：返回该 namespace 当前工作区权威回执；
- 回执绑定 namespace、run、run revision、workspace revision、state、commit、前一全局回执、
  远端时间、key id 和 receipt id；
- 客户端使用固定 Ed25519 公钥验证回执，不信任响应传入的公钥；
- 生产 endpoint 只允许 HTTPS；HTTP 仅存在于编译期测试的 loopback mock；
- 响应超过 64 KiB、非 JSON、未知字段、非 2xx、超时、签名/key/身份漂移、revision 跳跃或
  时间倒退全部拒绝；409 映射为不可覆盖的 revision 冲突。

## 部署配置

以下五项必须同时存在，任何部分配置均视为无效：

```text
NTPRO_S3_AUDIT_ANCHOR_ENDPOINT
NTPRO_S3_AUDIT_ANCHOR_NAMESPACE
NTPRO_S3_AUDIT_ANCHOR_KEY_ID
NTPRO_S3_AUDIT_ANCHOR_PUBLIC_KEY_BASE64
NTPRO_S3_AUDIT_ANCHOR_TOKEN
```

token 不得进入响应、日志、错误字段、本地回执或来源引用。NTPRO 只交付客户端合同，不在本地
文件或普通数据库中伪造生产 WORM 服务。

## 持久化合同

- `anchor-receipt-<revision>.json` 是不可覆盖的本地签名回执副本；
- `artifacts/live-run-audit-anchor-head.json` 是本地已发布的工作区全局 head；
- `state-head.json` v2 同时绑定 state、workspace commit 和 canonical receipt SHA-256；
- 所有候选的历史回执必须形成从 workspace revision 0 开始的连续全局链，保持前一回执
  SHA-256 和非递减远端时间；
- 远端 latest 必须与本地工作区 head 及全局最高回执完整一致；任一差异阻断读取和后续动作；
- 外部 append 成功但本地持久化失败时不得回退远端；候选保持 fail closed，由运维按远端
  回执恢复或隔离本地工作区。

## 强制边界

- `runtime_started=false`，外部市场数据连接、订单 endpoint、submit、cancel、replace、fill
  reconciliation、自动 retry/remediation/recovery 和交易控件继续关闭；
- `audit_anchor.trading_authority_granted=false`，锚点通过只证明状态证据，不授予交易权限；
- 页面加载不自动创建、preflight 或 stop，不自动重试锚点失败；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`。

## 完成条件

- Rust 覆盖正常签名、幂等、单调追加、配置错误、签名漂移、HTTP 合同、远端不可用、完整工作区
  快照恢复和本地工件篡改；
- OpenAPI、生成 SDK、严格客户端、React、Vitest、Playwright 和真实 Rust 浏览器一致；
- fmt、Clippy、Product API、Dashboard server、风险 inventory、MVP/backend freeze、current
  governance 和 Rust-only gates 通过；
- 独立 Gatekeeper 输出 `REVIEW_APPROVED`，hosted checks 全绿后手动合并，禁止 auto-merge。
