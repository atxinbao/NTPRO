# V03-008 - Runtime modules diagnostic panel

Milestone: v0.3 Dashboard MVP
Priority: P1
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Implement the Runtime Modules diagnostic panel.

Plain language: this panel helps diagnose which internal module appears healthy,
unknown, unsupported, stale, or failed.

## Dependencies

- `V03-007`

## Scope

Show at least these modules:

- `LiveNode`;
- `NautilusKernel`;
- `DataEngine`;
- `ExecutionEngine`;
- `RiskEngine`;
- `Portfolio`;
- `Cache`;
- `MessageBus`;
- `Logging`;
- `Metrics writer`;
- `Supervisor`.

For each module, show:

- status;
- health;
- last seen timestamp;
- redacted last error;
- evidence source.

Unavailable module details must be recorded in `gaps`.

## Non-goals

- Do not replace the Overview, Data Sources, Execution, or Risk panels with this
  diagnostic panel.
- Do not inspect mutable runtime objects directly.
- Do not expose engine internals, actor registries, cache contents, message-bus
  routing tables, raw orders, raw venue payloads, or secrets.
- Do not mark unknown module state as healthy.

## Implementation guidance

This panel is a diagnostic view. It may rely on derived artifact evidence from
`NodeStatus`, `NodeMetrics`, and log paths. Where no stable artifact exists, show
an explicit gap with the owner task or follow-up note.

## Verification criteria

- Runtime Modules panel renders all required module rows.
- Unknown, unsupported, stale, and not configured module fields are visible.
- `gaps` includes unavailable module details.
- Tests cover module status derivation from available and missing artifacts.
- Browser or Playwright verifies the panel is readable without overlap.
