# V061-003 - Enforce single source of truth for workflow run_id

Milestone: v0.6.1 offline hardening
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Make the Binance testnet workflow use one effective `run_id` across CLI output,
manifest, summary, config artifact, events, and Dashboard read-model output.

## Scope

- Resolve the effective testnet workflow run id as:
  - CLI `--run-id` when supplied;
  - otherwise `config.run.id`.
- Use that effective run id for all primary artifact identity fields.
- Preserve the configured `run.id` as audit-only metadata when it differs from
  the CLI value.
- Add regression coverage for CLI override, config fallback, events, config
  artifact identity, and Dashboard manifest display.

## Non-goals

- Do not connect to Binance testnet.
- Do not submit orders.
- Do not read or persist secret values.
- Do not change Dashboard controls.
- Do not change trading semantics.

## Required Evidence

- CLI dry-run with `--run-id custom-run-id` writes one effective run id across
  manifest, summary, testnet config artifact, and events.
- Dashboard snapshot tests prove the displayed run id comes from the manifest.
- `cargo test -p nautilus-cli workflow --lib` passes.
- `cargo test -p nautilus-cli dashboard --lib` passes.
- `scripts/ai/verify_fast.sh` passes.
- `git diff --check` passes.
- Migration note exists for the workflow run id contract.
