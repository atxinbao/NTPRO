## Goal

Define the v0.25.0 monitoring / observability contract for read-only production
runtime evidence. The contract fixes when monitoring may display `healthy`, when
it must degrade, and when it must fail closed because the artifact is no longer
monitoring-only evidence.

Plain Chinese summary: 本任务定义 v0.25.0 监控和 observability 的只读证据合同。
只有 source provenance、freshness、redaction、component health 和 no-side-effect
边界全部完整时，监控才允许显示 healthy；缺失 provenance/freshness/redaction 或 stale/
partial 状态必须 degraded 或 fail closed。它不新增真实交易操作、自动 remediation、
adapter send、live exchange request，也不把监控状态当成交易授权。

## Scope

Included:

- document runtime health, component health, freshness, source provenance,
  redaction, stale, degraded, and fail-closed semantics;
- define the monitoring truth boundary against exchange truth and adapter
  runtime truth;
- add golden trace cases for healthy, missing provenance, stale/partial,
  redaction breach, and side-effect/truth-boundary violations;
- add a verifier that recomputes the effective monitoring status from the trace;
- record the cases in the release replay scope as validator executable replay.
- harden the already-merged V250 intake dependency proof so v0.24.1 tag must be
  an ancestor of current `origin/main` after v25 work starts, matching the
  established V24 intake gate model.

Not included:

- production submit, cancel, replace, amend, flatten, retry, or order ticket;
- automatic remediation;
- adapter send or live exchange requests;
- Dashboard trading controls;
- product-grade trading terminal readiness claims.

## Acceptance Criteria

- Missing runtime/component source provenance cannot display healthy.
- Missing, stale, or partial freshness cannot display healthy.
- Missing or breached redaction cannot display healthy; redaction breach fails
  closed.
- Monitoring artifacts must declare no operation side effects.
- Monitoring artifacts must not claim exchange truth or adapter runtime truth.
- `scripts/ai/verify_release.sh v25-monitoring-observability-contract` passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records all V250
  monitoring contract cases as validator executable replay.
