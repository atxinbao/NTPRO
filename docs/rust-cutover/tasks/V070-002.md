# V070-002 - Harden env-only credential policy for optional online mode

Milestone: v0.7.0 deferred queue
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Harden the Binance testnet credential policy before any optional online mode can
read credentials. Credential values must remain environment-only and must never
be written to artifacts, stdout, logs, docs, or PR body.

## Scope

- Keep credential values out of checked-in config files.
- Record only env var names and present/absent booleans in artifacts.
- Split future probe semantics:
  - public read-only probe: does not require credentials;
  - authenticated read-only probe: requires credentials and is manual-online-only.
- Preserve the existing offline dry-run and V070 fail-closed network guard.
- Add regression tests for redaction and manual-only authenticated probe status.

## Non-goals

- Do not implement HTTP networking.
- Do not implement WebSocket networking.
- Do not submit, cancel, replace, or amend orders.
- Do not read or store credential values beyond environment presence checks.
- Do not turn Dashboard into a credential input or probe launcher.
- Do not create a tag or GitHub Release.

## Acceptance

- Credential policy artifact records env var names and presence booleans only.
- `values_recorded=false`, `api_key_value_recorded=false`,
  `api_secret_value_recorded=false`, and `secrets_redacted=true`.
- Public read-only probe status is explicit and does not require credentials.
- Authenticated read-only probe status is manual-only and blocked unless both
  credential env vars are present.
- Existing v0.6/v0.7 offline behavior remains offline and does not open sockets.
