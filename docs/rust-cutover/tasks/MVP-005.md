## 目标

在 MVP-003 身份合同和 MVP-004 四轴状态合同之上，提供机构工作台与控制中心共同
消费的版本化只读 HTTP 投影。两个门户读取同一组身份、状态和业务摘要，不各自建立
第二套状态源。

## 接口

```text
GET /api/mvp/v1/status
schema = ntpro.mvp_shared_status_api.response.v1
contract = ntpro.mvp_shared_status_api.v1
```

响应包含：

- 策略、版本、回测、Supervisor 节点、策略实例、账户、Venue 和环境身份；
- 研究、运行、技术健康和交易就绪四个独立状态轴；
- 账户、仓位、订单、成交、风险和生命周期的受控业务摘要；
- 来源、时效、可用性、错误、缺失、降级和阻断原因；
- 显式只读能力边界。

## Fail-closed 规则

- 身份或状态合同缺失、非法、schema 不匹配时拒绝建立共享事实；
- contract ID、配置重建身份、Supervisor 节点或运行来源路径不一致时拒绝投影；
- registry 和节点 artifact root 必须位于当前 MVP workspace 的固定路径；
- status、metrics 和 Unified Read Model 子工件不得通过改写路径或 symlink 逃逸节点
  artifact root；
- 顶层或单轴时间戳陈旧时重新标记为 stale，旧 healthy 不得继续生效；
- Unified Read Model 顶层及 account/positions 组件账户或 Venue 与 MVP 身份不一致时
  不投影业务字段；
- positions 必须携带匹配的 instrument Venue；orders/fills 若携带 instrument Venue，
  也必须与 MVP 身份一致；
- Unified Read Model 顶层及六个业务组件的时效必须按原始时间戳重新计算；
- Unified Read Model 缺失时业务摘要为 missing，交易就绪继续 blocked；
- HTTP 200 只表示查询成功，不表示研究通过、技术健康或交易就绪；
- POST、PUT、PATCH 和 DELETE 由路由返回 405。

## 非目标

- 前端页面、多节点、多账户或远程部署；
- 原始 Event Store、内部完整 Dashboard snapshot 或原始 Venue payload；
- submit、mutation、adapter send、live exchange、retry、remediation、recovery
  或交易控件；
- 修改 v0.32.0 冻结发布文件。
