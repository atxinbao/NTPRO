# V061-007 - Extract shared workflow artifact contract for writer and reader

Milestone: v0.6.1 offline hardening
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Extract the local workflow artifact DTOs and schema constants used by the CLI
workflow writer and Dashboard reader into one shared crate-internal contract.
The goal is to stop the writer and reader from drifting while preserving the
existing v0.6.1 offline artifact JSON format.

## Scope

- Add a shared workflow artifact contract module under `crates/cli/src/`.
- Move workflow manifest, summary, event, boundary, and v0.6 testnet artifact
  DTO definitions into the shared module.
- Keep writer-specific construction logic in `workflow.rs`.
- Make Dashboard read `manifest.json` through the shared manifest type.
- Add compatibility coverage proving CLI-generated artifacts deserialize through
  the shared contract types.

## Non-goals

- Do not add v0.7 real-network fields.
- Do not connect to Binance testnet.
- Do not submit orders.
- Do not change artifact filenames or JSON field names.
- Do not change Dashboard into an active workflow/probe runner.

## Required Evidence

- `cargo test -p nautilus-cli workflow --lib`
- `cargo test -p nautilus-cli dashboard --lib`
- `cargo clippy -p nautilus-cli --lib --tests -- -D warnings`
- `scripts/ai/verify_v06_binance_testnet_dry_run.sh`
- `scripts/ai/verify_fast.sh`
- `git diff --check`

## Acceptance

- CLI writer and Dashboard reader share one set of workflow artifact DTOs.
- CLI-generated `manifest.json`, `summary.json`, `events.jsonl`,
  `testnet/*.json`, and order/reconciliation artifacts deserialize through the
  shared contract types.
- v0.6.1 remains offline-only.
- Existing Dashboard workflow artifact health behavior is preserved.
