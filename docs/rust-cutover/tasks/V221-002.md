## Goal

Make the Trader Terminal Workbench operation boundary explicit at runtime:
operation, submit, ticket, dashboard control, mutation, repair, and live-terminal
claim fields must be present and set to `false`.

Plain Chinese summary: 本任务把 v0.22 Workbench 的只读操作边界从“缺失时显示
unknown”升级为 runtime required false。`new_submit_capability`、
`dashboard_submit_controls_enabled`、`trader_terminal_order_ticket_enabled`、
`manual_operation_submit_allowed` 等字段缺失或为 `true` 时会 fail closed；显式
`false` 才保持 healthy/ready。它不启用 submit/cancel/replace/amend/flatten。

## Scope

Included:

- require explicit `false` for v22 operation/control boundary fields;
- add runtime status coverage for `new_submit_capability`;
- remove optional-false parser behavior for the v22 Workbench boundary;
- add focused tests for explicit false, missing field, and true field cases;
- keep degraded missing-artifact fallback disabled.

Not included:

- enabling any live order submission or mutation action;
- changing adapter behavior;
- adding v0.23.0 multi-node capability;
- dashboard cosmetic refactor beyond rendering the new boundary value.

## Acceptance Criteria

- Missing required boundary field returns fail-closed runtime health/readiness.
- Explicit `false` boundary fields remain accepted.
- `true` boundary fields remain hard failures.
- `new_submit_capability` is represented in runtime status and dashboard
  read-only boundary rendering.
- Local focused and broad CLI tests pass.
