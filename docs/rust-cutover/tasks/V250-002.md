## Goal

Define the v0.25.0 alert taxonomy and routing evidence contract so monitoring
can express alert severity, category, source, scope, dedupe key, freshness,
acknowledgement requirement, provenance, and routing target as read-only
evidence.

Plain Chinese summary: 本任务定义 v0.25.0 的告警 taxonomy 和 routing evidence。
告警可以说明类型、严重性、来源、scope、dedupe key、freshness、是否需要人工确认、
provenance 和只读处理入口；但 routing target 只能是证据/人工处理入口，不会触发
submit/cancel/retry/replace/amend/flatten、adapter send、live exchange request 或
automatic remediation。

## Dependencies

- Depends on V250-001 monitoring contract.
- Hard-blocked by v0.24.1 issue closeout and release evidence through
  `scripts/ai/verify_release.sh v25-intake-gate`.

## Scope

Included:

- alert severity, category, source, scope, dedupe key, freshness, ack
  requirement, source provenance, redaction, and routing target contract;
- alert categories for stale data, missing provenance, risk fail-closed,
  order-control preview blocked, and release/gate drift;
- golden trace and verifier coverage for valid routing, missing required
  fields, redaction/secret breach, and automatic-action boundary violations;
- release replay scope entries as validator executable replay.

Not included:

- external paging service integration;
- automatic remediation;
- production submit/cancel/retry/replace/amend/flatten;
- order lifecycle changes;
- adapter send or live exchange requests.

## Acceptance Criteria

- Missing severity, category, source, source provenance, scope, dedupe key, or
  routing target fails closed.
- Alerts must not contain secret, raw credential, signed payload, signature, raw
  order id, or unredacted trading-sensitive field values.
- Automatic submit/cancel/retry/replace/amend/flatten and remediation flags are
  always false.
- Routing target is read-only evidence or manual review only.
