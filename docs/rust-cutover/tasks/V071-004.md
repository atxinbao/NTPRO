# V071-004 Validate Binance ServerTime Response Shape

Date: 2026-06-15
Executor: Codex
Owner role: Verification & Release Gatekeeper
Review role: Control & Scope Agent
Risk level: medium
Status: PR_REQUIRED

## Goal

Tighten the v0.7 Binance testnet HTTP probe success condition so HTTP 2xx is
not enough. A connectivity proof requires a validated Binance `/api/v3/time`
JSON response with a positive `serverTime` value.

## Scope

- Keep `response_shape=binance_server_time_v1` for the expected Binance time
  endpoint response.
- Keep `response_shape_validated=true` only when `serverTime` exists and is
  positive.
- Keep invalid shape responses classified as `response_shape_invalid`.
- Ensure invalid shape responses do not set `testnet_connection=true`.
- Do not store or print the raw response body.
- Record evidence under `docs/rust-cutover/evidence/V071-004.md`.

## Non-Goals

- No authenticated account access.
- No account mutation.
- No order submission.
- No real funds.
- No production Binance connectivity.
- No production trading claim.
- No v0.8 capability work.
- No tag creation.
- No GitHub Release publication.

## Acceptance

- Valid local HTTP 200 response with positive `serverTime` is treated as
  validated connectivity proof.
- HTTP 200 response with invalid `serverTime` shape is treated as failure.
- Failure artifact semantics keep `response_shape_validated=false` and
  `testnet_connection=false`.
- Raw response bodies are not persisted into diagnostics.
- v0.7 manual online gate still requires `response_shape_validated=true`.
