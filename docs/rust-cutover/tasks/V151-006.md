# V151-006 - Define execution dry-run adapter boundary contract

Date: 2026-06-23
Executor: Codex
Milestone: v0.15.1 execution dry-run hardening
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Make the v0.15 production live-alpha execution dry-run boundary explicit:

```text
StrategyIntent -> RiskDecision -> ExecutionCommand -> DryRunExecutionAdapter
```

The task moves the existing proof from field-only isolation toward an explicit
artifact contract. The proof must show that strategy intent can create only a
local dry-run execution command and that `ProductionExecutionAdapter` remains
outside the route.

Plain Chinese summary: 这项不是做真实下单 adapter，而是把“策略意图经过风控后，
只能生成本地 dry-run 执行命令，最后只写 dry-run adapter 证据”的边界说清楚、
写进 artifact、并用脚本防止误接到生产 adapter。

## Scope

Included:

- define the release-facing execution dry-run adapter boundary contract;
- add explicit boundary fields to the v0.15 execution dry-run artifact;
- prove ready and blocked paths with unit tests and script checks;
- keep `ProductionExecutionAdapter` route and instantiation disabled.

Not included:

- production execution adapter implementation;
- production order submission;
- production order mutation;
- production HTTP request execution;
- real exchange state;
- real funds;
- Dashboard order controls;
- v0.16 production execution behavior.

## Acceptance Criteria

- Release contract documents the boundary chain:
  `StrategyIntent -> RiskDecision -> ExecutionCommand -> DryRunExecutionAdapter`.
- Ready artifact records:
  - `execution_boundary_contract_ready=true`;
  - `execution_command_created=true`;
  - `execution_command_route=dry_run_adapter_only`;
  - `execution_command_destination=ntpro_local_artifact_dry_run_execution_adapter`;
  - `production_adapter_route_allowed=false`;
  - `production_adapter_instantiation_allowed=false`.
- Blocked artifact records:
  - `execution_boundary_contract_ready=false`;
  - `execution_command_created=false`;
  - `execution_command_route=blocked_before_execution_command`;
  - `execution_command_destination=none`;
  - production adapter route and instantiation remain false.
- Existing no-production-mutation evidence remains true:
  - `network_attempted=false`;
  - `production_orders_submitted=0`;
  - `production_order_mutations_attempted=0`;
  - `production_adapter_called=false`;
  - `dashboard_order_controls_enabled=false`.
