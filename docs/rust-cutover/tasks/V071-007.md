# V071-007 Clarify Production/Testnet/Network Connection Fields

Date: 2026-06-15
Executor: Codex
Owner role: Verification & Release Gatekeeper
Review role: Control & Scope Agent
Risk level: medium
Status: PR_REQUIRED

## Goal

Make Dashboard and release evidence distinguish three different concepts:

- production venue connectivity;
- public Binance testnet read-only connectivity;
- external network attempt.

## Scope

- Keep legacy `external_venue_connection`, `testnet_connection`, and
  `network_attempted` fields readable for compatibility.
- Prefer explicit fields in Dashboard overview and workflow rows:
  - `production_venue_connection`;
  - `testnet_public_network_connection`;
  - `external_network_attempted`.
- Derive Dashboard read-only testnet status from probe artifacts when a legacy
  or partial manifest summary has not set the explicit fields.
- Update release boundary docs to describe the Dashboard display contract.

## Non-Goals

- No CLI flag change.
- No artifact schema version change.
- No authenticated account access.
- No account mutation.
- No order submission.
- No real funds.
- No production Binance connectivity.
- No production trading claim.
- No v0.8 capability work.
- No tag creation.
- No GitHub Release publication.

## Acceptance

- Dashboard overview includes explicit production/testnet/network fields.
- Dashboard workflow status surfaces a successful read-only probe as
  `testnet_public_network_connection=true` and
  `external_network_attempted=true` without marking production connectivity.
- Release boundary documentation says Dashboard must use the explicit fields as
  primary labels.
- Existing compatibility fields remain serialized/readable.
