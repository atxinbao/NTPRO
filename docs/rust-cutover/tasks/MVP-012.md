## 目标

在隔离工作区对单 Supervisor + 单 sandbox 节点注入真实进程和工件故障，证明四轴状态、
共享 API 和控制中心不会把 HTTP 成功或进程存活解释为技术健康；可恢复故障只允许人工
显式操作或可信工件恢复，禁止自动 retry、restart、remediation 和 recovery。

## 故障矩阵

- 外部 SIGTERM：节点必须收敛为 stopped，operator 通过既有 start 恢复；
- SIGKILL：Supervisor 必须标记 stale，交易就绪保持 blocked，观察窗口内不得自动生成
  新 PID；控制中心 stop 不得误报成功，显式 `nautilus supervisor start` 后才恢复；
- status artifact：覆盖 missing 和 invalid JSON；
- metrics artifact：覆盖 missing 和 invalid JSON；
- 代际：覆盖 stale timestamp 和 status/metrics generation mismatch；
- identity contract：覆盖 missing、invalid JSON 和 config identity mismatch。

所有工件故障在节点 SIGSTOP 期间注入，避免正常 heartbeat 覆盖测试输入；恢复原始可信
工件并 SIGCONT 后，必须重新达到 running + healthy + fresh。每个状态均验证 required-false
边界和 `trading_readiness=blocked`。
