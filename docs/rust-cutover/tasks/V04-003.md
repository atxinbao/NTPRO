# V04-003 - EMA / RSI strategy contracts

Milestone: v0.4.0 Binance Sandbox Product Foundation
Priority: P0
Owner role: Trading Runtime Agent
Review role: Control & Scope Agent
Risk: medium

## Goal

Define the first built-in strategy contracts for v0.4.

Plain language: lock what EMA and RSI mean as product strategies before wiring
them into replay, mock execution, and dashboard state.

## Dependencies

- `V04-002`

## Scope

- Define EMA strategy inputs, outputs, and expected evidence.
- Define RSI strategy inputs, outputs, and expected evidence.
- Record what each strategy smoke must prove and what it does not prove.
- Keep the contract deterministic and sandbox-friendly.

## Non-goals

- Do not claim arbitrary user strategy loading.
- Do not claim production alpha or strategy profitability.
- Do not broaden strategy scope beyond the built-in v0.4 examples.

## Related files

- `crates/trading/` (REFERENCE): strategy runtime contracts.
- `docs/tutorials/` (REFERENCE): existing strategy documentation patterns.
- `docs/rust-cutover/specs/v0_4_strategy_contracts.md` (CREATE): strategy
  contract record.
- `docs/rust-cutover/evidence/V04-003.md` (CREATE): task evidence.

## Implementation guidance

Start from the product claim, not from internal indicator APIs. The contract
must be stable enough for config DTO, smokes, and dashboard panels to reuse.

## Verification criteria

- EMA and RSI contracts are documented in one place.
- Inputs, outputs, and evidence expectations are explicit.
- The contracts keep v0.4 sandbox-only and deterministic.
