# PAR-002 L2 Trailing Stop Trade-Tick Maintenance

Date: 2026-07-29
Executor: Codex
GitHub issue: #1170
Risk: high
Classification: separately-scoped-runtime-maintenance
Status: REVIEW_REQUIRED

## Goal

Restore the ignored L2 trailing-stop regression when
`trade_execution=false`. A trade tick must still advance time-based and
trailing-order maintenance, while the unchanged L2 order book remains the
only source for order matching.

中文摘要：关闭 trade execution 的含义是“不把逐笔成交价当成撮合盘口”，不是
“跳过撮合引擎维护”。本任务让逐笔成交继续更新 last price 并推进 trailing
更新、触发、GTD 和到期处理，但不会让普通限价单仅因逐笔成交价越过而成交。

## Scope

- continue matching-engine maintenance after a valid trade tick when
  `trade_execution=false`;
- preserve L2 order-book bid/ask as the matching source;
- restore `test_trailing_stop_market_updated_then_triggered` to the default
  suite with explicit disabled trade execution and cache event application;
- keep LastPrice submission, trigger-price modification, and explicit trailing
  activation bound to `core.last` when L2 trade execution is disabled;
- preserve stop versus touched comparison direction for every trigger type,
  including trailing-stop modifications;
- add a negative regression for an ordinary limit order crossed only by the
  trade price;
- add executable golden-trace coverage for the trailing update and fill;
- align the public L2 `trade_execution=false` backtest contract;
- update both ignored-test registers until PAR-011 unifies them.

## Non-Goals

- no change to the trailing offset formula;
- no risk-engine, adapter, CLI, or public API change;
- no production order submission or mutation authorization;
- no edit to frozen `docs/rust-cutover/release/v0_32_0_*` files.

## Behavior Contract

For a valid L2 trade tick with `trade_execution=false`:

1. `core.last` advances to the trade price;
2. L2 book bid/ask and trade-size execution state remain unchanged;
3. `iterate` evaluates orders against the existing L2 book, then performs GTD,
   trailing recompute, and instrument-expiration maintenance;
4. a LastPrice trailing stop improves and triggers from `core.last`, never from
   the unchanged L2 bid/ask;
5. LastPrice stop submission, modification, and trailing activation use the
   same trigger source and cannot be rejected or activated by L2 quotes alone;
6. trade, quote, depth, and order-book driven iterations preserve that trigger
   source distinction;
7. stop and touched order types retain their opposite comparison directions
   regardless of whether the trigger source is book or last;
8. every order side in one maintenance iteration uses the same captured market
   snapshot, so an earlier fill cannot replace the LastPrice trigger source;
9. BidAsk trailing maintenance requires only the quote side used by the order
   direction, and missing required market data skips the update without panic;
10. a triggered order fills from L2 book liquidity;
11. a normal limit order cannot fill solely because the trade price crosses it.

## Acceptance

- the previously ignored LastPrice trailing stop updates `1510 -> 1485`, does
  not trigger at last `1484`, then triggers at last `1490` and fills at L2 ask
  `1500`;
- the complete normalized event stream matches Accepted, Updated, and Filled
  payloads and timestamps from the golden trace;
- an L2 BUY limit at `95` does not fill when a trade prints `90` while the ask
  remains `100`;
- a LastPrice BUY stop rests and can be modified while last is below its
  trigger even when the L2 ask has crossed it, then fills from that ask after
  last crosses;
- an unrelated L2 book update cannot trigger that stop while last remains
  below its trigger;
- a LastPrice trailing stop with an explicit activation price remains inactive
  until last reaches that price, regardless of the current L2 ask;
- a BUY BidAsk market-if-touched order remains resting while ask is above its
  touch price, even after an unrelated trade tick;
- a BUY LastPrice trailing stop accepts a trigger above last and rejects a
  trigger below last during modification;
- a valid ask-only L2 book updates a BUY BidAsk trailing stop without requiring
  a bid or panicking;
- a BUY stop-limit fill cannot mutate the captured trade last and incorrectly
  trigger an opposite-side SELL LastPrice stop in the same iteration;
- standard and high-precision execution tests, Clippy, golden trace, risk
  inventory, and current governance pass;
- independent review and hosted checks approve the high-risk change.
