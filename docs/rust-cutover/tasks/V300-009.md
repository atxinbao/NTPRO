## Goal

Define audit retention and evidence export readiness for the backend go-live
candidate foundation.

Plain Chinese summary: 本任务为 v0.30.0 建立 audit retention 和 evidence export
readiness。它要求 approval、deployment、canary、rollback、config、telemetry、
incident 和 go/no-go decision 都能通过 immutable audit trail 重建；导出只读、
可 readback，不会触发 production mutation、adapter send、live exchange request
或 trading controls。

## Scope

Included:

- Define required audit records for approval, deployment, canary, rollback,
  config, telemetry, incidents, and go/no-go decisions.
- Define read-only evidence export bundles with deterministic readback.
- Define retention, redaction, lineage, and unverifiable-reference fail-closed
  boundaries.
- Add deterministic JSON and executable verifier.

Not included:

- production storage mutation;
- evidence export mutation or runtime side effects;
- automatic remediation;
- retry scheduler;
- adapter send or live exchange request;
- production order submit or mutation;
- Dashboard/Admin/Trader Terminal operation controls or trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Every go-live candidate decision has a reconstructable audit trail.
- Evidence export remains read-only and cannot trigger operational actions.
- Missing lineage, redaction failures, missing audit records, retention-boundary
  failures, export readback mismatches, and unverifiable audit references fail
  closed.
