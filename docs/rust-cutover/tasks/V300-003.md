## Goal

Define runtime enablement boundaries and controlled feature flag governance for
the v0.30.0 backend go-live candidate foundation.

Plain Chinese summary: 本任务建立 v0.30.0 runtime enablement 和 controlled
feature flags 的边界。所有 runtime switches 默认禁用；任何从 preview 到 enabled 的
变化都必须有后续 scoped issue、owner/operator approval、audit evidence、risk gate、
telemetry SLO gate、rollback gate 和 release gate。本任务不开放 submit、订单
mutation、adapter send、live exchange request、retry scheduler、automatic
remediation 或 Dashboard/Admin/Trader Terminal 交易控件。

## Dependency

- Depends on `V300-001` backend go-live candidate boundary contract.
- Depends on `V300-002` production deployment plan and environment readiness.
- Hard-blocked by published v0.29.1 release evidence and closed v0.29.1
  milestone.

## Scope

Included:

- Inventory candidate runtime switches and forbidden runtime flags.
- Prove every switch is default-disabled and current runtime effect is closed.
- Require explicit approval, audit evidence, and a scoped enablement issue
  before any switch can move from preview to enabled.
- Reject stale flag provenance, unsupported combinations, and trading-related
  flags.
- Add deterministic JSON and executable verifier.

Not included:

- production runtime enablement;
- default production submit;
- production order mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal operation controls or trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Runtime enablement artifacts cannot open trading controls by default.
- Missing approval, missing audit evidence, stale flag provenance, or missing
  scoped enablement issue fails closed.
- Unsupported flag combinations fail closed, especially submit/mutation with
  adapter/live-exchange paths.
- Forbidden trading/control flags fail closed if enabled.
