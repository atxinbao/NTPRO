# V170-006 - Add restart recovery evidence

Date: 2026-06-24
Executor: Codex
Milestone: v0.17.0 production reconciliation and orphan recovery
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Prove process restart can resume the existing local ledger/readback path without
duplicate submit, retry, cancel, or remediation.

Plain Chinese summary: 这个任务证明“重启后不会乱来”。大白话：系统重启后，只能读取已经
存在的本地账本，继续做只读回查、对账分类和孤儿单风险检测；不能重新发单、不能重试、
不能自动撤单，风险没解决前继续阻断新单。

## Scope

Included:

- add `scripts/ai/verify_v17_restart_recovery.sh`;
- generate a ready local ledger;
- simulate process restart by reusing the ledger from disk;
- resume exchange readback mapper from the recovered ledger;
- resume reconciliation classifier;
- resume orphan order detector;
- prove unresolved state sets manual review and new-order blocking.

Not included:

- new CLI command;
- actual process supervisor restart;
- network readback execution;
- duplicate guarded send;
- automatic cancel, retry, replace, amend, correction, flatten, or remediation;
- Dashboard order/cancel controls;
- release tag creation.

## Acceptance Criteria

- Recovered ledger has
  `schema_version=ntpro.v170_production_mutation_local_order_ledger.v1`.
- Recovered ledger has `restart_readable=true`.
- Recovered ledger preserves the original `order_lineage_id`.
- Post-restart mapper reads the recovered ledger path.
- Post-restart classifier completes from mapper evidence.
- Post-restart orphan detector halts risk and blocks new orders for unresolved
  open-order state.
- `duplicate_submit_attempted=false`.
- `retry_attempted=false`.
- `cancel_attempted=false`.
- `remediation_attempted=false`.
- `dashboard_order_controls_enabled=false`.
