## Goal

Define the v0.25.0 runbook and audit evidence model so manual observations,
acknowledgements, escalations, rollback recommendations, and decision reasons
are traceable without granting any real operation capability.

Plain Chinese summary: 本任务定义 v0.25.0 的 runbook/audit evidence 模型。每个
runbook step 必须有 runbook id、version、owner、versioned source、input evidence、
decision output、audit trace、provenance、freshness 和 redaction；但它只提供只读/
人工证据，不执行 shell/runbook 自动化，不新增自动 cancel/retry/remediation，也不授予
真实交易操作权限。

## Dependencies

- Depends on V250-003 incident lifecycle and operator acknowledgement.

  `scripts/ai/verify_release.sh v25-intake-gate`.

## Scope

Included:

- runbook id, version, step id/name, owner, versioned source, input evidence,
  decision output, audit trace, source provenance, lineage, freshness, and
  redaction contract;
- manual observation, manual acknowledgement, manual escalation, and manual
  rollback recommendation evidence;
- fail-closed coverage for stale runbook, missing version, missing audit trace,
  unapproved action, redaction breach, and automatic execution boundary;
- release replay scope entries as validator executable replay.

Not included:

- shell or runbook automation execution;
- automatic cancel, retry, remediation, strategy stop, submit, replace, amend,
  or flatten;
- permission system extension;
- adapter send or live exchange requests.

## Acceptance Criteria

- Every runbook step must have versioned source and audit trace evidence.
- Every runbook step must have owner, input evidence, decision output, source
  provenance, lineage, freshness, and redaction.
- Stale runbook evidence fails closed.
- Missing runbook version or audit trace fails closed.
- Unapproved actions can only appear as blocked recommendations; otherwise
  they fail closed.
- Evidence must not contain secret, raw credential, signed payload, signature,
  raw order id, or unredacted trading-sensitive field values.
- Runbook/audit evidence cannot directly trigger order mutation, shell
  execution, strategy stop, adapter send, live exchange request, permission
  system extension, or automatic remediation.
