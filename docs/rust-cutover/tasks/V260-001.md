## Goal

Define the v0.26.0 product hardening boundary contract. The contract declares
what v0.26.0 may harden as product foundation work and makes the forbidden
trading capability boundary explicit, required, and fail-closed.

Plain Chinese summary: 本任务定义 v0.26.0 的 product hardening 边界合同。v0.26.0
只允许做 permissions、operation audit、deployment provenance、upgrade/rollback、
SLO/runbook productization、long-run stability 和 read-only admin Dashboard
foundation；不新增真实下单、订单变更、adapter send、live exchange request、
automatic remediation、Dashboard trading controls，也不声明 product-grade live
trading terminal 已完成。

## Dependency

- Depends on `V260-000` intake gate and its `start_gate_status = satisfied`
  proof.
- Hard-blocked by v0.25.1 issue closeout and release publication evidence.
- Does not inherit any submit, mutation, adapter-send, remediation, or
  Dashboard trading-control capability from v0.25.1.

## Scope

Included:

- Define v0.26.0 product hardening foundation scope.
- Define allowed capability flags for hardening foundation areas.
- Define required-false boundary flags for forbidden trading and mutation
  capabilities.
- Add golden trace rows that prove forbidden submit, mutation, adapter send,
  automatic remediation, Dashboard trading controls, terminal claims, and
  missing required-false flags fail closed.
- Add a verifier that recomputes the effective boundary status from the trace.
- Record the trace rows in the release replay scope as validator executable
  replay.

Not included:

- production order submission;
- cancel, replace, amend, flatten, or any production order mutation;
- execution adapter call, adapter send, or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard operation controls or Dashboard trading controls;
- external identity-provider integration for a permission system;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Release docs identify v0.26.0 as product hardening foundation, not a
  product-grade trading system.
- All forbidden trading boundary fields are explicitly present and `false` in
  the passing fixture.
- Any submit, mutation, adapter send, automatic remediation, Dashboard trading
  control, or product-grade terminal claim set to `true` fails closed.
- Any missing required-false boundary field fails closed.
- `scripts/ai/verify_release.sh v26-product-hardening-boundary-contract`
  passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V260-001 cases as validator executable replay.
