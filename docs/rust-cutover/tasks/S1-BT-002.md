# S1-BT-002 - 策略工作台创建 Backtest Run 与服务端生命周期

Date: 2026-08-09
Executor: Codex
GitHub issue: #1272
Risk: high
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Status: REVIEW_REQUIRED

## 目标

让机构用户从策略工作台基于当前已注册的 `StrategyVersion` 创建真实 Backtest Run，
由服务端执行 `BacktestEngine`、写入不可变配置与结果，并通过既有 Product API Run 列表、
详情和指标合同读取完整生命周期。

## 范围

- 新增机构用户专用 `POST /api/product/v1/runs`，运维角色保持只读；
- 请求只允许 `backtest` 环境、当前策略版本、已登记数据集与模拟 Venue；
- 请求可配置初始资金、quote 数、EMA 快慢周期与交易数量，并设置严格范围；
- 服务端生成 Run ID，在阻塞线程池执行真实 `BacktestEngine`；
- 每次创建写入不可变 `request.toml`、`summary.json` 和 `run-manifest.json`；
- 动态 Run 与节点配置中的冻结 Run 一起进入列表、详情与 metrics 投影；
- 策略工作台启用 Backtest 栏目，提供中文创建表单、提交状态、错误状态和完成跳转；
- 更新 OpenAPI、生成的 TypeScript/Zod SDK、Rust/前端测试与治理证据。

## 非目标

- 不创建 Sandbox 或 Live Run，不连接外部 Venue，不提交真实订单；
- 不提供停止、取消、重试、补救、恢复、比较或复现操作；
- 不允许客户端提供 Run ID、文件路径、未登记 StrategyVersion、数据集或 Venue；
- 不修改 BacktestEngine 撮合、统计或交易语义；
- 不修改 v0.32.0 发布冻结文件。

## Post-freeze 例外

`crates/cli/src/dashboard/server.rs` 是 MVP frozen source。Issue #1272 已登记独立的
post-freeze 产品扩展：仅在既有 Product API 路由增加受角色限制的 Backtest 创建入口和
专用串行锁，并更新 freeze manifest 中该文件的精确 SHA-256。MVP 拓扑、退出条件和禁止
能力边界保持不变。

## 完成条件

本任务为 high risk。必须通过本地 Rust、API 合同、前端、浏览器与治理验证，取得独立
Gatekeeper 的 `REVIEW_APPROVED`，通过 hosted checks 后手动合并；禁止 auto-merge。
