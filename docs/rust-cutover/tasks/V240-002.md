## Goal

Establish the v0.24.0 order intent and execution policy artifact model so every
preview execution intent is auditable, replayable, and bound to one isolation
scope before later runtime work begins.

Plain Chinese summary: 本任务只定义 v0.24.0 order intent / execution policy
artifact 和 golden trace 覆盖。它要求 identity、policy provenance、owner
approval、risk/audit lineage 和 redaction boundary 都齐全；不发送 adapter，也不生成
真实交易请求。

## Scope

- Define the order intent schema fields: instrument, side, quantity, order type,
  time-in-force, account key, strategy key, venue node key, and isolation scope
  key.
- Define the execution policy schema fields: allowed order types, rate limit,
  throttle, slicing policy, retry policy, and risk/audit gates.
- Record policy provenance, owner/policy approval provenance, source
  provenance, and redaction boundary.
- Add golden trace coverage for valid intent, missing scope, policy mismatch,
  and forbidden operation cases.
- Add a fail-closed release verification stage.

## Non-Goals

- Do not send order intent artifacts to any execution adapter.
- Do not generate signed payloads or real trading requests.
- Do not add submit, cancel, retry, replace, amend, or flatten capability.
- Do not add Dashboard live order controls.

- Missing identity or policy provenance fails closed.
- Policy scope mismatch fails closed.
- Forbidden operation claims fail closed.
- Artifact examples do not contain secrets, raw credentials, signatures, signed
  payloads, raw request bodies, or raw exchange responses.
