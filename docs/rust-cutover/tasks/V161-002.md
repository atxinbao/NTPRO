# V161-002 - Make post-send kill switch a real second read

Date: 2026-06-23
Executor: Codex
Milestone: v0.16.1 guarded production mutation hardening
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Replace the v0.16 guarded-send post-send kill-switch evidence with a real
second read of the runtime gate after the HTTP result boundary.

Plain Chinese summary: 这个任务只把“发单边界前后有没有重新检查 kill switch”说清楚。
大白话：它不新增下单能力，只确保 artifact 里能看出 HTTP 边界后又读了一次
kill switch，并且如果第二次读取发现不干净，就要求人工复核并阻止后续新单推进。

## Scope

Included:

- keep the v0.16 single owner-approved tiny `LIMIT` `GTC` candidate boundary;
- read the kill-switch runtime gate before guarded-send readiness evaluation;
- read the same kill-switch runtime gate again after the HTTP result boundary;
- record pre-send and post-send runtime gate source, content hash, and checked
  timestamp evidence;
- record whether the post-send kill-switch state is clean;
- mark post-send progression blocked, manual review required, and new orders
  blocked when the post-send state is not clean;
- keep all default/offline gates no-send and no-network.

Not included:

- strategy-driven production execution;
- retry, cancel, replace, amend, flatten, or remediation;
- Dashboard order controls;
- multi-order or batch production execution;
- production order state reads or listenKey lifecycle;
- any production trading platform capability expansion.

## Acceptance Criteria

- Ready/offline guarded-send artifacts record matching pre/post runtime gate
  content hashes and clean post-send state.
- Active kill-switch artifacts record blocked send state and blocked post-send
  progression without attempting network.
- A unit test proves the post-send runtime gate read is independent by mutating
  the gate inside the injected HTTP executor and observing a different post-send
  content hash.
- Post-send dirty state sets:
  - `post_send_kill_switch_clean=false`;
  - `post_send_progression_blocked=true`;
  - `manual_review_required=true`;
  - `new_orders_blocked=true`.
- Release gates remain offline and fail-closed by default.
