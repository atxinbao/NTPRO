# V031-004 - registry stale lock recovery

Milestone: v0.3.1 Local Supervisor Control Console Hardening
Priority: P1
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Recover cleanly from stale local supervisor registry locks so a dead process
does not leave the control plane permanently wedged.

Plain language: if the lock owner is gone, the next supervisor command should be
able to recover instead of hanging forever.

## Dependencies

- `V031-003`

## Scope

- Extend the registry lock artifact with enough identity to detect stale locks.
- Detect whether the recorded lock owner is still alive.
- Recover a stale lock after the documented timeout or dead-owner condition.
- Preserve clear failure behavior for a genuinely active conflicting lock.
- Add deterministic tests for stale lock recovery and active lock refusal.

## Non-goals

- Do not redesign the whole supervisor storage format.
- Do not add distributed locking.
- Do not claim multi-user or remote coordination support.

## Related files

- `crates/cli/src/supervisor.rs` (TO_MODIFY): registry lock path.
- `crates/cli/src/opt.rs` (REFERENCE): supervisor CLI context if needed.
- `docs/rust-cutover/evidence/V031-004.md` (CREATE): task evidence.

## Implementation guidance

Prefer a narrow extension of the existing local lock artifact over a new
locking subsystem. Keep behavior local-only and inspectable from artifacts.

## Verification criteria

- A stale lock can be recovered by the next supervisor command.
- An active lock still blocks conflicting access explicitly.
- Tests cover both stale-owner recovery and active-owner refusal.
