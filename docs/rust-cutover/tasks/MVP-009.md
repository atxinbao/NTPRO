## 目标

为单 Supervisor + 单节点本地 MVP 建立服务端角色访问边界。机构用户不能直接读取
控制中心、旧 Dashboard 运维 API 或节点生命周期接口；运维用户也不能用运维会话
冒充机构工作台用户。

## 角色矩阵

| `/institution-workbench` | 允许 | 拒绝 |
| `/control-center`、`/dashboard` | 拒绝 | 允许 |
| `/api/mvp/v1/status`、`/api/mvp/v1/event-correlation` | 允许 | 允许 |

| `/api/server`、`/api/snapshot`、`/api/v28/*`、`/api/nodes/*` | 拒绝 | 允许 |

## 访问合同

- `dashboard serve` 每次启动使用 AWS-LC CSPRNG 生成两个独立 256-bit 本地 token；
- 启动输出提供角色专属 bootstrap URL；成功请求只返回 303、写入
  `HttpOnly; SameSite=Strict; Path=/` 会话 Cookie，并从 Location 删除 token；
- token 只在当前进程生命周期内有效，不持久化，不进入 API 响应或浏览器证据；
- 缺失、空值、伪造、错角色或重复 `access_token` 全部返回 403；
- 403 使用 `ntpro.mvp_portal_access.error.v1` 脱敏错误信封，并显式关闭交易、Supervisor
  action、外部 Venue、重试和自动补救边界；
- 静态 CSS/JavaScript 不含运行数据，可公开读取；运行数据和动作必须经过服务端角色检查；
- 现有 loopback-only、HTTP 方法、原始 Event Store 阻断和只读交易边界保持不变。
