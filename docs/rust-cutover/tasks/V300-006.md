## Goal

Define rollback and disaster recovery execution boundary for the backend
go-live candidate.

Plain Chinese summary: 本任务定义 v0.30.0 rollback / DR execution boundary。
它只验证 rollback plans、DR restore boundaries、data safety checkpoints、manual
approval requirements 和 incident freeze triggers，不执行 rollback、restore、data
restore 或 service restart。任何 ambiguous rollback execution、缺 operator approval、
stale restore point、deployment provenance 不一致或 execution=true 都会 fail closed。

## Dependency

- Depends on `V300-002` production deployment plan and environment readiness.
- Depends on `V300-004` operator approval freeze and change-window lifecycle.
- Depends on `V300-005` canary execution preflight and no-default-execution
  gate.
- Hard-blocked by published v0.29.1 release evidence and closed v0.29.1
  milestone.

## Scope

Included:

- Specify rollback plans, DR restore boundaries, data safety checkpoints,
  manual approval requirements, and incident freeze triggers.
- Validate preview evidence separately from execution evidence.
- Reject ambiguous rollback execution, missing operator approval, stale restore
  point, inconsistent deployment provenance, missing safety checkpoints, and
  missing incident freeze triggers.
- Add deterministic JSON and executable verifier.

Not included:

- rollback execution;
- DR restore execution;
- production data restore or service restart;
- production runtime enablement;
- default production submit;
- production order mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal operation controls or trading controls.

## Acceptance Criteria

- Rollback/DR readiness is verifiable without executing rollback or restore.
- Execution remains blocked unless a later scoped gate explicitly permits it.
- Ambiguous execution claims and stale/mismatched safety evidence fail closed.
