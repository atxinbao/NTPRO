# V100-008 Handle Reconciliation and Orphan Orders

Date: 2026-06-19
Executor: Codex
Status: IN PROGRESS

## Goal

Define offline reconciliation fixtures for inconsistent Binance testnet order
states and ensure each inconsistent state risk-halts and blocks new orders.

## Scope

- Add a local CLI fixture command for reconciliation/orphan-order states.
- Cover submit-without-local-ack.
- Cover cancel timeout.
- Cover local open while exchange is filled.
- Cover restart with unfinished testnet order state.
- Emit a JSON report with `risk_halted=true` and `new_orders_blocked=true`.
- Keep testnet and production order counters separated and at zero.

## Out Of Scope

- No Binance API calls.
- No online exchange readback.
- No submit or cancel.
- No matching-engine submission.
- No production Binance endpoint.
- No Dashboard order controls.
- No claim that V100-006 manual submit/cancel proof has passed.

## Acceptance

- All four scoped inconsistent-state fixtures are represented.
- Single-scenario rendering is supported for targeted evidence.
- Every inconsistent-state fixture records `risk_halted=true`.
- Every inconsistent-state fixture records `new_orders_blocked=true`.
- Report records `network_attempted=false` and `real_orders_submitted=false`.
- Report records `testnet_orders_submitted=0`,
  `testnet_orders_canceled=0`, `production_orders_submitted=0`, and
  `production_orders_canceled=0`.
- Offline CI does not require Binance credentials, network, or order
  submission.
