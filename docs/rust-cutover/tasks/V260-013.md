# V260-013 - v26 existing public Release body update after gate

Date: 2026-07-07
Executor: Codex
GitHub issue: #845
Milestone: v0.26.0

## Goal

Fix release publication so an already-public current Release can be updated from
corrected release notes after a successful hosted corrective tag gate.

## Context

After V260-012 made the hosted v0.26.0 tag gate pass, `release-publish.yml`
run `28853225168` failed because `publish_ntpro_release_after_gate.sh` checked
the stale public GitHub Release body before editing it. For corrective releases,
the public Release may already exist from an earlier successful gate and still
need a post-gate notes/body update.

## Scope

- Update existing public Release title/body after hosted gate success.
- Use GitHub Release `updated_at` as the ordering proof for corrective updates
  when `published_at` predates the latest gate.
- Keep draft publish and missing release create paths covered.
- Keep strict publication body validation required after publish.
- Do not change runtime, Dashboard, adapter, order, or public API behavior.

## Acceptance

- `scripts/ai/verify_release_publish_after_gate.sh` covers stale public Release
  update after gate and passes.
- `release-publish.yml` can update `ntpro-rust-only-v0.26.0` after the hosted
  gate run.
- Final v0.26.0 strict publication guard passes.
