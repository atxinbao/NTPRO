# V071-005 Tighten Manual-Online Proof Semantics

Date: 2026-06-15
Executor: Codex
Owner role: Verification & Release Gatekeeper
Review role: Control & Scope Agent
Risk level: medium
Status: PR_REQUIRED

## Goal

Tighten the v0.7 manual-online gate semantics so stable HTTP failures are
classification evidence only and cannot be counted as connectivity proof.

## Scope

- Keep the default manual-online script path CI-safe and offline.
- Keep real online mode manual opt-in only.
- Require real online proof to include:
  - `network_attempted=true`;
  - `testnet_connection=true`;
  - `error_code=none`;
  - `response_shape_validated=true`;
  - `real_orders_submitted=false`;
  - `values_recorded=false`;
  - `secrets_redacted=true`.
- Make stable HTTP failures fail with `classified_failure
  connectivity_proof=false`.
- Update release-facing docs to distinguish classification evidence from
  connectivity proof.

## Non-Goals

- No default network access.
- No authenticated account access.
- No account mutation.
- No order submission.
- No real funds.
- No production Binance connectivity.
- No production trading claim.
- No v0.8 capability work.
- No tag creation.
- No GitHub Release publication.

## Acceptance

- Default preflight passes without creating sockets.
- Real online branch cannot treat stable failure as connectivity proof.
- Release docs explicitly state that stable classified failures are diagnostic
  only.
- Existing v0.7 offline/manual scripts still pass in default local mode.
