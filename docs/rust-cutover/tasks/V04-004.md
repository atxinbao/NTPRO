# V04-004 - strategy config DTO

Milestone: v0.4.0 Binance Sandbox Product Foundation
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Trading Runtime Agent
Risk: medium

## Goal

Add a stable strategy configuration DTO for the v0.4 sandbox path.

Plain language: users and tests need one clean config shape for EMA and RSI
without guessing internal runtime knobs.

## Dependencies

- `V04-003`

## Scope

- Define a stable config DTO for built-in v0.4 strategies.
- Add validation rules for required fields and scoped defaults.
- Keep naming product-facing and explicit.
- Align config loading with the sandbox Binance boundary.

## Non-goals

- Do not add a generic strategy registry.
- Do not support arbitrary user-defined strategy schemas.
- Do not add production config branches.

## Related files

- `crates/cli/` (TO_MODIFY): config validation and loading.
- `crates/trading/` (TO_MODIFY): strategy-side DTO contract.
- `docs/rust-cutover/evidence/V04-004.md` (CREATE): task evidence.

## Implementation guidance

Keep the DTO small and predictable. Validation errors should be clear enough
that later dashboard and smoke work can depend on them.

## Verification criteria

- DTO exists and validates required fields.
- DTO supports EMA and RSI sandbox config inputs.
- Validation errors are deterministic and product-facing.
