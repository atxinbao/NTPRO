## Goal

Make the v28 Admin/Trader read-only backend API handoff production-ready on the
backend side.

Plain Chinese summary: 本任务把 Admin/Trader read-only backend API handoff 推进为
v0.29 backend production-readiness evidence。它定义 readiness、provenance、audit、
telemetry、permission、deployment 和 runbook status 的稳定只读 API/artifact 合同，包含
schema/versioning、freshness、redaction、pagination/size 和 deterministic failure
semantics；malformed、stale、unauthorized、partial-state 或 forbidden controls 都会 fail
closed 或降级为只读状态。本任务不开放 order ticket、submit/cancel/retry/replace/amend/
flatten 或 adapter send controls。

- Depends on `V290-000` v0.28.1 release publication dependency proof.

- Depends on V290 readiness modules for audit, telemetry, and permissions.
- Builds on `V280-007` Trader Terminal backend API contract handoff.

## Scope

Included:

- Define stable read-only backend API/artifact contracts for production
  readiness consumers.
- Add deterministic validation for schema/versioning, freshness, redaction,
  pagination/size, authorization, partial state, and failure semantics.
- Promote `read_only_backend_api_production_readiness` in the v0.29 readiness
  matrix to `production-ready` evidence.

Not included:

- HTTP server implementation;
- frontend/Admin/Trader Terminal UI implementation;
- order tickets or trading operation controls;
- submit/cancel/retry/replace/amend/flatten;
- adapter send or live exchange request;
- backend go-live or product-grade terminal readiness claims.
