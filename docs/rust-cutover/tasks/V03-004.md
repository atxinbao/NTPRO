# V03-004 - Supervisor artifacts to DashboardSnapshot aggregator

Milestone: v0.3 Dashboard MVP
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Build the backend read-model aggregator that converts v0.2 supervisor artifacts
into `DashboardSnapshot`.

Plain language: this is the real data bridge between v0.2 and the dashboard.

## Dependencies

- `V03-003`

## Scope

- Read local supervisor state through existing artifact paths and helper types.
- Use:
  - `registry.json`;
  - per-node `status.json`;
  - per-node `metrics.json`;
  - per-node `logs/events.log`;
  - per-node stdout/stderr log paths.
- Aggregate multiple nodes.
- Populate Overview, Nodes, Data Sources, Execution, Risk, Runtime Modules,
  Logs, Metrics, Alerts, Controls, and Gaps sections.
- Mark missing or stale artifacts explicitly.
- Preserve `external_venue_connection=false` and `real_orders_submitted=false`
  visibility for sandbox evidence.

## Non-goals

- Do not implement the HTTP server in this task.
- Do not implement UI rendering in this task.
- Do not add production telemetry emitters.
- Do not read mutable `LiveNode`, engine, cache, message bus, adapter, or
  account internals.
- Do not synthesize healthy states when artifacts are missing.

## Implementation guidance

Prefer using existing Rust structs and JSON parsers over parsing CLI text output.
The dashboard aggregator should be deterministic and testable with temporary
artifact directories.

## Verification criteria

- Aggregator tests cover:
  - missing registry;
  - empty registry;
  - one node;
  - two nodes;
  - missing status artifact;
  - invalid status artifact;
  - missing metrics artifact;
  - stale process or artifact state;
  - explicit gaps for unsupported module details.
- No test requires live exchange credentials or network endpoints.
