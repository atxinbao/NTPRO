# V03-013 - reconnect data source control

Milestone: v0.3.0 Local Supervisor Control Console
Priority: P0
Owner role: Adapter & Integration Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Implement a local sandbox-only reconnect data source control path.

Plain language: the local console should be able to ask a sandbox node to
reconnect its data source or return a clear unsupported result if no reconnect
path is available.

## Dependencies

- `V03-011`

## Scope

- Define the reconnect data source request/result contract.
- Wire a local supervisor/Dashboard-visible control path.
- Record reconnect result in status or metrics.
- Support sandbox/mock/fixture mode first.
- Return explicit unsupported status for real adapter reconnects that are not
  in v0.3.0 scope.

## Non-goals

- Do not reconnect production exchange data feeds.
- Do not add real credentials or venue secrets.
- Do not hide unsupported adapter behavior as success.
- Do not submit, modify, or cancel orders.
- Do not create a release tag or GitHub Release.

## Related files

- `crates/cli/src/supervisor.rs` (TO_MODIFY): supervisor command/status path.
- `crates/cli/src/dashboard.rs` (TO_MODIFY): control state and API result.
- `crates/cli/src/live.rs` (TO_MODIFY): local node control handling if needed.
- `docs/rust-cutover/evidence/V03-013.md` (CREATE): task evidence.

## Implementation guidance

Prefer a deterministic local fixture/mock reconnect path. If deeper runtime
adapter reconnect is not ready, make the result explicitly `not_supported` for
that adapter and keep the v0.3.0 release claim honest.

## Verification criteria

- Reconnect data source control returns `ok` for the supported sandbox/mock path
  or explicit `not_supported` for unsupported adapter paths.
- Dashboard/status/metrics expose the reconnect result.
- No external venue connection is opened.
- No real credentials are required.
