# V04-002 - Binance capability matrix

Milestone: v0.4.0 Binance Sandbox Product Foundation
Priority: P0
Owner role: Adapter & Integration Agent
Review role: Control & Scope Agent
Risk: medium

## Goal

Publish one honest capability matrix for the Binance product boundary.

Plain language: before building more product surface, say clearly what Binance
Spot and Binance USDT-M can and cannot do in v0.4.

## Dependencies

- `V04-001`

## Scope

- Inventory Binance Spot and Binance USDT-M product surfaces.
- Classify each surface as `supported`, `partial`, `sandbox-only`,
  `fixture-only`, `deferred`, or `removed`.
- Cover data, execution, risk, config, smoke, and dashboard-facing status
  surfaces.
- Keep the matrix aligned with actual local evidence and existing adapter code.

## Non-goals

- Do not implement new adapter behavior.
- Do not overstate parity with production Binance APIs.
- Do not turn fixture evidence into a production support claim.

## Related files

- `crates/adapters/binance/` (REFERENCE): current Binance adapter surfaces.
- `docs/rust-cutover/inventory/binance_capability_matrix.md` (CREATE): matrix
  record.
- `docs/rust-cutover/evidence/V04-002.md` (CREATE): task evidence.

## Implementation guidance

This task can stay documentation-first if needed. Its job is to constrain later
implementation, not to justify broad claims after the fact.

## Verification criteria

- Matrix exists and covers Spot and USDT-M.
- Matrix uses the agreed classification vocabulary.
- Matrix stays inside the v0.4 sandbox boundary.
