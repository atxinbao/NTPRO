# V241-004 - v24 schema-only trace classification and executable replay advancement

Date: 2026-07-05
Executor: Codex
GitHub issue: #773
Milestone: v0.24.1
Status: IMPLEMENTED

## Goal

Classify the v0.24.0 order-control golden traces that were previously recorded
as `schema_only_scoped`, promote the deterministic decision-envelope rows to
executable validator replay, and keep the runtime boundary explicit.

Plain Chinese summary: 本任务把 v24 的 order-control golden traces 从笼统的
schema-only 状态拆清楚。39 个 v24 决策 envelope 现在有可执行 validator replay
检查，但这不是 Rust runtime replay，也不是 adapter integration；真实 submit、
cancel、replace、amend、flatten、retry scheduler 和 Dashboard 操作控件仍然关闭。

## Scope

- Update `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json`.
- Add the v24.1 schema replay classification report.
- Add `scripts/ai/verify_v24_1_schema_replay_classification.sh`.
- Wire the new gate into `scripts/ai/verify_release.sh`.
- Record the post-release classification in `v0_24_0_release_manifest.json`.

## Non-Goals

- Do not add Rust order-control runtime adapter integration.
- Do not open submit, cancel, replace, amend, flatten, retry, or scheduler
  execution.
- Do not add live exchange requests or adapter send calls.
- Do not add Dashboard or Trader Terminal operation controls.
- Do not claim a complete executable order-control runtime.

## Classification Contract

`schema_only_scoped` means schema and contract presence only. It is not
executable replay and must not be described as executable order-control runtime.

`validator_executable_replay` means a deterministic executable validator checks
the golden trace expected decision envelope and fail-closed boundary flags. It
does not prove Rust projection replay, runtime adapter integration, exchange
truth, or production mutation capability.

`executable_replay` remains reserved for Rust harness replay through a crate or
CLI test entrypoint.

`runtime_adapter_integration` is a future proof class and remains absent for
v0.24.1.
