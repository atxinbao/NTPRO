# V03-005 - Local dashboard HTTP server

Milestone: v0.3 Dashboard MVP
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Add a local Dashboard HTTP server that serves static UI assets and JSON API
responses backed by `DashboardSnapshot`.

Plain language: run one local command, open one local page, see the system
state.

## Dependencies

- `V03-004`

## Scope

- Add a local CLI entrypoint, expected shape:

```bash
nautilus dashboard serve --registry <registry> --bind 127.0.0.1:5173
```

- Serve static HTML, CSS, and JavaScript.
- Serve local JSON API endpoints for:
  - dashboard snapshot;
  - node list;
  - node detail;
  - node metrics;
  - node logs;
  - later start/stop action endpoints.
- Use the v0.3 dashboard aggregator as the only backend data source.
- Default to local access on `127.0.0.1`.
- Do not require a token for v0.3 local MVP.

## Non-goals

- Do not add React, Vue, Next.js, Vite, or another frontend build system.
- Do not add multi-user permissions.
- Do not add remote deployment.
- Do not add production exchange connectivity.
- Do not implement start/stop controls in this task unless explicitly scoped as
  API placeholders returning unsupported.

## Implementation guidance

Use existing workspace dependencies where possible. Keep the server local and
small. The UI can be static assets embedded or served by the Rust binary. Avoid
introducing a new package manager or frontend build pipeline in v0.3.

## Verification criteria

- `nautilus dashboard serve --help` documents the local command honestly.
- Server starts on `127.0.0.1` with a registry path.
- `/` or `/dashboard` serves the dashboard shell.
- JSON API returns a `DashboardSnapshot`.
- Missing registry or invalid node state returns an explicit local error or gap,
  not a crash.
- No live credentials are required.
