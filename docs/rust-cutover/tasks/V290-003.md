## Goal

Move telemetry and SLO ingestion from deterministic runtime closure toward
backend production-readiness evidence.

Plain Chinese summary: 本任务把 telemetry/SLO ingestion 从 v0.28 runtime closure
推进为 v0.29 backend production-readiness evidence。它定义 telemetry source、
sampling、freshness、retention、redaction、SLO breach semantics 和 alert handoff 规则，
并用 source-controlled sandbox fixture 验证 ingestion 和 SLO state transition；malformed
metrics、stale telemetry、missing provenance、unredacted payload 或任何 submit/retry/
adapter/remediation/trading trigger 都会 fail closed。telemetry 仍只是 observability
input。

## Scope

Included:

- Define telemetry source, sampling, freshness, retention, redaction, SLO
  transition, and alert handoff production-readiness requirements.
- Add deterministic readiness validation for healthy ingestion, degraded SLO
  breach audit, stale source, missing provenance, malformed metrics, unredacted
  payload, and forbidden operation trigger cases.
- Promote `telemetry_slo_ingestion_production_readiness` in the v0.29 readiness
  matrix to `production-ready` evidence.

Not included:

- production telemetry transport or external observability backend ingestion;
- automatic remediation or retry scheduling;
- adapter send or live exchange request;
- production order submission or mutation;
- Dashboard/Admin/Trader Terminal trading controls;
- backend go-live or product-grade terminal readiness claims.
