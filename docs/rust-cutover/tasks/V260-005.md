## Goal

Define upgrade, rollback, and release operation runbook evidence so upgrade and
rollback flows are auditable, previewable, and blockable without automatically
executing production deployment or rollback.

Plain Chinese summary: 本任务定义 upgrade / rollback / release operation runbook
evidence。它覆盖 upgrade plan、rollback plan、preflight checks、owner approval、
release tag/source evidence、post-check evidence、release gate 和 Dashboard 只读证据；
所有 runbook 只能输出 preview 或 blocked preview，不能自动部署、自动回滚、触发 trading
operation 或 automatic remediation。

## Dependency

- Depends on `V260-003` operation audit trail.
- Depends on `V260-004` deployment provenance.
- Keeps runbook evidence and preview only.
- Does not execute real deployment or rollback.
- Does not integrate a CD system.
- Does not change release publication workflow.

## Scope

Included:

- Define upgrade plan, rollback plan, preflight checks, owner approval,
  release tag/source evidence, post-check evidence, audit lineage, release gate
  evidence, and Dashboard read-only evidence.
- Cover good path, missing approval, tag mismatch, failed preflight, rollback
  recommendation, and stale environment evidence.
- Add a verifier that recomputes runbook preview status from the trace.
- Register the trace rows in release replay scope as validator executable
  replay.

Not included:

- real deployment or rollback execution;
- CD system integration;
- release publication workflow changes;
- trading operation execution;
- automatic remediation;
- Dashboard execution controls.

## Acceptance Criteria

- Unapproved upgrade or rollback shows blocked preview only.
- Tag, source, or environment provenance mismatch fails closed.
- Failed preflight fails closed.
- Stale environment evidence fails closed.
- Release operation evidence has audit lineage to V260-003 and V260-004.
- Runbook evidence cannot trigger trading operation or automatic remediation.
- `scripts/ai/verify_release.sh v26-upgrade-rollback-runbook-evidence` passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V260-005 cases as validator executable replay.
