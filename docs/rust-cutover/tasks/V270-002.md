## Goal

Define the v0.27.0 external identity and permission integration foundation
without opening trading controls. The task maps external identity-provider
evidence into the existing read/admin permission boundary and proves that stale
or ambiguous identity mappings fail closed.

Plain Chinese summary: 本任务定义 v0.27.0 的 external identity / permission
integration foundation。它只记录外部身份来源、role mapping provenance、freshness、
redaction、lineage 和 v26 permission boundary 对齐证据；不接入真实 SSO/IAM runtime，
不新增 submit/cancel/retry/replace/amend/flatten 权限，不打开 adapter send、live
exchange request、Dashboard trading controls 或 product-grade live trading terminal
声明。

## Dependency

- Depends on `V270-001` product operations runtime integration boundary
  contract.
- Uses `V260-002` operator permission model as the local role/scope boundary
  baseline.
- Depends on `V270-000` intake gate and its v0.26.1 publication proof.
- Does not grant live operation authorization from external identity evidence.

## Scope

Included:

- Define external identity-provider evidence shape.
- Define role mapping provenance, freshness, redaction, and lineage fields.
- Validate operator, admin, auditor, and release-gatekeeper mappings against the
  v26 permission boundary.
- Add fail-closed cases for missing IdP provenance, stale role mapping, unknown
  role, cross-scope action, v26 boundary mismatch, and forbidden trading
  permissions.
- Add a verifier that recomputes effective identity permission status from the
  trace.
- Record the trace rows in the release replay scope as validator executable
  replay.

Not included:

- production order submission;
- cancel, replace, amend, flatten, or any production order mutation;
- execution adapter call, adapter send, or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard operation controls or Dashboard trading controls;
- product-grade live trading terminal readiness claims;
- real SSO/IAM runtime integration or token verification.

## Acceptance Criteria

- Valid external identity mapping is accepted only when IdP provenance,
  freshness, redaction, lineage, role, scope, and v26 permission boundary
  evidence are complete.
- Missing IdP provenance fails closed.
- Stale role mapping fails closed.
- Unknown role fails closed.
- Cross-scope action fails closed.
- v26 permission boundary mismatch fails closed.
- Any submit, cancel, retry, replace, amend, flatten, adapter send, live
  exchange request, Dashboard trading control, automatic remediation, or manual
  submit permission fails closed.
- `scripts/ai/verify_release.sh v27-external-identity-permission-foundation`
  passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V270-002 cases as validator executable replay.
