## Goal

Define the v0.24.0 execution algorithms and order-control contract before any
runtime implementation begins. The contract must state the allowed preview
surface, required gates, evidence, identity bindings, and prohibited claims.

Plain Chinese summary: 本任务只定义 v0.24.0 execution / order-control 合约。它把
limit/market、rate limit、throttle、slicing、cancel/replace/amend preview、
retry/no-retry、owner/policy/risk/audit gates 和 isolation_scope 绑定规则写清楚；
不调用真实 adapter，也不开 Dashboard 下单按钮。

## Scope

- Define limit and market order boundary decisions.
- Define rate-limit, throttle, order slicing, cancel/replace/amend preview, and
  retry/no-retry policy boundaries.
- Define minimum owner-approved, policy-approved, risk-gated, and audit-gated
  conditions.
- Define account, strategy, venue node, and isolation scope binding rules.
- Define Dashboard / Workbench read-only preview boundary.
- Add a fail-closed release verification stage for the contract.

## Non-Goals

- Do not implement runtime order-control code.
- Do not call execution adapters.
- Do not add live order-control buttons.
- Do not add submit, cancel, retry, replace, amend, flatten, or order-ticket
  capability.

- `scripts/ai/verify_release.sh v24-order-control-contract`

## Done Criteria

- The contract explicitly marks all real operations disabled by default.
- Missing `account_key`, `strategy_key`, `venue_node_key`, or
  `isolation_scope_key` fails closed.
- Cross-account, cross-strategy, cross-venue, and cross-node operation claims
  fail closed.
- The release verification stage rejects overclaims such as submit capability,
  production order mutation, adapter calls, live Dashboard controls, and
  product-grade trading terminal readiness.
