# V03-009 - Dashboard start/stop controls

Milestone: v0.3 Dashboard MVP
Priority: P1
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Add Dashboard start and stop lifecycle controls for local supervisor-managed
nodes.

Plain language: the operator can start or stop a local sandbox node from the
Dashboard, but cannot trade from the Dashboard.

## Dependencies

- `V03-008`

## Scope

- Add local API action handling for:
  - `start`;
  - `stop`.
- Wire controls through the local supervisor path.
- Show button availability based on lifecycle state:
  - stopped node: `Start` enabled;
  - running node: `Stop` enabled;
  - invalid states: disabled with reason.
- Show pause, resume, reconnect data, and reconnect execution as disabled or
  unsupported.
- Return auditable action responses with:
  - action id;
  - status;
  - previous state;
  - current state;
  - started/finished timestamps when available;
  - redacted message;
  - error code when rejected or failed.

## Non-goals

- Do not add manual order entry.
- Do not add order modification or cancellation.
- Do not add strategy hot reload.
- Do not add production reconnect behavior.
- Do not directly mutate runtime internals from UI code.
- Do not bypass the supervisor registry and artifact path.

This is a high-risk boundary because controls affect local node lifecycle. Keep
the implementation narrow. Stop at `REVIEW_REQUIRED` before merge according to
repo rules. Do not enable auto-merge.

## Verification criteria

- Browser or Playwright verifies enabled/disabled button states.
- Start from stopped updates node state to running.
- Stop from running updates node state to stopped.
- Unsupported controls are visible as disabled or unsupported.
- No manual order, order modification, order cancellation, strategy hot reload,
  or production reconnect control exists.
- `scripts/ai/v02_two_node_supervisor_smoke.sh` still passes.
