问题，使本地交付的正常停止稳定进入既有 MVP 节点收口路径。

## 实现合同

- 在 `run_mvp_serve` 事件循环外只创建一次 `tokio::signal::ctrl_c()` future；
- pin 后在所有状态刷新迭代中持续轮询同一个 future；
- 保持 Dashboard 退出、状态写入失败、`runtime.stop` 和停止日志语义不变；
- 直接回归至少经过三次状态刷新后再触发 shutdown，并要求同一监听完成退出。

## 风险与回滚

风险是信号 future 生命周期调整影响 Dashboard、刷新和停止分支的竞争顺序。实现不改变
`tokio::select!` 分支内容，只把监听生命周期提升到循环外，并通过直接回归及真实本地交付矩阵
验证。回滚时必须同时回退源码和 freeze manifest 哈希；#1326 恢复阻塞，不得用强杀代替
正常停止验收。
