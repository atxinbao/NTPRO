## Goal

Implement the multi-venue node registry and lifecycle boundary under the
v0.23.0 isolation contract.

Plain Chinese summary: 本任务把多 venue node 隔离先落到 Rust 可执行 replay 和 registry
contract 层。新增 `venue_node_key`、`account_key`、`strategy_key`、
`isolation_scope_key`、`adapter_instance_id` 的 fixture，证明两个 venue node 的
registry/lifecycle/adapter/connection/risk/audit/provenance 状态不会混读；跨 node
component mismatch 会 fail closed，unknown venue node identity 也会 fail closed。本任务
不新增凭证处理扩展、不新增实盘 submit/order mutation，不做 Dashboard 操作控件。

## Scope

Included:

- add V230 venue node lifecycle golden trace fixtures;
- add executable Rust projection replay for venue node registry/lifecycle
  identity;
- define the node registry contract shape in release evidence;
- validate `venue_node_key`, `account_key`, `strategy_key`,
  `isolation_scope_key`, and `adapter_instance_id` presence;
- fail closed on cross-node component mismatch;
- fail closed on unknown venue node identity;
- prove credential handling, production mutation, production submission,
  implicit cross-venue operation, and Dashboard operation controls remain
  disabled.

Not included:

- ungated production mutation;
- credential handling expansion;
- dashboard implementation;
- cross-node orchestration/control-plane implementation.

## Acceptance Criteria

- `tests/golden/read_model_venue_node_lifecycle_schema.jsonl` includes

  venue node cases as executable replay.
- Release/evidence docs define the node registry contract shape.
- No submit, order mutation, credential expansion, Dashboard operation-control
