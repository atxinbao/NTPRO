# V03-003 - Status detail DTOs

Milestone: v0.3 Dashboard MVP
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Define detailed dashboard status DTOs for data sources, execution gateways, risk
engine, runtime modules, logs, metrics, alerts, gaps, and controls.

Plain language: every panel needs a predictable data shape before UI work
starts.

## Dependencies

- `V03-002`

## Scope

- Add or refine DTOs for:
  - `DataSourceStatus`;
  - `ExecutionGatewayStatus`;
  - `RiskStatus`;
  - `RuntimeModuleStatus`;
  - `LogStatus`;
  - `MetricStatus`;
  - `AlertSummary`;
  - `DashboardGap`;
  - `ControlStatus`;
  - action response shape for local lifecycle actions.
- Data source status must express provider, connection, freshness, health, and
  redacted last error.
- Execution status must express gateway, venue, connection, started state,
  redacted account reference, order count summary, and redacted last error.
- Risk status must express trading state, health, rejection summary, and
  redacted last error.
- Runtime module status must express module name, status, health, last seen,
  last error, and evidence source.

## Non-goals

- Do not implement aggregation in this task.
- Do not implement HTTP endpoints in this task.
- Do not implement UI rendering in this task.
- Do not expose secrets, raw orders, raw fills, raw venue payloads, full account
  objects, credentials, or signing material.
- Do not claim real exchange readiness from DTO presence.

## Implementation guidance

Keep DTOs small and explicit. Missing data must be represented as an explicit
state, not an omitted field that the UI can misread as healthy.

## Verification criteria

- Unit tests cover each DTO default and JSON shape.
- Tests prove unavailable fields serialize as `unknown`, `not_configured`,
  `not_supported`, `stale`, or `redacted`.
- Tests prove raw order, raw fill, raw venue payload, raw account object, and
  credential fields are not part of the DTO shape.
