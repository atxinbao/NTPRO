## Goal

Define the v0.17.0 production reconciliation and orphan recovery boundary
before implementation begins.

Plain Chinese summary: 这个任务只定 v0.17 范围。大白话：先讲清楚 v0.17 只能围绕
v0.16 那一笔 owner 批准的小额生产订单候选做“本地记录 vs 交易所只读状态”的对账；
不能直接变成自动撤单、自动重试、自动补救或完整 OMS。

## Scope

Included:

- define single mutation candidate lineage reconciliation;
- define local ledger, readback mapper, classifier, orphan detection, restart
  recovery, and read-only Dashboard sequence;
- define manual review and new-order blocking semantics;
- preserve no automatic cancel/retry/remediation by default;
- document endpoint and artifact boundaries.

Not included:

- implementation code;
- production order submission;
- automatic cancel, replace, amend, retry, correction, flatten, or remediation;
- Dashboard order/cancel controls;
- multi-account or multi-venue reconciliation;
- strategy-driven production execution;
- release tag creation.

## Acceptance Criteria

- Scope doc explicitly limits v0.17 to one v0.16 mutation candidate lineage.
- Scope doc requires owner-gated read-only exchange readback.
- Orphan/mismatch outcomes require `manual_review_required=true` and
  `new_orders_blocked=true`.
- Automatic cancel/retry/remediation remain forbidden by default.
- Dashboard scope is read-only evidence only.
- README current public/source milestone is not expanded by this scope decision.
