# S2-DM-001 - Demo Run 创建与 Supervisor 生命周期

Date: 2026-08-10
Executor: Codex
GitHub issue: #1280
Risk: high
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Status: REVIEW_APPROVED

## 目标

让策略工作台用户基于当前不可变 StrategyVersion 创建一个 Demo Run，绑定冻结的单
Supervisor + 单 Sandbox node，并通过显式 start/stop 动作驱动真实节点生命周期。

## 范围

- Demo Run 创建合同、不可变请求、版本快照与 manifest；
- Supervisor node、strategy instance、Sandbox account 和 Venue 的精确身份绑定；
- 活动 Run 生命周期从 Supervisor 实际注册表和节点状态投影，停止/失败终态作为不可变历史保存；
- 同一时刻最多一个活动 Demo Run，终态 Run 不阻塞下一次创建且不得随 node 复用发生漂移；
- Supervisor registry 保存 Run ownership 和终态哈希锚点，所有非 ownership 启停入口必须拒绝
  活动 Demo node；
- 正式 `nautilus mvp serve` 只准备 Dashboard、身份合同和 registry，不预启动 node；Demo start
  是唯一启动入口；
- 用户显式 start/stop，服务端串行化动作并返回实际结果；
- start 在完整运行投影校验失败时必须停止并确认节点终态，不允许留下孤儿进程；
- 自然停止和异常退出必须在来源健康检查前可靠终态化；缺失或非法 Supervisor 时间戳、未锚定
  终态、合法形状重签终态均 fail closed；
- MVP 退出必须 owner-aware 停止并终态化活动 Demo；同一 workspace 重启后历史终态仍可读取，
  且 node 不得自动重启；
- MVP 退出不得依赖可能过期的完整产品投影或 stop 前 manifest 校验；运行进程必须先按 registry
  ownership 停止，再校验和发布终态；
- 同一 workspace 重启必须在精确校验 registry 标准路径后删除旧 status/metrics/pid 运行快照，
  再以 NotStarted + Missing 状态重新登记；路径漂移不得触发任何删除；
- 无运行工件的正式 NotStarted 准备态，以及已锚定且边界完整的 stopped/failed 快照，不因
  心跳停止而失去可读性；运行中的 status contract、status/metrics、未锚定终态或边界异常的
  旧快照继续 fail closed；
- OpenAPI、生成 TypeScript/Zod SDK、严格 Product client 和策略工作台 Demo 页面；
- Rust、前端、浏览器、权限、并发、产物篡改和失败清理负向 fail-closed 验证。

## 非目标

- 不开放真实 Live、外部 Venue、真实订单、撤改或交易控件；
- 不实现自动重试、自动补救、自动恢复或多节点调度；
- 不实现 Demo 结果明细或 Backtest/Demo 比较；
- 不修改 v0.32.0 发布冻结文件。
