# V130-006 - Decimal-only risk/execution amount boundary

Date: 2026-06-21
Executor: Codex

## Goal

Define and verify the v0.13 Decimal/string-only boundary for risk and execution
amount fields before any future live alpha mutation scope can be considered.

Plain Chinese summary: 这个任务不是让系统开始算实盘下单金额。它只是把金额字段的
底线固定住：未来 risk/execution preflight 里的 price、quantity、notional、limit 都必须是
普通十进制字符串，用 `Decimal` 处理；不能用 `f64`，也不能接受 `1e-5` 这种科学计数法。

## Scope

Included:

- enforce plain non-negative decimal string parsing for the local shadow
  notional preflight parser;
- keep high-precision Decimal/string notional summation evidence;
- explicitly keep `f64_aggregation_used=false`;
- explicitly keep `live_alpha_money_math_ready=false` and
  `risk_or_execution_grade=false`;
- document required amount fields for a later owner-approved live alpha
  mutation proposal;
- add local verification script
  `scripts/ai/verify_v13_decimal_amount_boundary.sh`.

Not included:

- production order submission;
- production cancel / replace / amend / retry / correction;
- live-alpha risk/execution-grade money math;
- production portfolio parity;
- production order-state reads;
- real funds or production trading;
- Dashboard order controls.
