## Goal

Define the authoritative repository cleanup boundary before any tracked
post-v0.32.0 hygiene deletion or configuration change.

Plain Chinese summary: 本任务只建立清理归属和现状基线，不删除文件、不修改运行时。
它保护 v0.32.0 冻结发布包和完整 Rust cutover 审计链，并把本地噪声、配置残留、
测试 fixture 及后端性能优化分配给各自独立 issue。

## Scope

- add `governance/backend_hygiene_authority_map.md`;
- classify immutable, retained, tracked-cleanup, reproducible-local,
  user-owned-local, and separately scoped runtime surfaces;
- record tracked file counts and current local artifact state;
- bind BFH-002 through BFH-007 to exact GitHub issue dependencies;
- update the governance index.

## Not In Scope

- deleting tracked or local files;
- modifying `crates/**` or runtime behavior;
- editing `docs/rust-cutover/release/v0_32_0_*`;
- publishing v0.32.1 or authorizing a later backend capability.

## Acceptance Criteria

- every top-level and high-volume surface has an owner and disposition;
- target, release publication evidence, Python cache, `.DS_Store`,
  `project.html`, local analysis directories, docs, tests, and runtime source
  are explicitly classified;
- subsequent BFH issues have an exact owner and dependency;
- backend freeze and zero-Python gates pass;
- the change contains no deletion or runtime modification.
