# V04-001 - Binance product boundary contract

Milestone: v0.4.0 Binance Sandbox Product Foundation
Priority: P0
Owner role: Control & Scope Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Lock the v0.4.0 product boundary before implementation starts.

Plain language: v0.4 is the first Binance sandbox product foundation release,
not a production trading release.

## Dependencies

- none

## Scope

- Define the v0.4 product claim as Binance sandbox foundation only.
- Record that fixture, testnet, and mock evidence are the default validation
  path.
- Keep real funds, production trading, and production venue behavior out of
  scope.
- Distinguish what is in scope for Binance Spot and what remains deferred for
  Binance USDT-M.
- Record the release-surface wording that later README and readiness work must
  follow.

## Non-goals

- Do not implement venue connectivity.
- Do not enable real order submission.
- Do not claim Docker or production deployment support.
- Do not create a release tag.
- Do not publish a GitHub Release.

## Implementation guidance

Keep this task documentation-only. The point is to stop v0.4 from expanding
into a vague multi-exchange or production-trading milestone before the runtime
and evidence paths exist.

## Verification criteria

- Scope contract exists for `v0.4.0`.
- Scope contract states Binance sandbox-only boundary explicitly.
- Scope contract excludes real funds and production trading.
