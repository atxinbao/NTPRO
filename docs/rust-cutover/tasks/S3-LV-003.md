# S3-LV-003 - Live 账户、资金与资产结果产品化

## 目标

复用 S3-LV-002 的显式 Binance Spot 生产账户只读检查，把通过验证的账户类型、交易所权限
标志和非零资产余额投影为稳定 Product API 合同，并在策略工作台中展示。不同资产没有可信
价格换算时不生成虚假的组合总值。

## 范围

- 继续使用 `POST /api/product/v1/strategies/{strategy_id}/versions/{version_id}/live-account/actions/refresh`；
- 继续复用唯一的 Binance `GET /api/v3/account` HTTP、签名和凭证读取实现；
- 使用 Rust `Decimal` 校验 `free`、`locked` 并精确计算 `total`，不经过浮点数；
- 输出账户类型、`can_trade`、`can_withdraw`、`can_deposit`；
- 过滤零余额，按资产代码稳定排序，并返回源条目、非零条目和省略条目数量；
- 限制最多 2,048 个源余额条目和 256 个非零资产；
- 在 JSON 解析前限制响应体最多 1 MiB，同时检查声明长度与实际流式读取长度；
- Product API 严格客户端复核数量、顺序、唯一性和逐资产精确加法；
- 策略工作台 Live 页面展示账户摘要与原生单位资产表；
- OpenAPI、生成 TypeScript/Zod SDK、React、Rust 和浏览器合同同步更新。

## Fail-closed 边界

- 非法账户类型、非法资产代码、重复资产、非规范/负数 Decimal、加法溢出和超量结果失败；
- `connected` 必须携带完整结果；`blocked` 或 `failed` 必须不携带账户和资产结果；
- 原始响应、UID、commission、updateTime、凭证、请求头、签名、查询和 URL 不返回、不记录、
  不持久化；
- 不跨币种直接求和，`portfolio_value` 和 `valuation_currency` 固定为 `null`；
- 页面加载不执行生产 refresh，用户每次点击最多读取一次，失败不自动重试；
- 不访问订单 endpoint，不开放 Live Run、下单、撤单、改单、成交对账、自动补救、自动恢复或
  交易控件；
- 不继承 Backtest/Demo 权限，不修改 `docs/rust-cutover/release/v0_32_0_*`。
