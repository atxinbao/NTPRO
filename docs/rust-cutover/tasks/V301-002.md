## Goal

Make release-publish-after-gate prove the published `v0.30.0` release as the
current release instead of proving an older default release.

Plain Chinese summary: 本任务把 release-publish-after-gate 的 current release
绑定从历史 `v0.29.0` 收口到当前 `v0.30.0`。默认 gate 现在必须证明
`ntpro-rust-only-v0.30.0`、hosted release gate `29139384219` 和 tag commit
`0f0949156401fa6e6016c0160697e7090a6da788`，并且负测拒绝把 v0.29.0 输出当成
v30 current binding。它不改变 runtime，不开放 backend go-live、submit、mutation、
adapter send、live exchange request、retry、automatic remediation 或任何交易控件。

## Dependency

- Depends on V301-001 source-controlled v0.30.0 closeout evidence.
- Blocks v0.31.0 start-gate proof until v30 current-release publication binding
  is source-controlled and executable.

## Scope

Included:

- Update `verify_release_publish_after_gate.sh` default current binding to
  `v0.30.0`.
- Support the v0.30.0 `post_release_closeout` manifest state with binding pass.
- Add a negative self-test rejecting v0.29.0 fallback as v30 current binding.
- Add a dedicated V301 publish-after-gate current-binding verifier.

Not included:

- backend go-live;
- production submit or production order mutation;
- execution adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal trading controls;
- product-grade live trading claim.
