## Goal

Integrate telemetry/SLO gate and incident freeze evidence for the backend
go-live candidate.

Plain Chinese summary: 本任务为 v0.30.0 建立 telemetry/SLO gate 和 incident freeze
integration。它定义 telemetry freshness、SLO thresholds、alert routing、incident
freeze criteria 和 release-blocking health states；stale、missing、degraded 或
critical incident 状态都会阻塞 candidate go/no-go。Telemetry 事件只用于 observability，
不能触发 automatic remediation、retry、adapter send 或 trading controls。

## Scope

Included:

- Define telemetry freshness, SLO thresholds, alert routing, incident freeze
  criteria, and release-blocking health states.
- Prove degraded, stale, missing, and critical incident states block go-live
  candidate advancement.
- Prove telemetry events remain observability-only and cannot trigger action.
- Add deterministic JSON and executable verifier.

Not included:

- automatic remediation;
- retry scheduler;
- adapter send or live exchange request;
- production order submit or mutation;
- Dashboard/Admin/Trader Terminal operation controls or trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Candidate go/no-go fails closed on stale telemetry or active freeze criteria.
- Telemetry cannot trigger automatic remediation, retry, adapter send, or
  trading controls.
- Missing telemetry and degraded SLO states fail closed.
