# V141-002 - Split exchange-truth semantics

Date: 2026-06-22
Executor: Codex
Risk: medium

## Goal

Split ambiguous exchange-truth fields so production order-state read-only truth
is separate from shadow, dry-run, and portfolio truth.

Plain Chinese summary: 以前很多 artifact 和 Dashboard 都叫 `values_are_exchange_truth`，容易让人误会
“订单状态只读查到了交易所数据” 等于 “shadow portfolio / dry-run / 组合状态也是真交易所数据”。
这个任务把它拆清楚：订单状态真值、shadow 真值、portfolio 真值分别展示和判断。

## Scope

Included:

- add explicit `order_state_values_are_exchange_truth`;
- add explicit `shadow_values_are_exchange_truth`;
- add explicit `portfolio_values_are_exchange_truth`;
- keep legacy `values_are_exchange_truth` as a compatibility summary;
- keep order-state read-only truth out of shadow/portfolio boundary violation
  logic;
- update Dashboard JSON DTOs and Chinese UI labels;
- update V141 owner-evidence validator to require explicit truth fields.

Not included:

- production order submission;
- production cancel / replace / amend / retry / correction;
- listenKey lifecycle;
- Dashboard order controls;
- production trading;
- changing order lifecycle, risk, execution, or adapter semantics.

## Acceptance

- Order-state read-only success can set
  `order_state_values_are_exchange_truth=true`.
- Shadow and portfolio artifacts generated by local proof paths keep
  `shadow_values_are_exchange_truth=false` and
  `portfolio_values_are_exchange_truth=false`.
- Dashboard no-production-mutation boundary checks do not degrade solely because
  order-state read-only truth is true.
- Existing legacy `values_are_exchange_truth` remains present for compatibility.
- Targeted CLI/Dashboard tests pass.
