# PAR-001 Matching Engine Contingent State Repair

Date: 2026-07-29
Executor: Codex
GitHub issue: #1169
Risk: high
Classification: separately-scoped-runtime-maintenance
Status: REVIEW_REQUIRED

## Goal

Repair the matching-engine OUO update path so contingent quantity propagation
and zero-leaves cancellation use the validated post-update parent quantity,
even when the emitted update event has not yet been applied to cache.

中文摘要：父订单修改事件已经更新 cache，但历史 helper 仍读取修改前的本地副本，
导致子订单少更新一次，或在父订单剩余数量为零时错误更新为 `0.400` 而不是取消。
本任务只修复该状态读取顺序，并恢复两个默认回归测试。

## Scope

- pass the validated post-update parent quantity into the contingent decision;
- restore `test_updating_of_contingent_orders` to the default suite;
- restore `test_ouo_child_cancelled_when_parent_leaves_zero` to the default suite;
- update both existing ignored-test registers until PAR-011 unifies them;
- record deterministic Rust integration evidence for event ordering.

## Non-Goals

- no trailing-stop behavior change;
- no risk-engine, adapter, CLI, or public API change;
- no production order submission or mutation authorization;
- no edit to frozen `docs/rust-cutover/release/v0_32_0_*` files.

## Acceptance

- the parent quantity `2.000` propagates to the linked OUO child;
- parent zero leaves cancels the child before the parent is canceled;
- quantity propagation passes while cache event application is deliberately
  deferred, proving the helper does not depend on synchronous parent refresh;
- both tests run without `#[ignore]` in standard and high-precision modes;
- execution tests, Clippy, risk inventory, and current governance pass;
- independent review and hosted checks approve the high-risk change.
