Review role: Verification & Release Gatekeeper
Risk: medium

Risk override: the owner approved V070-003 through V070-007 for automated

turn WebSocket proof into a default CI or release blocker.

## Goal

Add optional Binance testnet WebSocket read-only probe artifacts after the HTTP
probe path exists.

## Scope

- Keep WebSocket probing behind explicit manual opt-in.
- Record timeout, DNS, handshake, and protocol failures with stable
  `error_code` values.
- Preserve `real_orders_submitted=false`, `order_submission=disabled`,
  `values_recorded=false`, and `secrets_redacted=true`.
- Keep default CI independent of WebSocket success.

## Non-goals

- Do not make WebSocket proof mandatory for the default release gate.
- Do not subscribe to private account/order streams.
- Do not submit, cancel, replace, or amend orders.
- Do not persist or display credential values.
- Do not create a tag or GitHub Release.

## Required Evidence

- `cargo fmt --check`
- `cargo check -p nautilus-cli`
- targeted CLI workflow tests
- optional/manual WebSocket artifact fixture or classified dry-run evidence
- default CI/offline check proving WebSocket is not required
- `git diff --check`

## Acceptance

- WebSocket probe artifacts can be generated in the manual online path or from
  deterministic classified fixture evidence.
- Timeout, DNS, handshake, and protocol failures have clear `error_code`
  values.
- Default CI and release smoke do not depend on WebSocket success.
- No order API, account stream, production endpoint, or credential value is
  exposed.
