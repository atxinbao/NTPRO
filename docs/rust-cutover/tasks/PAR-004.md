# PAR-004 Emulator Routing Placeholder Replacement

Risk: high

## Goal

Replace the three empty emulator-routing placeholders with executable default
tests at the component that owns the current routing decision.

中文摘要：历史空测试位于 RiskEngine，但当前实现会在命令进入 RiskEngine 之前，
由 Strategy 将 emulated submit、order list 和 modify 发送到
`OrderEmulator.execute`。本任务把测试迁到真实所有权位置，验证命令只进入
emulator，不误入 RiskEngine。

## Scope

- remove the three ignored empty placeholders from the risk integration test;
- cover an emulated child in a bracket order list;
- cover a single order whose initialization metadata requests emulation;
- cover modify after a real `OrderEmulated` state transition;
- assert exact command type and identity at `OrderEmulator.execute`;
- assert zero matching commands at `RiskEngine.queue_execute`;
- update both ignored-test registers until PAR-011 unifies them.

## Non-Goals

- no production routing or risk behavior change;
- no emulator matching, triggering, release, venue send, or live exchange claim;
- no submit, mutation, adapter-send, retry, remediation, or trading-control
  capability authorization;
- no edit to frozen `docs/rust-cutover/release/v0_32_0_*` files.

## Behavior Contract

1. A bracket list containing an emulated child is sent once to
   `OrderEmulator.execute` and never to RiskEngine.
2. A single order with initialization-time emulation metadata is sent once to
   `OrderEmulator.execute` and never to RiskEngine.
3. A modification of an order in `OrderStatus::Emulated` is sent once to
   `OrderEmulator.execute` and never to RiskEngine.
4. Tests use real order metadata/state transitions and contain assertions that
   fail on wrong endpoint, wrong command kind, wrong identity, or wrong quantity.

## Acceptance

- all three historical names run in the default trading suite with no
  `#[ignore]`;
- the risk test file contains none of the three stale placeholders;
- the restored trading tests pass in standard and high precision, the complete
  standard trading/risk targets pass, and the complete high-precision risk
  target passes;
- Clippy, ignored-test scan, risk inventory, current governance, backend freeze,
  and fast smoke pass;
- independent review and hosted checks approve the high-risk change.
