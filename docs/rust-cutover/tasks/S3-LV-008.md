## 目标

在 S3-LV-007 单笔真实订单上增加显式交易所状态查询、机构用户发起且运维确认的人工撤单，
并把部分成交后的累计成交量和剩余数量投影为可恢复、可审计状态。复用 Binance Spot
`query_order`、`cancel_order` 和 LiveNode reconciliation，不改变交易所 wire behavior。

## 控制合同

- 对账和撤单都绑定当前 Run、admission、StrategyVersion、instrument、client order ID 与订单状态哈希；
- 对账必须由用户显式触发，页面加载和 Runtime 启动不得自动创建产品控制请求；
- 撤单先由机构会话创建不可变请求，再由运维会话确认同一请求；
- Runtime 只消费有效期内、身份和哈希完全匹配、尚未消费的单个控制请求；
- 对账调用单订单查询；撤单只针对当前单笔订单的剩余未成交数量；
- 每个控制请求写入独立结果，重启不得重复查询或重复撤单；
- 交易所状态未知、订单缺失、重复事件或状态倒退全部 fail closed，并要求人工复核。

## 部分成交恢复

- 订单状态持久化原始数量、累计成交数量、剩余数量和 Venue order ID；
- 成交事件和交易所对账只能单调推进累计成交量，不得回退；
- 部分成交后不补单、不改变价格、不扩大数量；
- 人工撤单确认后，已成交部分继续保留，剩余数量进入撤单生命周期；
- 对账和撤单失败不触发自动重试、自动修复、自动恢复或补偿交易。

## 强制边界

- 不允许改单、批量撤单、自动撤单、自动重试、自动修复、自动恢复或补偿交易；
- 不允许对账结果自动创建订单；
- 不允许 Backtest/Demo 权限继承；
- 测试不得访问真实 Binance endpoint 或发送真实订单；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`，不关闭 S3 milestone。
