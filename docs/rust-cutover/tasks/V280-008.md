## Goal

Harden v0.28.0 runtime integration so partial backend closure cannot be
misread as product-ready trading runtime. The task adds deterministic
fail-closed checks across identity, audit, deployment, telemetry, Admin
Workbench bridge, Trader Terminal API handoff, and the backend closure boundary
matrix.

Plain Chinese summary: 本任务把 v0.28.0 backend closure 的 fail-closed 汇总层固化。
它证明 identity、audit、deployment、telemetry、Admin bridge、Trader Terminal API
handoff 或 boundary matrix 任一 missing、stale、partial、source-drift、unredacted、
或打开 forbidden controls 时，都不会被读成 healthy/product-ready trading runtime。
runtime closure health 与 trading readiness 继续分离。

## Scope

Included:

- Add deterministic fail-closed replay for all v28 backend closure components.
- Reject product-ready/live-trading claims when required components are missing,
  stale, partial, source-drifted, malformed, or unredacted.
- Add negative checks for forbidden submit/mutation/adapter/remediation/trading
  controls and missing required-false fields.
- Keep backend closure health separate from trading readiness.
- Promote `backend_closure_fail_closed_hardening` to `runtime-closed` in the
  v0.28 backend closure readiness matrix.

Not included:

- product-grade live trading terminal readiness;
- frontend implementation;
- order tickets or submit/cancel/retry/replace/amend/flatten controls;
- production order submission or mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation.

## Acceptance Criteria

- Partial closure is reported as degraded/blocked, not healthy/product-ready.
- Missing required backend closure components fail closed.
- Stale components degrade and do not become product-ready.
- Source drift fails closed.
- Product-ready or live-trading claims fail closed.
- Any submit/mutation/adapter/remediation/trading control field set true fails
  release gates.
- Missing required-false boundary fields fail closed.
- `scripts/ai/verify_release.sh v28-backend-closure-fail-closed-hardening`
  passes.
- `scripts/ai/verify_release.sh v28-backend-closure-boundary-contract` reports
  runtime-closed=9, evidence-only=2, blocked=0, deferred=1.
