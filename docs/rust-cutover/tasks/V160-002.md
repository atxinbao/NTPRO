# V160-002 - Add owner-approved production mutation runtime gates

Date: 2026-06-23
Executor: Codex
Milestone: v0.16.0 minimum owner-approved production order mutation candidate
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Add the v0.16 runtime gate artifact that must block production mutation send
consideration unless every owner-approved precondition is present.

Plain Chinese summary: 这个任务加的是“发送前总闸门”。它会检查 owner approval
是否已消费、kill switch 是否打开、risk preflight 是否通过、request preview 是否
ready、是否单笔 `LIMIT GTC`、是否极小 notional，以及 signing approval 是否存在。
当前 signing approval 还没有实现，所以即使前面的 v0.15 artifact 都 ready，v0.16
runtime gate 也必须 fail-closed，不允许发送。

## Scope

Included:

- add `live production-mutation-runtime-gate`;
- write `ntpro.v160_production_mutation_runtime_gate.v1` artifact;
- require owner runtime confirmations;
- require consumed one-time owner approval evidence from request preview;
- require kill-switch runtime gate evidence before any send consideration;
- require risk preflight `dry_run_approved`;
- require ready redacted request preview with `request_sent=false`;
- require single tiny `LIMIT` `GTC` candidate under a max notional cap;
- require signing approval, but mark it missing until V160-003;
- keep request sending, network, order submission, mutation, retry, cancel,
  replace, amend, flatten, listenKey, and Dashboard order controls disabled.

Not included:

- signing approval artifact implementation;
- production credential reads;
- production request signing for send;
- production HTTP send path;
- production order submission;
- response redaction implementation;
- post-submit readback;
- retry, cancel, replace, amend, correction, or flatten;
- Dashboard order controls;
- trading engine semantic changes.

## Acceptance Criteria

- Missing runtime-gate confirmations produce `blocked_missing_gate`.
- Active kill switch produces `blocked_kill_switch_active`.
- Blocked or already-sent request preview produces `blocked_request_preview`.
- Ready v0.15 source artifacts still produce `blocked_signing_approval` until
  V160-003 creates the separate signing approval artifact.
- Every blocked artifact records:
  - `runtime_gate_open=false`;
  - `send_consideration_allowed=false`;
  - `request_sent=false`;
  - `network_attempted=false`;
  - `production_orders_submitted=0`;
  - `production_order_mutations_attempted=0`;
  - `dashboard_order_controls_enabled=false`;
  - `retry_attempted=false`;
  - `cancel_attempted=false`;
  - `replace_attempted=false`;
  - `amend_attempted=false`;
  - `flatten_attempted=false`;
  - `listen_key_lifecycle_attempted=0`.
