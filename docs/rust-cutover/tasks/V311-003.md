## Goal

Make the publication guard prove the published `v0.31.0` GitHub Release after
publication rather than accepting pre-publication gate-ready wording.

Plain Chinese summary: 本任务把 `check_github_release_published.sh` 默认 current
release 切到 v0.31.0，并让 v31 post-publication guard 必须验证 GitHub Release body 是
`Status: RELEASED`，且 normalized/raw body hash 都与源码内 v31 release notes 一致。
它同步了 live GitHub Release body，但不 retag、不改变 runtime，也不开放 backend go-live
或任何交易能力。

## Dependency

- Depends on V311-001 / #1036 released v31 source notes and closeout evidence.
- Depends on V311-002 / #1037 current v31 release-surface defaults.
- Part of the v0.31.1 release governance closeout patch.
- Blocks v0.32.0 backend production closeout until all V311 issues close and
  `ntpro-rust-only-v0.31.1` release evidence is published.

## Scope

Included:

- Update `scripts/ai/check_github_release_published.sh` defaults to v0.31.0.
- Require v31 GitHub Release body to contain `Status: RELEASED` after
  publication and reject `Status: RELEASE GATE READY`.
- Make v31 post-publication guard fail closed unless normalized and raw release
  body hashes match tracked v31 release notes.
- Update the public `ntpro-rust-only-v0.31.0` GitHub Release body from tracked
  `docs/rust-cutover/release/v0_31_0_release_notes.md`.
- Record current body reconciliation hashes in the v31 manifest and closeout
  ledger.

Not included:

- release retag;
- runtime behavior change;
- backend go-live;
- production submit or production order mutation;
- execution adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal trading controls;
- product-grade live trading claim.
