# V070-001 - Add fail-closed network opt-in guard for Binance testnet workflows

Milestone: v0.7.0 deferred queue
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Add the first runtime guard for future Binance testnet read-only network access.
The workflow must stay offline unless every v0.7 opt-in condition is true.

## Scope

- Evaluate the network gate before any future HTTP or WebSocket client can be
  created.
- Require all of the following before network access can ever be attempted:
  - `--allow-testnet-network`;
  - `NTPRO_ALLOW_TESTNET_NETWORK=1`;
  - `venue.environment = "testnet"`;
  - `execution.order_submission = "disabled"`;
  - `execution.real_orders_submitted = false`.
- Record gate status and blocked reasons in the testnet connectivity artifact.
- Preserve the existing offline dry-run workflow and v0.6 verification smoke.
- Keep secrets out of artifacts, stdout, logs, docs, and PR body.

## Non-goals

- Do not implement HTTP networking.
- Do not implement WebSocket networking.
- Do not submit, cancel, replace, or amend orders.
- Do not read or store API key/API secret values beyond existing presence
  booleans.
- Do not change Dashboard behavior.
- Do not create a tag or GitHub Release.

## Required Evidence

- `scripts/ai/verify_fast.sh`
- `cargo fmt --check`
- `cargo check -p nautilus-cli`
- `cargo test -p nautilus-cli workflow::tests::binance_testnet --lib`
- `scripts/ai/verify_v06_binance_testnet_dry_run.sh`
- `git diff --check`

## Acceptance

- Without `--allow-testnet-network`, the gate is blocked and
  `network_attempted=false`.
- Without `NTPRO_ALLOW_TESTNET_NETWORK=1`, the gate is blocked and
  `network_attempted=false`.
- A non-testnet config fails before artifacts are accepted.
- A config with `order_submission != "disabled"` fails before artifacts are
  accepted.
- When all opt-in conditions are true, V070-001 still records
  `network_attempted=false` because real HTTP proof belongs to V070-003.
