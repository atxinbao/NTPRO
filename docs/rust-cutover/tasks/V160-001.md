## Scope

Included:

- create `docs/rust-cutover/release/v0_16_0_production_mutation_scope.md`;
- define v0.16 as `Minimum Owner-Approved Production Order Mutation Candidate`;
- restrict v0.16 to one owner-approved tiny `LIMIT` `GTC` order candidate;
- require default offline fail-closed behavior;
- require runtime gates, signing-material approval, redaction, readback, kill
  switch, audit trail, and no-retry semantics before release claim;
- document grepable non-goals and forbidden surfaces.

Not included:

- runtime implementation;
- production credential reads;
- production request signing;
- production HTTP request execution;
- production order submission;
- order-state readback implementation;
- cancel, replace, amend, retry, correction, or flatten;
- strategy-driven production execution;
- Dashboard order controls;
- release tag or GitHub Release creation.

## Acceptance Criteria

- Scope contract states the only allowed v0.16 candidate:
  `Minimum Owner-Approved Production Order Mutation Candidate`.
- Scope contract defines one venue/account/symbol/side, tiny capped amount,
  `LIMIT` order type, `GTC` time in force, and at most one submission attempt
  per run.
- Scope contract includes explicit not-included terms for:
  production trading, strategy-driven production execution, multiple orders,
  `MARKET`, cancel/replace/amend, retry/correction/flatten, Dashboard order
  controls, multi-venue, multi-account, and listenKey lifecycle.
- Scope contract states that this task does not implement runtime behavior or
  change trading semantics.
- Evidence records positive scope markers and negative capability guard.
