## Goal

Materialize the BPO-001 workload contract on bounded hosted runners without
making noisy measurements merge authority.

Plain Chinese summary: 本任务在同一个 hosted job 内先测 PR base、再测 candidate，
每个 workload 各跑三次并上传 JSON 和日志。低噪声指标可以按预先固定的阈值阻断
回归；execution lookup 和运行中 CV 超限的指标只报告，不阻断。它不修改交易运行时，
也不继承任何生产提交、mutation、adapter send、live request 或交易控件能力。

## Scope

- six independent workload jobs on `ubuntu-22.04`;
- pull-request, weekly schedule, and manual triggers;
- same-job baseline/candidate commit capture;
- 60-minute timeout, cancellation, Rust cache, and separate ephemeral targets;
- three Criterion sessions per commit and workload;
- result and comparison JSON schemas plus logs;
- stable/noisy classification and a fail-closed Rust comparison command;
- 30-day GitHub artifact retention.

## Regression Policy

- preclassified stable: core, model, data, live, and network;
- preclassified informational: execution matching lookup;
- observed CV above 5% makes a result noisy and informational;
- stable warning threshold: 5%;
- stable failure threshold: greater of 10% or three times baseline CV;
- only a same-runner, back-to-back stable comparison can block merge.

## Not In Scope

- optimization or runtime behavior changes;
- all-benches-in-one-process execution;
- production deployment or production SLO changes;
- editing `docs/rust-cutover/release/v0_32_0_*`;
- single-run or cross-machine performance claims.

## Acceptance Criteria

- workflow and contract validation pass;
- local workflow-equivalent capture and comparison smoke pass;
- hosted matrix records baseline and candidate commits;
- all six jobs upload valid artifacts;
- stable and noisy outcomes follow the source-controlled contract;
- backend freeze and zero-Python gates remain required.
