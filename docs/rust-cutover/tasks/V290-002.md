## Goal

Move persistent audit storage from deterministic runtime closure toward backend
production-readiness evidence without mutating real production storage.

Plain Chinese summary: 本任务把 persistent audit storage 从 v0.28 的 runtime
closure 推进为 v0.29 的 backend production-readiness evidence。它定义生产审计存储
配置、schema/migration、retention、redaction、idempotency 和 lineage 要求，并用
source-controlled sandbox fixture 验证写读边界；缺配置、source stale、schema drift、
lineage 断裂、payload 未脱敏或任何交易/自动修复路径都会 fail closed。本任务不连接真实
生产存储，不执行订单，不开放自动修复或交易控件。

## Scope

Included:

- Define a v0.29 persistent audit storage production-readiness contract.
- Add source-controlled sandboxed audit storage configuration evidence.
- Add deterministic validation for write/read, schema drift, retention,
  redaction, idempotency, and lineage requirements.
- Promote `persistent_audit_storage_production_readiness` in the v0.29
  readiness matrix to `production-ready` evidence.

Not included:

- real production storage mutation;
- external database provisioning;
- order execution or production mutation;
- adapter send or live exchange request;
- retry scheduler or automatic remediation;
- Dashboard/Admin/Trader Terminal trading controls;
- backend go-live or product-grade terminal readiness claims.
