# S3-LV-009 - 策略意图绑定的逐笔 Live 执行

Date: 2026-08-14
Executor: Codex
GitHub issue: #1306
Risk: critical
Owner role: Rust Product Surface Agent + Rust Core Runtime Agent + Frontend Agent
Review role: Verification & Release Gatekeeper
Status: REVIEW_REQUIRED

## 目标

将冻结 Demo Run 中由同一不可变 StrategyVersion 产生的订单意图，绑定到现有单笔 Live
执行准入。真实订单继续使用独立三角色审批、风险上限、外部审计锚点、一次性发送、人工对账
和撤单链路，不把 Demo 权限直接提升为 Live 权限。

## 控制合同

- 来源必须是同策略、同 StrategyVersion、已停止且结果冻结的 Demo Run；
- 只接受 Demo 运行时已阻断提交、风险决定为 rejected 且无实际发送的最新策略意图；
- instrument、side、quantity 必须逐值等于来源意图，客户端只能填写 LIMIT 价格和最大名义金额；
- 同一 `source_demo_run_id + intent_id + source_result_sha256` 在整个工作区只能绑定一个 Live Run；
- owner、risk、operator 三份审批和最终 admission 都绑定同一意图字节哈希；
- 三角色审批、外部锚点、最终 admission 与 state 发布必须持久化阶段并可幂等恢复，任何恢复
  都重新读取冻结 Demo 来源并拒绝意图漂移；
- mutation lock 必须由 OS advisory file lock 保证单 writer；活 owner 不可接管，异常退出后由
  内核释放，重启必须自动恢复 stage，不要求人工删除锁；
- Runtime 注册执行客户端前必须回读意图文件，并核对 Run、版本、标的、方向、数量与哈希；
- 订单状态 v3 持久化 Demo Run、intent ID 和 intent hash，结果可反向追溯来源。

## 强制边界

- 不开放策略自动连续下单、追加订单、改单、批量动作、自动重试、自动修复或自动恢复；
- 页面加载和 Demo 停止不会自动创建 Live 准入或发送订单；
- LIMIT 价格不从 Demo market 意图继承，仍须通过独立审批与名义金额风控；
- 当前策略意图 quantity 属于既有 Demo 运行语义；仓位 sizing 产品化不在本任务内；
- 测试不得访问真实 Binance endpoint 或发送真实订单；
- 不修改 `docs/rust-cutover/release/v0_32_0_*`，不关闭 S3 milestone。

## 完成条件

- Rust 覆盖来源冻结、身份/哈希绑定、跨 Run 重放、漂移、风险拒绝和 Runtime fail closed；
- Rust 故障注入覆盖审批、receipt、workspace head、admission、state/commit/receipt/head 的全部
  发布边界，并证明重试不会生成第二份审批或准入；
- Product API、OpenAPI、生成 SDK 和策略工作台展示同一意图来源链；
- 前端不允许修改策略标的、方向和数量；
- S3-LV-008 task/evidence/roadmap/project 状态收口为 DONE；
- fmt、Clippy、Rust-only、风险 inventory、冻结治理与浏览器 smoke 通过；
- 独立 Gatekeeper 审批、hosted checks 全绿后手动合并，禁止 auto-merge。

## 非目标

本任务不定义新的仓位 sizing 算法，不开放无人值守策略执行、多账户执行或多订单编排。
