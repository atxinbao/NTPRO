# PAR-006 dYdX Reconnect Subscription Restoration

Date: 2026-07-29
Executor: Codex
GitHub issue: #1174
Risk: critical
Classification: separately-scoped-adapter-maintenance
Status: REVIEW_REQUIRED

## Goal

Restore the ignored dYdX reconnect/subscription tracking regression as a
deterministic default adapter test without live credentials or exchange access.

中文摘要：生产 WebSocket 客户端会在重连成功后发送内部 `RECONNECTED` 消息，
随后重放已保存订阅。历史测试超时是因为 mock server 的断连开关持续为 true，
导致新连接也立即关闭。本任务把故障注入改为只触发一次，并精确验证重连和订阅恢复。

## Scope

- make the Axum mock server consume each disconnect request exactly once;
- remove `#[ignore]` from the historical restoration test;
- isolate pre-reconnect events from replay events;
- assert exactly one replacement connection;
- assert exactly one successful expected trade subscription replay;
- assert the client returns to active state;
- update both ignored-test registers until PAR-011 unifies them.

## Non-Goals

- no production WebSocket client, reconnect backoff, retry, auth, or
  subscription-state implementation change;
- no real dYdX credential, endpoint, order, transaction, or venue-send claim;
- no submit, mutation, live exchange, remediation, or trading-control
  capability authorization;
- no edit to frozen `docs/rust-cutover/release/v0_32_0_*` files.

## Behavior Contract

1. The active mock connection consumes a server-side disconnect request once.
2. The replacement connection remains open instead of inheriting the fault.
3. The client emits exactly one successful replay for `v4_trades/BTC-USD`.
4. Connection count increases by exactly one and the client is active.

## Acceptance

- the historical test runs by default and passes repeatedly;
- the complete dYdX WebSocket fixture suite passes with zero ignored tests;
- complete adapter tests, Clippy, golden replay, ignored-test scan, risk
  inventory, current governance, backend freeze, and fast smoke pass;
- independent critical review and hosted checks approve the change.
