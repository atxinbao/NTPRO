## Goal

Close the Event Store Medium finding recorded in `project.html`: the embedded
single-instance log is a valid source for audit and replay, but a browser must
never consume its unstable crate API, raw payloads, run directories, or `redb`
files directly.

中文摘要：本任务把 Event Store 到 Trader Terminal 的消费边界写成明确合同，并
用 Dashboard HTTP 负向测试保证原始 Event Store、redb、run 目录和 raw event
路径保持未挂载。终端只能消费经过可信 Rust 服务投影、脱敏和版本化的只读 DTO。

## Dependencies

- `TTR-001` / GitHub issue `#1147` is closed.

- v0.32.0 remains the frozen backend baseline.

## Scope

Included:

- document the Event Store browser and Trader Terminal consumption boundary;
- require stable, versioned read-model DTO projection;
- reject explicit raw Event Store APIs, run-event paths, download paths, and
  `redb` namespaces before matched Dashboard handlers execute;
- add direct HTTP regression coverage for namespace variants and all common
  HTTP methods;
- prove the guard blocks an otherwise registered handler without treating
  dynamic node IDs as storage namespaces.

Not included:

- stabilizing the Event Store crate API;
- cross-instance aggregation, OLAP, consensus, auth, or realtime streaming;
- submit, cancel, retry, replace, amend, flatten, adapter send, or live exchange.

## Acceptance Criteria

- The Event Store README explicitly defines the terminal consumption boundary.
- Forbidden raw Event Store namespaces return an exact `404 Not Found` status
  for GET, POST, PUT, PATCH, and DELETE.
- The six v0.28 GET routes still return versioned read-only DTOs.
- Non-GET methods remain rejected for the six v0.28 routes.
- Targeted tests, formatting, Clippy, governance, and frozen-baseline checks pass.
- No persistence behavior, public trading capability, or frozen v0.32.0 file changes.
