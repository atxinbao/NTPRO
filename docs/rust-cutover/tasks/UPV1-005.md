## 目标

把现有 Supervisor、单 node、Product API 和策略工作台整理为普通用户可通过一个入口启动、
使用、停止和恢复的本地产品交付流程。

## 范围

- 复用已冻结的 `nautilus mvp serve` 编排合同，不修改冻结后端源码；
- 生成包含主程序、node、原生启动器、必要配置、production frontend 和中文说明的自包含交付目录；
- 提供一个 `start-ntpro` 用户入口，不要求手工编排 Cargo、Vite 或后台进程；
- 首次创建持久工作区，验证交付文件、绑定地址、端口和运行参数；
- 使用 PID 所有权锁拒绝重复启动，原子接管死进程锁，并由独立守护进程处理 launcher-only 异常；
- 把 `TERM/HUP` 映射为 MVP 可处理的 `SIGINT`，确保活动 Demo 走统一停止和终态冻结；
- Ctrl-C 统一停止产品服务和仍在运行的 Sandbox node；
- 验证同一工作区重启和数据保留；
- 把本地交付 lifecycle/browser smoke 接入 hosted change-classified gate。

## 非目标

- 不建设安装器商店、云平台、多租户或远程多节点部署；
- 不改变 Product API、Supervisor registry、Run artifact 或 frontend schema；
- 不开放真实 Venue、真实订单、自动重试或自动恢复权限；
- 不修改 `docs/product/mvp_freeze_manifest.json` 中的冻结来源；
- 不修改或重新解释 v0.32.0 后端冻结文件。
