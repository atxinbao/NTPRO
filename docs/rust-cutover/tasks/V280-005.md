## Goal

Move telemetry/SLO ingestion from the v0.27 evidence foundation into a v0.28
backend runtime closure artifact. The task validates telemetry source
integrity, sampling, freshness, lineage, SLO status transitions, and redaction
without allowing telemetry events to trigger submit, retry, remediation,
adapter send, or trading controls.

Plain Chinese summary: 本任务把 telemetry/SLO ingestion 推进为 v0.28.0 backend
runtime closure。它只用 source-controlled artifact 和 verifier 复放 telemetry source、
sampling、freshness、lineage、SLO transition audit 和 redaction；telemetry event 仍然只是
observability input，不会触发 submit、retry、remediation、adapter send 或交易控件。

## Scope

Included:

- Define telemetry ingestion source, sampling, freshness, lineage, SLO breach,
  and payload redaction semantics.
- Add deterministic replay cases for healthy ingestion, audited SLO breach
  degradation, stale telemetry, missing provenance, malformed metrics,
  unredacted payload, and forbidden operation triggers.
- Promote `telemetry_slo_ingestion_runtime_closure` to `runtime-closed` in the
  v0.28 backend closure readiness matrix.

Not included:

- production telemetry transport or external observability backend ingestion;
- automatic remediation or retry scheduling;
- adapter send or live exchange request;
- production order submission or mutation;
- Dashboard/Admin operation controls or trading controls;
- product-grade live trading terminal readiness claims.

## Acceptance Criteria

- Backend telemetry/SLO health classifies through a deterministic,
  source-controlled replay path.
- SLO status changes are auditable and can degrade without triggering actions.
- Stale telemetry fails closed.
- Missing provenance fails closed.
- Malformed metrics fail closed.
- Unredacted payloads fail closed.
- Telemetry events cannot trigger submit, retry, remediation, adapter send,
  live exchange requests, Dashboard/Admin trading controls, or product-grade
  terminal claims.
- `scripts/ai/verify_release.sh v28-telemetry-slo-ingestion-runtime-closure`
  passes.
- `scripts/ai/verify_release.sh v28-backend-closure-boundary-contract` reports
  runtime-closed=6, evidence-only=2, blocked=3, deferred=1.
