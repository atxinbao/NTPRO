# V03-014 - reconnect execution gateway control

Milestone: v0.3.0 Local Supervisor Control Console
Priority: P0
Owner role: Adapter & Integration Agent
Review role: Verification & Release Gatekeeper
Risk: high

## Goal

Implement a local sandbox-only reconnect execution gateway control path.

Plain language: the local console should be able to ask a sandbox node to
reconnect its execution gateway or return a clear unsupported result if no safe
reconnect path is available.

## Dependencies

- `V03-011`

## Scope

- Define the reconnect execution request/result contract.
- Wire a local supervisor/Dashboard-visible control path.
- Record reconnect result in status or metrics.
- Support sandbox/mock/fixture mode first.
- Return explicit unsupported status for real execution adapters that are not in
  v0.3.0 scope.

## Non-goals

- Do not reconnect production execution gateways.
- Do not enable real order submission.
- Do not add real credentials or venue secrets.
- Do not hide unsupported adapter behavior as success.
- Do not create a release tag or GitHub Release.

## Related files

- `crates/cli/src/supervisor.rs` (TO_MODIFY): supervisor command/status path.
- `crates/cli/src/dashboard.rs` (TO_MODIFY): control state and API result.
- `crates/cli/src/live.rs` (TO_MODIFY): local node control handling if needed.
- `docs/rust-cutover/evidence/V03-014.md` (CREATE): task evidence.

## Implementation guidance

Keep reconnect execution sandbox-only. If the runtime does not yet expose a
safe execution reconnect primitive, return explicit `not_supported` and record
the limitation instead of pretending that production reconnect works.

## Verification criteria

- Reconnect execution gateway control returns `ok` for the supported
  sandbox/mock path or explicit `not_supported` for unsupported adapter paths.
- Dashboard/status/metrics expose the reconnect result.
- No real orders are submitted.
- No external venue execution connection is opened.
