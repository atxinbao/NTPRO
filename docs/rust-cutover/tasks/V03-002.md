# V03-002 - DashboardSnapshot DTO

Milestone: v0.3 Dashboard MVP
Priority: P0
Owner role: Rust Product Surface Agent
Review role: Verification & Release Gatekeeper
Risk: medium

## Goal

Define the stable `DashboardSnapshot` read model consumed by the local
Dashboard HTTP API and static UI.

Plain language: the page should read one clean data packet, not scrape random
files or runtime objects.

## Dependencies

- `V03-001`

## Scope

- Add a dashboard read model DTO for the local MVP.
- Include these top-level sections:
  - `overview`;
  - `nodes`;
  - `data_sources`;
  - `execution_gateways`;
  - `risk`;
  - `runtime_modules`;
  - `logs`;
  - `metrics`;
  - `alerts`;
  - `controls`;
  - `gaps`.
- Include schema version and generated timestamp.
- Preserve explicit missing-state values:
  - `unknown`;
  - `not_configured`;
  - `not_supported`;
  - `stale`;
  - `redacted`.

## Non-goals

- Do not implement the HTTP server in this task.
- Do not implement UI rendering in this task.
- Do not implement runtime telemetry emitters.
- Do not read mutable engine, cache, message bus, adapter, or account internals.
- Do not expose secrets, raw orders, raw fills, raw venue payloads, or raw
  account objects.

## Implementation guidance

Prefer a small Rust DTO module close to the local dashboard or CLI product
surface. Reuse existing status enums where practical. If a value cannot be
derived from v0.2 artifacts, represent the gap explicitly instead of inventing a
healthy state.

## Verification criteria

- DTO serializes to stable JSON.
- Unit tests cover:
  - empty snapshot;
  - one-node snapshot;
  - two-node snapshot;
  - explicit unknown/not configured/not supported/stale gaps;
  - no secret/raw payload fields.
- No Python, PyO3, or Cython product dependency is added.
