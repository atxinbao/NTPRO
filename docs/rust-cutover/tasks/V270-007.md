## Goal

Harden v0.27.0 runtime integration failure semantics so identity, audit,
deployment orchestration, telemetry/SLO, and Admin Workbench bridge artifacts
share one fail-closed/no-trading-control validation contract. Partial or stale
integration can only downgrade a read-only surface; it can never display
product-grade trading readiness.

Plain Chinese summary: 本任务新增 v27 runtime integration fail-closed hardening
证据。它把 identity、audit、orchestration、telemetry 和 Admin Workbench bridge
artifact 放到同一个只读校验里，统一处理 partial/stale downgrade、缺失 artifact、
provenance/redaction 失败、禁止控制字段为 true 或缺失、以及 product-ready 误报；
不会新增下单、改单、adapter send、live exchange request、retry scheduler、automatic
remediation、Dashboard/Admin trading controls 或 product-grade terminal claim。

## Scope

Included:

- Define shared fail-closed checks for v27 runtime integration artifacts.
- Require explicit `false` for all submit/mutation/adapter/remediation/control
  fields; missing values fail closed.
- Distinguish downgrade-only conditions from fail-closed conditions.
- Add negative trace rows for forbidden submit, adapter/remediation, product
  readiness, and missing required-false boundary fields.
- Register trace rows in release replay scope as validator executable replay.

Not included:

- Runtime UI implementation changes.
- Trading, operation submission, adapter sends, live exchange requests,
  automatic remediation, retry scheduling, or production readiness claims.
- Any product-grade live trading terminal claim.

## Acceptance Criteria

- Any forbidden trading/control capability fails closed across V270 artifacts.
- Missing required-false boundary flags fail closed.
- Partial or stale runtime integration is degraded/fail-closed, never
  healthy/product-ready.
- Downgrade vs fail-closed rules are documented in the release contract.
- `scripts/ai/verify_release.sh v27-runtime-integration-fail-closed-hardening`
  passes.
- `docs/rust-cutover/golden_trace/RELEASE_REPLAY_SCOPE.json` records the
  V270-007 cases as validator executable replay.
