# V170-004 - Add orphan order detection

Date: 2026-06-24
Executor: Codex
Milestone: v0.17.0 production reconciliation and orphan recovery
Risk: medium
Auto-merge: allowed after local validation and hosted smoke PASS

## Goal

Detect open/orphan order risk from one v0.17 reconciliation classifier artifact
and force manual review/new-order blocking when the lineage is unsafe.

Plain Chinese summary: 这个任务只做“孤儿单风险检测”。大白话：如果交易所还能看到打开的订单，
或者本地说没发但交易所看到了订单，或者回查失败、重启后账本证据不可靠，就把风险停住，
要求人工复核，并阻断新单。它不自动撤单、不重试、不修复。

## Scope

Included:

- add `live production-mutation-orphan-order-detector`;
- consume one v0.17 reconciliation classifier artifact;
- output orphan risk detection evidence;
- mark risk cases with:
  - `orphan_risk_detected=true`;
  - `risk_halted=true`;
  - `manual_review_required=true`;
  - `new_orders_blocked=true`;
- cover clean terminal, open orphan, local missing/exchange seen, readback
  failure, and stale ledger restart cases.

Not included:

- owner-approved cancel recovery;
- restart recovery execution;
- automatic cancel, retry, replace, amend, correction, flatten, or remediation;
- Dashboard order/cancel controls;
- network readback execution;
- multi-account or multi-venue reconciliation;
- release tag creation.

## Acceptance Criteria

- Detector artifact uses
  `schema_version=ntpro.v170_production_mutation_orphan_order_detector.v1`.
- Ready detector sets `orphan_detection_completed=true`.
- Clean terminal state does not detect orphan risk.
- Open order observed without a local terminal state detects orphan risk.
- Local no-send/exchange-order-seen detects orphan risk.
- Readback failure or ambiguous lineage halts risk and blocks new orders.
- Stale ledger restart evidence halts risk and blocks new orders.
- API keys, secrets, signatures, signed query/URL, raw exchange response,
  response body, and response headers are not persisted.
- Duplicate submit, retry, cancel, remediation, and Dashboard order controls
  remain disabled.
